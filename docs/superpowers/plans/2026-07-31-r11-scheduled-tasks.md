# r11 本地定时任务实施记录

日期：2026-07-31

## 目标

让用户只回答三件事就能创建任务：momo 要做什么、什么时候做、结果放到哪个工作区。任务复用现有对话、模型、工具、权限和工作区能力，不再让用户配置内部模型、Skill、执行器或系统调度参数。

## 已定产品边界

- 支持一次、每天、每周；均按设备本地时间运行。
- Leemo 进程存活时自动运行，但不抢走用户正在看的页面。
- Leemo 完全退出时不假装后台执行；再次启动后明确列出漏跑任务，让用户选择“补跑”或“跳过”。
- 每个任务绑定一个真实工作区，产物继续走该工作区的正常对话与工具路径。
- 保留暂停、继续、立即运行、编辑、删除和最近运行记录。
- v1 不做云调度、Windows 计划任务、系统常驻服务、复杂 cron 表达式或静默 token 消耗。

## 实施清单

- [x] 定义一次、每天、每周的领域模型和本地日历计算，校验过去时间与非法输入。
- [x] 在现有 SQLite 中保存任务与运行记录，以事务推进到期任务并防止重复 claim。
- [x] 主进程拥有本地时钟；启动时恢复中断运行并把退出期间到期的任务标为漏跑。
- [x] 通过窄 preload/IPC 接口暴露 CRUD、补跑、跳过、claim、完成和结果对话关联。
- [x] renderer 复用现有会话发送路径，后台创建目标工作区对话且不切换当前页面。
- [x] 工作台增加“定时任务”入口、轻量创建表单、任务列表、漏跑选择和最近运行记录。
- [x] 对话终态立即落盘，renderer 卸载前 best-effort 冲洗，避免任务刚完成就关窗时丢结果。
- [x] 覆盖领域、SQLite、主时钟、IPC 客户端、renderer store、页面和导航测试。
- [x] 打包应用真实验证自动运行、不中断当前页面、结果对话、重启恢复、漏跑选择和紧凑视口。

## 收工判据

- 自动任务真实产生 momo 对话结果，不是只更新任务状态。
- 自动运行不改变用户当前视图；结果可从任务页打开。
- 重启后任务、运行记录及已完成结果对话都还在。
- 完全退出期间的任务不会假成功；回来后必须由用户决定补跑或跳过。
- `1440x900` 和 `720x640` 无横向溢出，关键操作不被裁切。
- 隔离验收不读取真实工作区，不调用外网或付费模型，退出后无残留测试进程。
