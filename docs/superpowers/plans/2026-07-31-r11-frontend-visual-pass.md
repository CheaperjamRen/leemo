# R11 内测前整机视觉与排版收口计划

> 这是功能 P0（搜索、外部工作区、定时任务、基础文件工具、Skills）完成后的最后一道内测门槛。它不是“把页面换一套颜色”，而是让用户在每条核心路径中都能看懂当前状态、下一步和结果。

## 设计方向

采用 **Swiss** 方向：中性白与浅灰表面、深墨色正文、单一 Leemo 橙作为动作/焦点色，1px 细线和严格网格承载信息密度；不使用渐变、装饰性光晕或无意义的卡片堆叠。这样保留 NewMax/ColaOS 的安静、可持续使用感，同时让 Leemo 从“普通浅色后台”变成有明确秩序的本地工作台。

记忆点是“状态先于装饰”：每个正在运行、等待授权、失败、完成、已保存的状态都用同一套位置、图标、颜色和动效表达，用户扫一眼就知道 momo 在做什么以及是否需要自己介入。

## 执行顺序

### 1. 先做用户路径审计（必须）

- 搭子态：闲聊、长回答、记忆轻回执、失败与重试。
- 工作台：文件树、对话、工具过程、审批、成果、空工作区。
- 设置：模型预设卡、连接器/搜索、权限、个性化、用量；重点看 720x640 的滚动与输入区。
- 新用户：首设模型 → 第一条消息 → 新建/挂载工作区。
- 复杂能力：搜索成功/失败、定时任务运行/漏跑、外部工作区切换、产物预览。

每条路径记录“用户看到的当前状态、是否知道下一步、是否能恢复”，不以 DOM 存在代替可用性。

### 2. 建立统一视觉 token（必须）

- 颜色：正文/次要/禁用/成功/警告/错误/焦点的明确对比；橙色只承担动作和注意，不铺满页面。
- 字体：中文优先系统无衬线，标题/正文/辅助信息固定层级与行高；模型 ID、路径、数量使用等宽或 tabular numerals。
- 间距与尺寸：统一 4/8 基线、按钮 36/40/44 三档、输入区最小高度、设置弹窗最大宽高和分区滚动边界。
- 形状与层次：减少嵌套卡片，重复项用行/分组；弹窗、结果卡、审批卡保留必要边界；阴影只用于浮层。
- 图标与动效：统一 lucide 图标语义；运行态、流式态、完成态动效短、克制、可关闭。

### 3. 重排信息层级（必须）

- 设置页：左导航宽度、选中态、页标题/说明、分组标题、字段状态、保存回执固定节奏；来源与模型配置不再靠灰度猜层级。
- 主界面：顶部上下文、时间线、过程折叠、输入区和底部状态栏形成稳定纵向骨架；长内容只能在时间线滚动，不能推出 composer。
- 过程与回执：默认一句人话，细节按需展开；错误必须告诉用户“发生了什么、是否已产生副作用、下一步怎么恢复”。
- 空态：只写真实可执行的下一步，不用假对话、假统计或装饰性提示填空。

### 4. 补齐高频状态组件（必须，按真实场景）

优先实现并复用 Skeleton、Toast、Dialog、Tooltip、Empty、RunningDot、StreamingPulse；Tab/Slider 等只在真实设置需求出现时补，不为凑组件数扩张包体。

### 5. 四尺寸与性能复核（必须）

在 `1440x900 / 1280x720 / 1024x768 / 720x640` 分别目验搭子、工作台、设置、模型配置和搜索；检查文本不重叠、按钮可点、弹窗可滚、输入区完整。记录包文件数、安装器大小、冷启动、空闲内存和长对话输入区，不能以视觉改版为由引入大量小文件或新运行依赖。

### 6. 独立视觉评审与收口（必须）

评审者只看截图和真实用户路径，不读实现细节；按“层级、可读性、状态可信、密度、响应式、品牌辨识度”逐项给出 P0/P1/P2。P0/P1 清零后再进入内测候选包。

## 边界

### 内测前必须完成

- 核心路径不裁切、不溢出、不遮挡；加载/运行/失败/完成/空态可理解。
- 设置、模型接入、搜索和权限文案不暴露 Claude Code 内部心智。
- 视觉 token 和状态组件在至少两个高频页面复用，而不是局部特效。

### 内测后再做

- 用量统计的高级图表、主题扩展、更多动效、学习场景的专属插画与成就视觉。

### 明确暂不做

- 为追求“像竞品”引入云端设计系统、商业字体、图片资源包或大规模组件依赖。
- 只为截图好看而增加假数据、复杂渐变、装饰性卡片或牺牲长对话可用宽度。

## 验收产物

- 一份四视口截图索引和问题清单。
- 一份组件/token 变更清单与包体对比。
- 一次独立视觉评审记录，含 P0/P1/P2 结论。
- 一个可安装的内测候选包，复跑核心用户路径后再宣称完成。
