# Word 高保真精确修改设计

日期：2026-08-01

## 目标

让用户可以直接告诉 momo 修改现有 Word 文档中的明确文字，并得到一份可回滚的修改副本。这里的“高保真”是可验证的窄承诺：只修改命中的正文文字节点，未触及的 OOXML 部件内容保持不变；不把原文抽成纯文本后重新生成一个外观相似的新文档。

## 用户路径

1. 用户在当前工作区内指出一个 `.docx` 和要替换的原文、新文。
2. momo 调用内置 Word 精确修改工具；一次可提交最多 20 项文字替换。
3. 每项默认必须在可安全编辑的正文中恰好命中一次。模型可显式声明预期命中次数；实际数量不同则整次操作不落盘。
4. 未指定输出路径时，在原文件旁生成 `原名-修改版.docx`；源文件永不被覆盖。
5. 回执只说明生成了哪份副本和完成几处修改，成果页登记新副本，不大张旗鼓展示内部实现。

## 实现边界

- 先完整校验 DOCX/OOXML 包、正文 XML 和输入限制。
- 按段落拼接 `w:t` 文字，使一句话即使被粗体、颜色或其他 run 样式拆开，也能精确命中。
- 替换跨多个 run 时，新文字继承命中起点的样式；未命中的文字节点、图片、关系、主题、样式、页眉页脚、批注等包部件保持原始内容。
- 只支持单段落内的字面量替换，不把正则表达式暴露给模型。
- 为避免误改域、修订痕迹或嵌入对象，命中涉及 `fldChar/instrText/del/moveFrom/drawing/object/tab/br` 等复杂结构时停止并给出人话说明。
- 替换文字不得含换行、制表符或其他控制字符；结构性增删、表格重排、图片替换、样式重构、修订模式、宏文档不在本卡承诺内。

## 安全与失败恢复

- 源路径和输出路径都必须位于当前工作区，且不得写入 `.leemo/memory`。
- 输出路径必须是新的 `.docx`，不得与源路径相同；目标已存在时不覆盖。
- 所有替换先在内存中验证和生成，最后复用同目录临时文件加 rename 的原子写入。
- 任一替换找不到、数量含糊、发生重叠或遇到不安全结构，整批失败，源文件和目标文件均不改变。

## 验收

- 普通单 run、跨样式 run、中文和 XML 转义文字均可修改并读回。
- 多项替换全部通过才写入；0 次、重复次数不符、重叠、复杂结构、同路径和已有目标均不落盘。
- 解包前后逐项对比：除 `word/document.xml` 外所有部件的解压内容逐字节相同；正文 XML 除目标 `w:t` 内容与必要的 `xml:space` 外不变。
- 工具受现有工作区边界和 `acceptEdits` 语义治理；成功副本进入成果索引。
- 源码测试、三套 typecheck、renderer/main build 和打包态真实用户路径通过后才标记 Release-verified。

## 后续而非本卡

1. 用同一“精确命中、另存副本、部件保真、歧义不写”契约扩展 PPTX 文字和 XLSX 单元格修改。
2. 单独设计 Markdown 预览编辑、富文本工具栏和选中文字询问/改写，不与 Office 包修改耦合。
3. 收到真实模板编辑需求后，再评估图片、表格结构、批注/修订和原位覆盖加自动备份。
