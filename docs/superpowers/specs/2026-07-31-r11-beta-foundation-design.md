# Leemo r11 内测基础能力设计

> 日期：2026-07-31
> 状态：产品方向已批准；工程实现按独立卡片推进
> 目标：在不牺牲本地优先、用户心智和安装体验的前提下，补齐可交给邀请用户使用的通用 Agent 基础能力，并为英语学习差异化和 Leemo Gateway 留出稳定扩展边界。

## 一、已批准决定

1. Luna 补贴采用邀请制、固定每日额度，只服务搭子态日常问答和轻计划；工作台、coding、长任务继续使用用户自己的模型。
2. 任何共享模型密钥都不得进入桌面客户端。Leemo Gateway 持有上游凭据、鉴权、额度和撤销能力。
3. 定时任务的用户主流程只回答三件事：做什么、什么时候、结果放哪里。模型、Skill、补跑和失败策略由系统自动处理，详情页只展示必要状态。
4. 内测版提供不少于 40 个可选 Skill，但不默认全部启用。首装只启用 6-8 个低风险核心 Skill，其余按分类选择。
5. Skill 数量不能靠空卡片伪装能力。每个 Skill 必须声明所需工具；依赖缺失时显示原因，不能允许用户触发后才失败。
6. PDF、Word、PPT、Excel 不直接复制 Anthropic 的 source-available 文档 Skills。Leemo 自己实现可分发的本地文档工具，再用自有 Skill 教 momo 正确调用。
7. 每项发布验收固定覆盖：成功、失败、重启恢复、用户能否看懂；并重测安装文件数、冷启动、空闲内存和长对话输入区。

## 二、发布顺序

### P0：邀请内测前必须完成

1. 搜索源：豆包搜索、秘塔、Google 兼容入口、arXiv 学术检索。
2. 外部文件夹工作区：已有目录可成为一等工作区，并绑定对话、产物和本地记忆。
3. 本地定时任务：单次、每天、每周，支持暂停、运行记录和应用重启后的补偿判断。
4. Skill 中心：40 个可选 Skill、分类搜索、启停、可用性和来源信息。
5. 第一版文档工具：PDF 读取/提取；DOCX、PPTX、XLSX 的读取与新建；不伪称支持尚未验证的复杂原地编辑。
6. 打包态用户路径和性能回归。

### P1：首批邀请用户后

1. Leemo Gateway 邀请制 Luna 日常额度。
2. 英语学习闭环：目标诊断、每日任务、主动回忆、纠错账本、间隔复习、周度同型验收。
3. 定时任务与英语计划结合，每天主动生成小任务。
4. 文档工具扩展到可靠的模板编辑、批注、渲染和视觉验收。

### P2：出现留存或付费信号后

1. 订阅、充值、支付和更完整的模型中转能力。
2. 自运营在线 Skill Hub（账号、评分、推荐流、托管与自动更新）。
3. 语音对话、发音反馈和跨端提醒。
4. 本子模板市场和复杂自动化编排。

## 三、搜索设计

### 3.1 用户心智

设置页仍叫“联网搜索”。用户只需要看到：来源、适合什么、是否可用、是否已配置。默认自动选择；高级用户可调整备用顺序。打开联网后，已启用的只读搜索不重复索权。

### 3.2 来源职责

| 来源 | 定位 | 凭据 | 默认行为 |
| --- | --- | --- | --- |
| AnySearch | 免 Key 通用默认源 | 可选 | 保留第一顺位 |
| 豆包搜索 | 中文时效搜索 | API Key | 已配置后进入通用 fallback |
| 秘塔 | 中文研究与引用 | API Key | 已配置后进入通用 fallback |
| Google | 兼容已有 Custom Search 凭据 | API Key + CX | 非新用户默认，明确显示服务限制 |
| arXiv | 论文元数据与摘要 | 无 | 独立“学术检索”，不混进普通 fallback |
| Tavily / 博查 | 现有备用源 | API Key | 继续兼容 |

所有来源归一化为可引用的 `title/url/snippet`。服务错误、配额不足、认证失败和零结果必须是不同诊断；不能把错误伪装成“没有结果”。arXiv 遵守请求间隔与缓存要求。

## 四、外部工作区设计

1. “本子”仍是 Leemo 管理的学习/求职容器；“工作区”是用户选择的真实文件夹。两者共享 Agent、成果、权限和记忆能力，但不强迫用户把外部目录复制进 `~/Leemo`。
2. 左侧提供“打开文件夹”入口和最近工作区。选择后当前对话 cwd、文件树、成果和默认写入位置都指向该目录。
3. 外部工作区在根目录创建 `.leemo/` 保存对话与本地记忆；首次写入前用一句话说明，不弹技术确认表单。用户可在设置中移除工作区记录，但不删除目录或用户文件。
4. 路径治理以当前工作区根为边界。切换工作区只影响新对话；已有对话始终回到原路径，目录不存在时显示可恢复错误。
5. `~/Leemo/默认工作区` 仍是 momo 全局视野下无归属产物的兜底，不被包装成一个本子。

## 五、定时任务设计

### 5.1 创建流程

聊天中说“每天八点给我 10 分钟英语练习”时，momo 返回一张轻确认卡：

```text
每天 08:00
给我一份 10 分钟英语练习
结果：当前工作区 / 定时任务对话
[创建]
```

专用页面的新建表单只展示：

1. 任务内容；
2. 时间（自然语言、单次、每天、每周）；
3. 结果位置（默认当前工作区）。

任务名称从内容自动生成，可在详情中修改。模型默认使用任务创建时的可用模型策略；Skill 自动匹配，普通用户不需要选择。

### 5.2 内部可靠性

内部仍需持久化 `schedule/timezone/nextRunAt/workspaceId/prompt/status`，并记录每次运行结果。它们是系统可靠性字段，不是创建表单字段。

第一版采用 Electron 主进程本地调度：Leemo 在运行或托盘后台时准时执行；完全退出后不运行，重新打开时显示错过记录并让用户选择是否补做。首版不注册每任务一条 Windows `schtasks`，不建设云端调度。

任务只支持单次、每天、每周；不向普通用户暴露 cron。运行写文件继续走现有权限和工作区边界。失败要显示人话原因和“重试”，不能静默跳过。

## 六、40 个 Skill 的产品结构

### 6.1 加载原则

1. 40 个是“可选目录”，不是 40 个常驻提示词。
2. 启动时只读取 `name/description/category/requirements`；Skill 正文仅在触发时加载，参考资料再按需读取。
3. 首装默认启用 8 个：深度研究、网页资料整理、文件整理、PDF 学习、每日计划、每日回顾、简历诊断、JD 匹配。
4. 同类 Skill 描述必须互斥，减少自动触发冲突。用户可通过 `/技能名` 明确调用。
5. 内置 Skill 只读更新；用户可“复制为自定义”后编辑。自定义 Skill 与内置 Skill 分开显示。

### 6.2 首批目录

- 学习 12：课程规划、PDF 深读、论文精读、概念讲解、主动回忆、出题测验、错题归因、间隔复习、每日计划、每日回顾、英语每日练习、英语写作反馈。
- 求职 10：简历诊断、JD 匹配、简历定制、求职信、STAR 故事、模拟面试、面试复盘、公司调研、岗位比较、投递计划。
- 研究与办公 10：深度研究、网页资料整理、事实核验、来源对比、arXiv 检索、PDF 提取、Word 报告、PPT 大纲、Excel 分析、会议纪要。
- 创作与工作台 8：Markdown 整理、翻译润色、内容大纲、信息图脚本、文件整理、代码库导读、故障诊断、测试验收。

### 6.3 工具与 Skill 的关系

- Tool 是可执行动作，例如读文件、写文件、搜索、解析 PDF、创建 DOCX。
- Skill 是任务方法，例如“先抽取目录，再逐章提问，再生成主动回忆题”。
- Skill 不会凭空补齐运行时。文档 Skill 必须依赖真实的 Leemo 文档工具；工具不可用时卡片显示“当前版本不支持”，而不是让模型临时安装依赖。

### 6.4 打包策略

内置目录和 Skill 正文编译成一个版本化资源包，避免安装器新增几十个零散文件。只把用户启用的 Skill 物化到运行时目录；发行包继续记录文件数和解压耗时。

MVP 不建设或依赖 Leemo 自营的在线 Skill Hub。技能中心由两类本地数据组成：随应用打包、可启停的内置 Skill；以及编译进客户端的精选下载清单。浏览和搜索这份清单不联网，用户点击安装时才由本地发起一轮按需下载流程（可能包含固定来源的多次文件请求）。skill.sh 只作为发现入口，客户端解析后直接访问其上游来源，不做后台同步或轮询。

用户也可以粘贴 GitHub / skill.sh 链接、选择 ZIP / 文件夹或用自然语言安装。未知来源默认不强制扫描、不因扫描结论拒绝安装；结构性安全检查始终保留。Leemo 自己展示的精选清单则必须固定提交版本、核验许可证与哈希并通过预审。若以后需要统一维护，可使用公开 GitHub 仓库存放清单或经许可的自有 Skill，但它仍是静态下载源，不演化为首版平台服务。

## 七、Leemo Gateway

### 7.1 首版边界

桌面端只拿 Leemo 的短期访问凭证。Gateway 负责：邀请用户鉴权、Luna 模型白名单、每日请求/token 额度、并发限制、服务端上游 Key、用量台账和单用户撤销。

首版 API 只开放搭子态需要的对话接口，不开放任意模型代理、任意 Base URL 或工作台工具执行。使用中转站 Luna 时，上游作为可替换 Adapter；必须先确认对方允许转售或下游分配，且随时可切回官方上游。

### 7.2 可扩展性

领域模型从第一天分开：`User/Invite/Entitlement/UsageLedger/Upstream/ModelPolicy`。支付和套餐只会新增 Entitlement 来源，不改变桌面协议。因此日后可扩展为模型订阅平台，但不在没有留存证据时先建设钱包、充值和结算系统。

Cloudflare 负责 DNS、TLS、限速和边缘防护；Worker 或小型服务负责鉴权与额度。Cloudflare 不是法律或商业授权替代品，也不能保证中国大陆网络质量。

## 八、英语学习差异化

Leemo 不复制 Duolingo 的固定课程树。第一版围绕用户自己的课程、PDF、论文、求职目标和真实表达构建：

```text
目标诊断 -> 每日小任务 -> 输入理解 -> 主动回忆
-> 写/说输出 -> momo 纠错 -> 错误进入复习队列
-> 周度同型测验与作品对比
```

进度证据是同一能力的前后输出、错误复发率、可独立完成的真实任务和复习掌握度，不只显示连续天数。FSRS 等调度器负责复习时间，momo 负责内容与反馈。

## 九、发布验收

每个子项目先定向红绿测试，再跑全量测试、三套 typecheck、renderer/main 构建。涉及主进程、文件、网络或定时行为时必须在最终安装包中走真实用户路径：

1. 成功完成一次；
2. 制造认证/网络/路径/模型失败并能恢复；
3. 关闭、重启后状态与文件仍正确；
4. 普通用户不需要理解 Provider、cron、Claude Code 或内部路径；
5. 1440x900、1280x720、1024x768、720x640 无遮挡；
6. 对比上一发布包的安装器、解包文件数、冷启动、内存和 renderer chunk。

## 十、明确不做

- 不把共享 Key 打进客户端；
- 不在首版开放匿名无限 Luna；
- 不把 Google 当稳定的新用户默认搜索；
- 不默认启用全部 40 个 Skill；
- 不复制不可再分发的 Anthropic/OpenAI 文档 Skill；
- 不为首版定时任务建设云端队列或暴露 cron；
- 不建设或依赖 Leemo 自营在线 Skill Hub；
- 不把 NewAPI/Sub2API 嵌进 Leemo 桌面端核心；
- 不为了“模块化”制造大量小文件和依赖树。
