# Leemo 工作台主界面视觉规范 v1.0

> 日期：2026-08-08<br>
> 状态：产品视觉方向已批准；等待前端统一实施<br>
> 视觉基准：`docs/design-audition/visual-redesign/workbench-main-v1.png`

## 一、页面心智

工作台不是单一聊天页，而是用户在多个本子、对话与本地文件之间持续工作的全局地图。页面必须同时保留：

- 左侧本子与「与 momo 的对话」；
- 中部对话协作；
- 文件预览或编辑；
- 右侧「文件 / 概览 / 搜索」工具栏；
- 浮动输入框与紧凑运行状态。

## 二、视觉基调

- 使用成熟的暖中性色，而不是大面积奶黄或灰白开发界面；
- 暖灰画布、暖白内容面、深墨蓝结构与文字、琥珀铜作为少量运行反馈；
- 由排版、分隔、选中态和轻微层次建立专业感，不堆叠等权卡片；
- 正文字号保证可读，辅助信息可以更紧凑但不能浅到看不清；
- 阴影保持中性、低模糊、低存在感；圆角按组件层级统一。

## 三、momo 与消息

- 用户消息靠右的小型气泡区分，不显示用户头像；
- momo 头像只作为回复与运行状态的身份锚点；
- 实施时头像要比视觉稿再缩小一档，约 `20–24px`，只保留最低可辨认度；
- 运行条中的 momo 约 `24–28px`，整条高度控制在 `44–48px`；
- momo 不得抢过正文、文件标题或当前任务状态。

## 四、关键组件

- 左栏默认约 `288px`，本子与「与 momo 的对话」各自滚动；
- 当前本子与对话使用淡墨蓝底和细琥珀标记，不使用厚重浮卡；
- 对话与文件在宽屏下左右并排，约 `42% / 58%`；
- 运行过程使用窄条、简短状态、细进度路径与「展开」入口，不使用大面积思考卡；
- 步骤数、完成比例和当前 Todo 只能来自运行时的真实结构化任务计划，不能从回复文字、工具次数或耗时中推测；执行模型可以在任务中新增、删除、重排和改写 Todo，界面必须随同一真源即时更新；
- 当执行器没有提供可靠计划，或当前状态无法与计划同步时，只显示「正在处理」及真实工具轨迹，不显示 `2 / 3`、百分比、预计剩余时间等伪精确进度；
- 展开后的运行过程把「模型思考」与「事实轨迹」分开：模型过程以「已思考约 N 秒」作为二级折叠入口；真实工具与命令统一收进「工具与命令 · N 次」，默认折叠但始终可追溯；
- 折叠行标题只承担人话摘要与状态，例如「运行了命令」「读取了 1 个文件」；展开后不得再次复述同一摘要，而应直接进入原始技术记录；
- 原始技术记录按工具自身形态展示：Shell 显示未改写的完整命令、工作目录、`stdout`、`stderr`、退出码或信号与耗时；其他工具显示原始工具名、输入参数、返回结果、错误和相关文件。失败时直接呈现真实错误文本，仅对敏感值做遮盖，不把报错改写成模糊的人话摘要；
- 长命令和输出使用等宽字体、内部滚动、选择与复制；视觉层级参考成熟 Agent 的终端记录，而不是业务表单。任务完成或应用重启后，原始记录仍随会话保留；
- 过程透明不等于泄露敏感信息：API Key、认证头、令牌与安全环境变量在详情层自动遮盖，其余真实输入与结果不做美化或伪造；
- 运行中的排队消息只使用约一行文字高度的窄卡：截取消息开头并省略，其位置本身即表示“已排队”；不重复展示附件、图片、状态标题或快捷键教学。右侧以铅笔、路径转向箭头、垃圾桶三个紧凑图标提供「修改 / 立即引导 / 删除」，默认不占用文字宽度，悬停显示中文提示并保留无障碍名称；多条消息按相同窄卡纵向排列；
- 问询卡继续使用对话时间线内的整行选项，不改成弹窗或输入框上方常驻面板。卡片外壳只负责清晰展示，选项的信息质量由模型工具契约保证；
- 模型每次问询应优先只问一个高信息量问题；只有彼此紧密相关、一次回答明显更省事时，才允许在同一张卡中组合少量问题；
- 每个选项必须包含简短标题与必填解释。标题用于快速扫描；解释必须说明「选择后会如何执行」，并至少补充「适合什么情况」或「主要取舍」之一，不能复述标题、只给时间数字或使用空泛宣传语；
- 单选项必须彼此可区分且尽量互斥；多选仅用于可以同时成立的选择。「其它」输入由 Leemo 统一提供，模型不得自行生成一个名为「其它」的选项；
- 没有充分上下文时不强行标记推荐。确有依据时，推荐只作为轻量附注，并说明与当前用户目标相关的理由，不能让推荐项在视觉上压倒其余选择；
- 用户提交后，结构化选择与自由补充必须返回给同一个等待中的任务，由模型沿当前上下文继续执行；已回答卡片原位收成一行轻回执，不新建会话、不丢失问题归属；
- 视觉参考：`docs/design-audition/visual-redesign/workbench-ask-user-v2.png`。其中复习节奏示例必须让用户直接比较「稳扎稳打 / 重点突破 / 考前冲刺」各自的执行方式和代价，而不是只显示一句口号；
- 审批等级不能只由命令名决定，必须同时判断操作、已解析目标、影响范围、归属和可恢复性。同样是 `Remove-Item` / `rm`，清理 Leemo 自己管理且可重新生成的缓存、预览、临时与 staging 目录时默认直接执行，只在折叠工具轨迹中留下「已清理缓存」；不得弹审批卡，更不得染成红色；
- 有明确目标、范围有限的普通写入、移动、覆盖、单文件删除或对外动作，按用户当前权限设置使用中性或琥珀色行内审批，说明真实对象和结果，不使用危险警报视觉；
- 红色只保留给可能造成实质且难以恢复损害的操作，例如对用户数据或系统路径的大范围递归删除、永久删除、磁盘或注册表破坏、提权执行，以及同等级不可逆外部后果。高风险卡必须展示已解析的真实目标与影响范围，不能只展示一条吓人的命令；
- 审批结束后原位收成一行轻回执；自动放行的维护动作不额外炫耀。视觉稿 `workbench-approval-v1.png` 仅为已否决草案，不作为实现依据；
- 输入框悬浮于对话区底部，有轻边框和中性阴影，不横向铺满整个应用；
- 输入框操作栏固定保留 `+`、`/`、`@` 三个入口：`/` 只显示斜杠，不附带 “Skill” 英文；悬停时再以中文提示“技能”；`@` 用于引用便签、文件等上下文；
- `+` 菜单按从上到下的单列展开，只收纳附件与低频能力，不在菜单内重复 `/` 和 `@`，避免拥挤与重复心智；
- 右侧工具栏常驻但默认收起，避免挤压主要工作面；
- 左下角使用「看板 / 技能 / 定时 / 设置」四个紧凑横排入口。

## 五、实现边界

- 视觉稿是布局、层级、比例与气质基准，不要求逐像素照搬生成图中的模型名或权限文案；
- 所有文案、状态、文件和任务必须接真实数据；
- 任务进度属于事实状态而非视觉装饰：发布前必须验证创建计划、执行中调整 Todo、完成或失败后的状态收口，以及会话恢复后界面与运行时一致；任一执行器无法满足时，对该执行器降级为无精确进度展示；
- 图标统一使用项目图标系统，不把字符或 emoji 当正式图标；
- 熟悉且高频的紧凑操作优先使用图标与中文 tooltip；含义难以仅凭图标判断的核心动作继续保留文字，不为了节省空间制造猜谜；
- 动效只服务于页面切换、分栏展开、运行状态和 momo 微表情；
- 适配最小窗口时优先保证输入、对话和当前文件可用，再折叠辅助文字与面板。
