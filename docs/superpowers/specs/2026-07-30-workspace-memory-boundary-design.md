## 一、结论

Leemo 采用“原生 Auto Memory + Leemo 治理层”，但不把底层 Harness 的产品心智暴露给用户。

这张卡先解决三个会直接破坏信任的问题：

1. 普通文档和代码不得因为 momo 判断失误而写进长期记忆；
2. momo 记住的当前事实必须能随时间更新，同时保留可查询的历史；
3. 完整时间和来源保存在本地，但不能把整份元数据账本塞进每轮上下文。

遗忘曲线和后台 LLM 定时整理是已经确认的后续能力，不从路线图删除；当前卡先把边界、版本、来源、撤销与上下文预算做对。

## 二、用户心智与物理边界

### 2.1 用户只需要理解四个词

| 用户看到的概念 | 含义 | 不是 |
|---|---|---|
| 本子 | 一个真实文件夹，也是一个项目/课程的工作范围 | 数据库标签、虚拟空间 |
| 默认工作区 | 没有进入本子时，普通产物的物理兜底目录 | 本子、人格、独立记忆范围 |
| 产物 | 汇总展示各本子与默认工作区中真实文件的虚拟总览 | 又一份文件、复制仓库 |
| momo 记得的 | momo 对用户和各本子的长期理解 | 普通文件夹、聊天记录全文 |

`momo` 在根视野中仍能看见所有本子。默认工作区不拥有独立人格、对话范围或记忆；它只是普通文件无处归类时的落点。

### 2.2 路径真相

```text
~/Leemo/
  默认工作区/                 # 无本子时的普通产物，不是本子
  <本子名>/                   # 本子就是工作区
    .leemo/                   # 对话与本子内部状态，不在普通文件树展示
      memory/                 # 本子记忆，随本子一起迁移
  .leemo/
    memory/                   # 全局记忆内部文件，不在普通文件树展示
  .claude/skills/             # 技能运行资源，不属于用户记忆
```

“产物”不新建物理目录。它按需读取默认工作区和各本子中的真实文件，并始终显示来源位置。

当前代码中的 `Inbox` 迁移为用户可理解的 `默认工作区`。升级时保留兼容读取和可撤销迁移，不能产生第二份兜底目录或丢文件。

主人格对话的 cwd 继续是 `~/Leemo/` 根，保证 momo 保有跨本子的全局视野；`默认工作区` 只是普通产物的默认写入目标，不能通过偷偷修改 cwd 获得。Host 向会话提供明确的默认产物目录，并在标准文件写入工具执行前把无本子的相对产物路径解析到该目录。用户明确指定其他位置时仍按真实权限流程处理，不能把“默认落点”做成新的沙箱。

## 三、写入决策表

| 用户行为或信息 | 写入位置 | 规则 |
|---|---|---|
| 在某个本子里要求写报告、代码、笔记 | 当前本子 | 文件工具的 cwd 与用户看到的本子一致 |
| 未进入本子时要求写普通文件 | `默认工作区` | 不写根目录，不写 memory |
| 用户明确说“记住……” | 全局记忆或当前本子记忆 | 按语义确定作用域，必要时轻量确认 |
| 用户清楚表达长期偏好、稳定画像、重要目标 | 全局记忆 | 自动写入并显示轻量回执 |
| 当前本子的目标、约定、关键决策、进度、下一步 | 本子记忆 | 只在本子内生效 |
| 当前聊天的草稿、临时推理、一次性细节 | 会话工作记忆 | 会话结束后不自动持久化 |
| 研究报告、网页摘要、代码、表格、图片等成果 | 工作区文件 | 即使内容讨论“记忆”，也不是用户记忆 |
| 未确认推测 | 不持久化 | 可留在当前会话，不能升级为事实 |
| API Key、密码、令牌、身份证号等秘密 | 不持久化 | 即使出现在对话或文件中也不得自动记忆 |

文件名、主题或正文里出现 `memory`、`记忆`，不能作为分类依据。写入位置由用户意图、当前本子范围和产物类型共同决定。

## 四、架构

### 4.1 原生 Auto Memory

Leemo 对 SDK 显式设置：

- `autoMemoryEnabled = rememberMode`；
- `autoMemoryDirectory` 指向 Leemo 拥有的当前作用域；
- `autoDreamEnabled = false`，首版不允许服务器默认值触发隐形模型调用。

无本子对话的原生记忆目标是全局记忆；本子对话的原生记忆目标是对应本子的 `.leemo/memory/`。本子对话仍可读取压缩后的全局当前画像，但写入默认落到本子范围，除非内容明确属于跨本子的用户事实。

原生 Auto Memory 是能力底座，不是产品边界的唯一裁判。Leemo 治理层负责作用域、敏感信息过滤、变更来源、轻量回执、撤销、纠正和重启恢复。

### 4.2 Leemo 治理层

每个全局或本子作用域只维护固定数量的 Leemo 治理文件：

- 一个紧凑的“当前视图”，供当前上下文使用；
- 一个追加式变更账本，保存来源、时间、替代和撤销信息。

搜索索引使用一个应用级可重建索引，不作为用户数据的唯一真源，也不随每个本子复制一套数据库。Leemo 不为每条记忆或每次对话创建独立小文件。SDK 自身产生的文件要纳入数量与体积验收；若其默认行为导致无界小文件增长，治理层必须合并或限制，而不是把成本留给安装、备份和文件扫描。

### 4.3 运行时分工

```text
对话内容
  -> 原生 Auto Memory 判断候选内容
  -> Leemo 治理层检查作用域、敏感性和变化
  -> 写当前视图 + 追加变更账本
  -> 成功落盘后才显示“记住了 · 撤销”

新一轮对话
  -> 注入少量全局当前视图
  -> 有本子时叠加少量本子当前视图
  -> 只有问题需要历史时才检索时间与来源
```

不能继续把整个 `~/Leemo/CLAUDE.md` 和本子 `CLAUDE.md` 当成无限增长的提示词全文注入。

## 五、记忆分层

记忆同时按“作用域”和“语义类型”组织，不能用一个目录名混合表达两种维度。

### 5.1 作用域

- **会话**：当前对话工作记忆，默认不持久化；
- **全局**：跨对话理解用户；
- **本子**：只属于一个课程、项目或求职任务；
- **历史**：已结束、被纠正或被替代，但仍可回答过去问题的内容。

### 5.2 语义类型

- **基本画像**：姓名、自我认同、MBTI 等高稳定信息；
- **偏好与习惯**：表达风格、工具、工作方式、喜恶和雷区；
- **当前近况**：学校、工作、所在地、求职阶段、最近在做什么；
- **目标与计划**：长期方向、近期计划和重要约束；
- **重要经历与关系**：对后续理解用户有持续意义的事件与人物；
- **本子上下文**：目标、关键决策、约定、进度和下一步。

“程序记忆”不混入用户画像。可执行流程继续属于 Skills、MCP 和 Agent 能力；只有“用户偏好 momo 怎样做事”才属于个人偏好。

## 六、时间与版本模型

每条持久记忆在存储层可具有以下字段：

```text
id / scope / kind / statement
learnedAt                 # momo 什么时候得知
validFrom / validTo       # 事实实际从何时到何时成立
lastConfirmedAt           # 最近一次由用户确认
sourceConversationId / sourceMessageId
sourceType                # 用户明确陈述、导入、迁移等
status                    # current / uncertain / superseded / deleted
supersedes / confidence / pinned
```

这些字段是本地存储和检索信息，不是常驻提示词格式。普通聊天只看到一句压缩后的当前结论；只有处理冲突、历史追问、时效判断或记忆管理时才取回必要字段。

### 6.1 更新而不是覆盖

- 新事实不物理覆盖旧事实；
- 明确更新会结束旧记录的有效区间，并建立新版本；
- 用户明确纠正高于模型推测、出现频率和时间新旧；
- 无法判断是补充还是替代时，标记待确认，不擅自选一个；
- 当前回答只使用有效版本，历史问题可使用旧版本。

例如“去年在 A 公司实习，现在准备秋招”同时包含两个时间事实。Leemo 回答“去年”和“现在”时应得到不同结果。

### 6.2 不存在真正不可变的画像

MBTI 等信息属于“高稳定、默认不衰减、可被用户纠正”，而不是永久真理。当前近况则必须带时效：过久未确认时使用“截至某日”的表达，不能装作仍然确定。

## 七、上下文预算

### 7.1 三层预算

| 层 | 内容 | 是否进入每轮上下文 |
|---|---|---|
| 磁盘账本 | 完整来源、时间、版本、撤销历史 | 否 |
| 当前视图 | 当前有效的压缩事实 | 少量进入 |
| 按需检索包 | 与当前问题直接相关的历史与证据 | 仅需要时进入 |

首版默认预算：

- 全局当前视图最多 600 tokens；
- 当前本子视图最多 400 tokens；
- 单轮按需历史检索最多 600 tokens；
- 所有记忆内容合计硬上限 1600 tokens。

未使用的某层预算不自动用来灌入更多低价值记忆。达到上限时按作用域匹配、用户明确程度、当前有效性、相关性和重要性排序，而不是简单截断文件尾部。

### 7.2 常驻内容必须是结论，不是账本

常驻当前视图只保留类似以下内容：

```text
- 自我认同：ENTP（用户明确陈述，当前）
- 回答偏好：先给结论，再解释关键取舍
- 当前阶段：正在求职（截至 2026-07）
```

不附带消息 ID、完整时间四元组、置信度小数、JSON 字段或整段原对话。需要解释“为什么记得”时再查询来源。

## 八、写入、纠正与召回规则

### 8.1 自动写入

满足以下任一条件且边界清楚时，可以自动写入：

- 用户明确要求记住；
- 用户清楚陈述有跨会话价值的画像、偏好、近况或目标；
- 用户明确更新既有事实；
- 当前本子形成了会影响后续工作的关键决策、进度或约定。

强情绪、重复提及或模型认为“很重要”只能作为候选信号，不能替代用户事实。未确认推测不进入持久记忆。

### 8.2 轻量回执

成功落盘后，只在本轮助手消息的元信息行显示：

```text
记住了：正在准备秋招 · 撤销
```

不使用独立卡片、气泡、Toast、动画或通知，不推动滚动位置。一次回复写入多条时合并为一行摘要。点击撤销必须恢复写入前的当前状态，并保留可审计撤销事件。

### 8.3 召回

- 全局当前画像可用于搭子态和工作台态；
- 本子记忆只在对应本子生效；
- 历史和来源默认不注入，只有相关时才检索；
- 旧近况不能以现在时回答；
- 找不到可靠记忆时明确说不知道或询问，不能补写一个看似合理的事实；
- 记忆被用于影响回答时，用户可从低调的来源入口查看原因并纠正。

首版优先使用结构化字段、时间过滤和本地全文搜索。只有真实长期对话评测证明关键词与时间检索不够，才增加本地 embedding；不为架构想象提前引入模型、依赖和安装体积。

## 九、设置与管理界面

设置中的记忆入口使用用户能理解的名称，例如“momo 记得的”，不展示 Auto Memory、RAG、向量库或底层 Harness 名称。

基础能力：

- 总开关：关闭后当前对话不读取也不写入长期记忆；
- 当前画像：以自然语言查看 momo 现在如何理解用户；
- 本子记忆：从具体本子进入，只显示该本子的目标、决策、进度和下一步；
- 编辑、纠正、删除、钉住；
- 查看历史和来源；
- 打开本地源文件，供高级用户检查和备份。

界面筛选使用“现在的我 / 长期偏好 / 重要经历 / 本子”等人话，不把内部 schema 直接做成导航。

## 十、旧数据迁移

### 10.1 旧记忆库

当前 `~/Leemo/CLAUDE.md`、`memory/profile.md`、`preferences.md`、`bookmarks.md`、`moments.md` 作为旧格式候选来源。迁移必须：

1. 只从已知旧记忆文件提取候选，不把 `memory/` 下任意 Markdown 自动当画像；
2. 不把旧索引全文继续注入新提示词；
3. 为迁移记录来源和时间，允许撤销；
4. 原文件在迁移成功和验证前不删除；
5. 发现冲突时保留为待确认，不静默覆盖。

`C:\Users\Example\Leemo\memory\research-ai-memory.md` 是回归样例：它是普通研究成果，不是用户画像。升级后它不得进入记忆上下文；应通过可撤销迁移进入默认工作区，且旧索引引用同步清理。

### 10.2 旧 Inbox

若只有 `Inbox`，升级时原子迁移为 `默认工作区`；若两者同时存在，不静默覆盖重名文件，先继续兼容读取并给出一次清理动作。失败时保持旧目录可用。

## 十一、失败与恢复

- 原生 Auto Memory 当前版本不可用时，显式“记住”仍由 Leemo 治理层安全落盘；自动记忆显示为暂不可用，不能假装成功；
- 写入或账本追加失败时不显示“记住了”；
- 当前视图损坏时可从变更账本重建；
- 搜索索引损坏时可从本地源文件重建；
- 重启后未完成的记忆变更要么完整恢复，要么完整回滚，不能出现半条当前事实；
- 关闭记忆后，已有数据不删除；用户主动删除时明确作用域并完成真实删除；
- 日志不记录秘密、完整记忆正文或用户文件绝对路径。

## 十二、已经确认的后续路线

### 12.1 当前必须做

1. 修正默认工作区、普通产物与记忆写入边界；
2. 接通并验证原生 Auto Memory 的读写开关与作用域；
3. 建立当前视图、时间版本、来源、纠正、删除、撤销；
4. 建立全局与本子记忆，并完成重启恢复；
5. 用真实打包应用验证上下文预算和用户路径。

### 12.2 基础稳定后做，已进入 TODO

1. **遗忘曲线**：只降低召回优先级，不删除历史真相；钉住和高稳定画像不衰减，当前近况过期后转为待确认；
2. **后台 LLM 定时整理**：支持手动和可配置的空闲时整理，默认不静默消耗额度，执行去重、归纳、冲突建议和归档，并可撤销；
3. 基于真实长期对话评测决定是否增加本地 embedding；
4. 记忆被采用、纠正和撤销的本地质量统计，用于改进召回权重。

### 12.3 明确不在当前阶段做

- 知识图谱和复杂关系数据库；
- 每段对话一个 episode 文件；
- 云端记忆、跨设备同步和团队共享画像；
- 用微调把用户信息写进模型权重；
- 静默运行的付费反思任务；
- 为尚未出现的五年数据量提前重写整个存储层。

## 十三、验收标准

### 13.1 工作区边界

- 无本子时说“写一份调研报告”，文件出现在 `默认工作区`；
- 在本子内执行同一任务，文件出现在当前本子；
- 两种路径都不会把报告写进全局或本子 memory；
- 主人格仍能从根视野读取和整理所有本子，默认产物定向不能把 cwd 或视野缩到默认工作区；
- “产物”能看到两处真实文件并显示来源，不产生副本；
- 打包应用重启后路径、来源和当前本子保持正确。

### 13.2 全局记忆

- 用户明确说“我是 ENTP，记住”，下一次新对话能正确使用；
- 元信息行只出现轻量回执，并可撤销；
- 用户改为其他自我认同时，当前回答使用新值，历史仍能说明曾经的记录；
- 关闭记忆后不读取也不写入，重新打开后原有数据仍在；
- API Key 或密码不会被自动保存，也不会出现在回执、日志和源文件中。

### 13.3 时间与更新

- “去年在 A 实习，现在准备秋招”能分别回答过去和当前问题；
- 一条过久未确认的当前近况以“截至某日”表达，不伪装成当前确定事实；
- 用户纠正后旧值成为历史，不与新值同时注入当前视图；
- 询问来源时能定位到对应对话，普通聊天不携带完整来源元数据。

### 13.4 本子隔离

- A 本子的目标、决策、进度不会出现在 B 本子；
- 全局偏好在 A、B 两个本子都可用；
- 拷走一个本子时，其 `.leemo/memory/` 随文件夹移动；
- 默认工作区没有独立本子记忆和人格。

### 13.5 上下文与性能

- 常规全局对话的记忆上下文不超过 600 tokens；
- 常规本子对话的全局加本子当前视图不超过 1000 tokens；
- 触发历史检索后总记忆上下文不超过 1600 tokens；
- 提示词中没有完整账本、JSON 元数据、消息 ID 列表或全文历史；
- 长记忆只影响检索耗时，不线性增加每轮提示词；
- 对比安装包体积、解包文件数、启动时间和空闲内存，没有无法解释的明显回退。

### 13.6 发布包证据

- 单元测试覆盖作用域、更新、预算、迁移和敏感过滤；
- 打包用户路径覆盖写入、回执、撤销、跨会话召回、时间更新、本子隔离、关闭开关和重启；
- 主进程改动后必须重新打包并重启，不以 renderer mock 代替；
- 验收报告记录真实命令、截图、包哈希和残余风险。

## 十四、研究依据与取舍

- [LongMemEval](https://arxiv.org/abs/2410.10813) 将信息提取、跨会话推理、时间推理、知识更新和克制回答列为长期记忆的核心能力，并验证时间感知检索的价值；
- [Zep 时序记忆研究](https://arxiv.org/abs/2501.13956) 说明保留历史关系比覆盖当前事实更适合持续变化的信息；
- [Letta Context Hierarchy](https://docs.letta.com/v1-sdk/memory/context-hierarchy) 区分少量常驻重要信息和大量按需检索信息；
- [Generative Agents](https://arxiv.org/abs/2304.03442) 验证经历记录、反思和动态召回的组合，但反思成本和误归纳风险决定它不应先于基础治理；
- [OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq) 的当前产品设计强调自动更新、来源、纠正、删除和临时对话，说明用户可理解与可控制和记忆准确率同样重要。

Leemo 不直接复制任何一套研究原型。当前阶段选择“少量当前视图 + 本地时间账本 + 按需检索”，因为它能用最小依赖解决真实污染、过期和上下文膨胀问题，也最符合本地优先与低成本约束。
