## 一、结论

Leemo 在视觉总重构前新增一套完整但克制的个人工作闭环：

```text
随时捕获
  ↓
安静记录与整理
  ↓
转为真实待办，或交给 momo 执行
  ↓
提醒、完成、等待与成果回到同一工作台
```

它不是聊天里的另一张卡片，也不是把 OneNote、Notion 或 Todoist 全部重做一遍。它解决三个具体痛点：

1. 想到事情时，不必回桌面新建文件、打开手机或先决定保存到哪里；
2. 独立思考时，不被 AI 回复顶走内容或打断思路；
3. 记录、行动和 Agent 执行之间可以互相引用，而不是散落在聊天、文件和提醒中。

核心产品哲学是：

> **AI 原生不等于 AI 必须一直说话。AI 的价值是用户需要时，它能理解并操作用户的真实数据；用户独立思考时，沉默本身就是能力。**

## 二、用户只需要理解的五个概念

| 概念 | 用户心智 | 明确不是什么 |
| --- | --- | --- |
| 快速便签 | 用快捷键随时落下当前念头 | 一条必须发送给 AI 的消息 |
| 便签 | 比聊天可靠、比正式文件轻的持久记录 | 本子文件树里的隐藏 Markdown |
| 待办 | 用户明确要推进、完成或提醒的行动 | 便签里的每一个复选框 |
| 收集箱 | 尚未整理的便签状态 | 第四套存储或新的一级应用 |
| 工作看板 | 今天、便签和待办的统一工作面 | AI 自动编出来的日报或第二套 Agent 状态库 |

“本子”继续只表示真实本地文件夹。全局便签库、用户待办和本子可以建立引用关系，但不能偷偷改变彼此的物理边界。

## 三、整体信息架构

### 3.1 入口与主画布

- 工作台右侧工具栏继续保留「文件 / 概览 / 搜索」三个元能力。
- 点击「概览」后，中间主画布完整切换为工作看板，而不是只展开狭窄侧栏。
- 左侧全局本子与对话地图、右侧工具栏继续保留。
- 工作看板内部固定三个一级视图：`今天 / 便签 / 待办`。
- 再次点击已激活的「概览」或返回，可回到进入前的对话或文件工作面；草稿、附件和滚动位置不丢失。
- 打开单条便签时，同一主画布进入沉浸式编辑；聊天退出当前工作面，momo 不默认插话。

这项设计仅覆盖旧工作台规格中「概览」作为窄摘要面板的形态。Explorer、Search、本子和对话真源不改变；现有运行、等待、失败和成果仍来自原有事件与数据，不在看板中复制一份状态。

### 3.2 全局与本子范围

- 工作看板默认显示全局数据，因为快速捕获不属于单一本子。
- 顶部提供轻量范围筛选：`全部`或当前本子；筛选只是查询，不移动数据。
- 便签可关联一个本子，待办也可关联一个本子；未关联时保持全局。
- 将便签“转为本子文档”才会在真实文件夹中创建 Markdown；仅关联不会生成文件。

### 3.3 「今天」首页

首版不用满屏等权小卡片，而使用明确的信息优先级：

1. **今天要做**：今天计划推进、今天截止、已被用户钉到今天的普通待办；
2. **需要你处理**：Agent 正在等待审批、回答或已经失败的真实状态，只显示事实和入口；
3. **收集箱**：未整理便签数量与少量最近内容；
4. **继续记录**：置顶或最近编辑、尚未归档的便签。

AI 不自动写一段“今日总结”占据首页。每日回顾继续是独立能力；以后可作为用户主动添加的组件进入画布。

后续确定演进为可拖拽、可隐藏、可扩展的组件画布，承载日历、学习、科研、Agent 进度和成果等模块；首版的数据和视图边界必须允许这种演进，但不提前实现自由布局引擎。

## 四、快速捕获窗口

### 4.1 生命周期

- 默认全局快捷键为 `Alt+N`，可在设置中录制和修改。
- 快捷键冲突或注册失败必须说明原因并保留应用内「快速便签」入口，不能静默失效。
- 快捷窗口是单例：重复按快捷键只显示并聚焦已有窗口，不创建多个草稿窗口。
- 主窗口关闭后，Leemo 默认隐藏到系统托盘，快捷键仍然可用。
- 用户从托盘明确选择「退出 Leemo」后才真正退出；完全退出后快捷键不再唤起应用。

### 4.2 捕获语义

- 快捷窗口提供 `便签 / 待办` 两种模式，默认便签。
- 便签中的圆形复选框只是内部清单，不自动进入正式待办。
- 输入持续自动保存为草稿，不调用模型，不消耗额度。
- `Ctrl+S`：将当前非空内容收进全局便签库或待办区并关闭小窗。
- `Esc`或关闭按钮：只隐藏，下一次继续同一草稿。
- 空白草稿不生成记录。
- `Ctrl+Enter`不用于保存，保留给对话中的运行中追加引导。
- 标题可以为空；列表中使用首个非空文本片段作为显示摘要，用户进入完整编辑器后可补标题。

### 4.3 编辑能力

快捷窗口和完整便签编辑器共享同一种 Markdown 语义，但快捷窗口只露出高频动作：

- 标题、正文与注释块；
- 加粗；
- 有序列表、无序列表；
- 可点击圆形清单；
- 换行与段落；
- `Tab / Shift+Tab`调整列表层级；
- 撤销与重做；
- 粘贴图片、拖入图片与文件。

Windows 的 `Alt+Tab`必须保留给系统切换窗口，不得被编辑器劫持。表格、涂鸦、扫描、OCR、音视频录制和无限画布不进入首版。

### 4.4 视觉定稿

视觉基准：`docs/design-audition/visual-redesign/quick-capture-window-v1.png`。

- 快捷窗口采用约 `520 × 420px` 的独立桌面悬浮工具形态；视觉稿为方便审阅有所放大，实施时不得按整页比例放大；
- 不显示工作台侧栏、聊天气泡、momo 头像或 AI 回复，保持用户可以安静记录、不被对话打断的心智；
- 顶部只保留小型 Leemo 标识、标题、窗口控制与克制的「便签 / 待办」切换；默认便签，切换不使用大面积彩色分段按钮；
- 编辑正文是视觉主区。富文本工具栏固定放在正文上方，使用单行图标与必要分隔，不给每个动作套独立圆角方框；附件以紧凑条目呈现；
- 底栏同时说明自动保存、`Ctrl+S` 收下和 `Esc` 稍后继续，右侧保留一个明确但不过大的琥珀色「收下」主动作；
- 颜色、字体、线条、阴影与圆角继承工作台的暖中性色、深墨蓝与少量琥珀铜，不做手机 App、玻璃拟态或儿童便签风格。

## 五、完整便签应用

### 5.1 便签库

便签默认可以不分类。系统提供：

- 全部便签；
- 收集箱；
- 置顶；
- 最近编辑；
- 已归档；
- 回收站；
- 用户创建的轻量分组；
- 多个标签；
- 覆盖标题、正文、标签和附件名的搜索。

不复制 OneNote 的“笔记本 → 分区 → 页面”层级，避免与 Leemo 的真实文件夹「本子」冲突。分组和标签都是捕获后的可选整理动作。

### 5.2 沉浸编辑

- 编辑器直接呈现格式效果，用户无需操作 Markdown 源码。
- 底层保留清晰 Markdown 语义，复制给 AI 或转为文件时可迁移。
- 自动识别正文中的 `http` 与 `https` 链接；编辑状态下使用 `Ctrl + 点击`交给系统默认浏览器打开，普通点击仍用于定位光标和选择文字。
- 外链行为由全局共享组件提供，并在聊天 Markdown、便签、文件预览等可点击文本中保持一致；本地文件路径继续使用「打开文件 / 打开所在位置」，不与网页链接混用。
- 全局 Markdown 必须支持 `$...$` 行内公式与 `$$...$$` 块级公式。聊天正文、过程摘要、Markdown 文件预览和便签使用同一种数学排版；保存、编辑与复制时继续保留原始 LaTeX，而不是把公式栅格化成图片。
- 工具栏使用渐进披露：固定高频操作，其余格式和附件动作进入紧凑菜单。
- 用户独立编辑时不显示 AI 回复流。
- 需要帮助时，用户可从选择菜单或明确按钮调用 momo，例如“整理这段”“提取待办”“转为本子文档”；默认不自动调用。

### 5.3 与本子和 AI 的关系

- 关联本子只建立查询和上下文关系，不生成文件。
- 明确选择「转为本子文档」后，在真实文件夹中创建 `.md`；原便签保留，并显示双向来源入口。
- 聊天输入区的 `@`搜索应能引用一条或多条便签；引用传递结构化 note id 和当时可见内容，不复制出新的孤立便签。
- momo 读取或修改便签必须调用同一主进程服务，不能靠提示词维护影子清单。

## 六、待办与提醒

### 6.1 创建时轻量，但可以一次填完整

新建待办只有标题输入是默认主角；同一创建界面提供可展开的完整字段：

- 计划日期；
- 截止时间（DDL）；
- 提醒时间；
- 重复规则；
- 优先级；
- 本子关联；
- 补充说明；
- 来源便签。

用户可以只写一句话立即创建，也可以第一次就展开并一次设置完整。不能强迫用户先建一条残缺任务，再跳到待办详情二次补全。

无日期待办使用三态心智，避免把随手记录全部变成逾期负担：

1. **默认未标记**：创建当天先出现在「今天」，帮助用户马上看见；当日未完成时自动顺延到「不限期限」，不计为未完成或逾期；
2. **明确今天**：用户主动标记为今天要完成的承诺；跨日未完成后继续进入「未完成」，直到完成、改期或改为不限期限；
3. **明确不限期限**：从创建起就进入不限期限清单，不占用今天的承诺区。

快捷输入必须提供清楚但轻量的「今天 / 不限期限」切换；未操作时保持默认未标记，不能把“创建于今天”误当成用户承诺“今天必须完成”。

### 6.2 一个自适应输入区

- 短内容保持单行；粘贴长内容后自然扩展为多行。
- 不另放一个“智能粘贴”大文本框。
- 解析出的字段显示为可编辑、可移除标签，例如：`截止 周五 17:00`、`提醒 提前 2 小时`、`关联 求职本子`。
- 手动详情入口始终保留；智能识别与手动字段不是互斥模式。
- 保存前用户能看见所有解析结果，不允许后台偷偷决定字段。

### 6.3 本地优先、模型兜底

解析顺序固定：

1. 本地解析常见且唯一的日期、时间、重复和提醒表达；
2. 发现多个日期、多个时间或角色不明确时，不把第一个时间机械当作截止时间；
3. 设置允许且模型可用时，只把当前待办或用户选中的便签片段交给模型解析；
4. 模型结果仍以可编辑标签呈现；
5. 设置关闭、无模型或解析失败时，完整保留原文，不填写不确定字段。

「使用模型理解复杂待办」默认开启，设置中明确说明只在复杂歧义时调用，并可能消耗少量模型额度。不能上传整份便签库、无关附件或其他本子内容。

### 6.4 便签批量转待办

- 用户可选择多行、列表项或复选项，执行「转为待办」。
- Leemo 将内容拆成多条候选，而不是一个超长任务。
- 原位展开紧凑批量预览；每条候选可取消、修改标题、修正解析标签。
- 日期、本子等共同字段可一次应用到全部候选，再逐条覆盖。
- 最终按钮明确显示「创建 N 条待办」。
- 原便签不被剪走；每条待办保存来源 note id 和对应原文快照，便签侧显示已转出任务入口。即使便签后来被编辑，任务仍能展示当时的来源内容。

### 6.5 momo 自然语言管理

用户可以直接说：

- “帮我记一条待办，周五前交简历，提前两小时提醒”；
- “把刚才那三条都加到待办”；
- “把求职本子里那条简历待办改到下周一”；
- “这条完成了”；
- “删掉刚才记错的提醒”。

momo 必须调用与界面相同的待办服务，真实新增、修改、完成、删除和注册提醒。明确时直接执行并轻量回执；歧义影响执行时才追问。不能只在聊天里答应“我会提醒你”。

## 七、后台常驻、提醒与运行中引导

### 7.1 托盘与启动

- 「关闭窗口后在后台继续运行」默认开启。
- 「开机时自动启动 Leemo」默认关闭，与后台常驻分开设置。
- 主窗口隐藏后不占 Windows 任务栏；系统托盘提供：打开 Leemo、快速便签、退出 Leemo。
- 隐藏状态不重复挂载完整 renderer，也不让模型、轮询或空闲任务无意义运行。

### 7.2 系统通知

系统通知覆盖：

- 用户待办提醒；
- Agent 任务完成；
- Agent 等待审批或回答；
- Agent 任务失败。

点击通知回到对应待办或对话。窗口已聚焦且用户正查看对应内容时不重复弹系统通知。通知设置可按类别关闭。

### 7.3 运行中追加引导是相邻独立卡

`Ctrl+Enter`保留给对话运行中的追加引导：

- 支持原生 steer 的运行时把消息送入当前 active turn；
- 暂不支持时仍收下、不停止当前任务，并标记「下一步会采用」；本轮结束后自动继续；
- `追加引导`、`停止`和空闲时的普通新消息必须是三种不同动作。

这项通用 Agent 能力必须在视觉总重构前完成，但不混入快速便签的数据模型和快捷窗口实现。

## 八、数据、附件与存储

### 8.1 单一真源

主进程 SQLite 保存：

- `QuickDraft`：快捷窗口唯一未收下草稿及当前模式；
- `Note`：标题、Markdown 正文、状态、置顶、分组、标签、本子关联和时间；
- `UserTask`：标题、说明、状态、计划日期、截止、提醒、重复、优先级、本子和来源；
- `NoteTaskLink`：任务与来源便签、来源原文快照的关系；
- `Attachment`：图片、复制文件或外部路径引用；
- `TrashMetadata`：删除时间和到期清理信息。

Inbox、Today、置顶、最近编辑和工作看板都只是查询视图，不建立第二套存储。AgentRun、Artifact、ScheduledTask 继续复用既有真源。

### 8.2 图片与普通文件

- 粘贴或拖入图片时，复制到 Leemo 管理的持久附件目录。
- 普通文件默认只记录原始绝对路径和展示信息，不复制。
- 设置可切换为「拖入文件时保存副本」；开启后，未来拖入的普通文件复制到托管目录，不逐次弹窗。
- 切换设置不追溯改变已有附件。
- 文件卡提供打开文件与打开所在文件夹。
- 「打开文件」必须交给系统默认应用；「在资源管理器中显示」必须打开文件所在目录并尽可能选中目标文件。外部引用和 Leemo 保存的副本使用同一套入口，用户无需先理解存储类型。
- 外部路径引用失效时保留卡片和原路径，说明文件已移动或不可用；不能把引用失败误报为便签损坏。

### 8.3 一个可见的全局文件存储位置

设置页提供一个「Leemo 文件存储位置」，下设可见子目录：

- 收集箱附件；
- 便签图片；
- 文件副本；
- 下载与可清理缓存；
- 回收站中的托管附件。

设置页显示当前路径、各类别占用、总占用和目标磁盘剩余空间，并提供打开文件夹和更改位置。数据库、设置等小型内部数据可以留在应用数据目录；本子仍留在用户选择的真实位置。

首次需要持久保存图片或大文件前，用户必须看见并确认该位置；不能静默把增长型内容持续写进 C 盘。如果存在非系统固定磁盘，可推荐空间充足的位置，但不能在用户不知道的情况下自行选择陌生目录。

### 8.4 更改位置与迁移

- 更改位置时先计算现有托管数据量和目标可用空间。
- 迁移期间显示进度，新的附件写入遵循同一迁移锁，避免两边分裂。
- 先复制已有托管文件并核对预期文件集合与大小；不为普通复制引入内容寻址或对每个文件做多轮密码学审计。
- 只有迁移完整成功后才切换配置并清理旧副本。
- 失败或取消时继续使用原位置，原文件不受损。

### 8.5 回收站

- 删除便签只移入 Leemo 回收站，不弹确认框，并提供轻量撤销；回收站主页面默认只展示便签。
- 删除待办是更轻的整理动作：立即从待办列表移除并提供短暂撤销；错过撤销后，可从回收站中的低调入口「查看已删除待办」找回，但不与便签并排占据主页面。
- 便签与已删除待办都默认保留 30 天；用户可以恢复或提前彻底删除。
- 只有「彻底删除」需要确认；当前不提供醒目的「清空回收站」，避免把低频危险操作做成主能力。
- 便签拥有的托管图片和文件副本随记录进入回收站，清理后再删除。
- 仅引用的外部原文件永远不被 Leemo 删除。

## 九、设置中的用户语言

| 设置区域 | 用户看到的设置 | 默认值 |
| --- | --- | --- |
| 通用 | 关闭窗口后在后台继续运行 | 开启 |
| 通用 | 开机时自动启动 Leemo | 关闭 |
| 快捷键 | 快速便签 | `Alt+N` |
| 便签与待办 | 拖入文件时保存副本 | 关闭 |
| 便签与待办 | 使用模型理解复杂待办 | 开启 |
| 文件与存储 | Leemo 文件存储位置、占用与迁移 | 首次使用前确认 |
| 通知 | 待办提醒、任务完成、等你处理、任务失败 | 开启，可分项关闭 |

普通设置中不出现 SQLite、renderer、IPC、Claude Code、模型别名或内部路径键名。

## 十、最小工程形态

### 10.1 主进程

- 一个 `CaptureAdmin`或等价域服务管理便签、待办、草稿、附件、提醒与回收站。
- 复用现有 SQLite 连接和迁移体系，不引入第二个数据库、向量库或常驻服务。
- 快捷窗口使用独立、窄权限 preload 与 IPC，只暴露捕获所需方法。
- 快捷窗口和主窗口保存后由主进程广播变更，两个 renderer 都从同一真源重取或增量更新。
- 全局快捷键、Tray、系统通知和开机启动由 Electron 主进程管理。
- momo 的便签 / 待办工具调用同一 Admin，不直接写数据库文件。

### 10.2 Renderer

- 快捷窗口使用独立轻量 surface，不重新挂载完整 `App`、模型连接和工作区 stores。
- 主工作看板有统一 store，但数据真源仍在主进程。
- 便签编辑器可以复用现有 Markdown 工具思路，但不能把当前文件预览 textarea 硬扩成两种产品；编辑核心需支持可点击清单、选择片段和来源转换。
- 不为每个字段创建一个小模块；按快捷窗口、工作看板、编辑器、待办解析和存储管理等真实边界组织代码。

## 十一、失败与恢复

| 场景 | 必须发生的行为 |
| --- | --- |
| 快捷键冲突 | 人话提示，保留原快捷键与应用内入口，可重新录制 |
| 快捷窗口崩溃或重启 | 恢复未收下草稿和模式，不生成重复便签 |
| 主窗口关闭 | 默认进托盘；Agent 和提醒继续；任务栏不残留窗口 |
| 真正退出 | 退出前持久化草稿，注销快捷键和托盘 |
| 外部引用文件移动 | 卡片保留并提示路径失效，不删除便签 |
| 模型解析失败 | 保留原文和本地结果，不填不确定字段，可手动设置 |
| 提醒注册失败 | 待办仍保存，但明确显示提醒未生效并允许重试 |
| 存储空间不足 | 迁移或复制前阻止写入，原位置与原文件保持可用 |
| 批量解析部分有歧义 | 只在预览中标记对应候选，不阻止用户修改其他条目 |
| 回收站恢复 | 记录、来源关系和仍存在的托管附件一起恢复 |

## 十三、实施顺序

1. **基础真源与生命周期**：SQLite 迁移、Admin、Tray、快捷键、快捷窗口草稿；
2. **安静记录闭环**：便签库、编辑器、图片 / 文件、工作看板「今天 / 便签」；
3. **行动闭环**：待办详情、提醒、本地解析、批量转换、回收站；
4. **AI 与存储接线**：复杂解析、momo CRUD、`@`引用、存储位置与迁移；
5. **用户路径验收**：打包环境下测试快捷键、托盘、通知、重启、失败和 C 盘边界；
6. **相邻通用能力**：单独完成运行中追加引导；随后进入前端视觉总重构。

每步使用聚焦 TDD 和一次用户路径验收，不建立庞大测试矩阵，也不为简单文件复制引入不必要的多轮哈希审计。数据丢失、系统盘挤满、权限泄漏和假成功仍属于必须修复的真实风险。

## 十四、验收路径

1. **随手记**：主窗口隐藏时按 `Alt+N`，输入、粘图、`Ctrl+S`；工作看板立即出现，重启后仍在；
2. **中途退出**：输入一半按 `Esc`或重启，重新唤起继续，不生成重复记录；
3. **完整待办**：第一次创建时一次填入计划日、DDL、提醒、本子和说明，保存后通知按时出现；
4. **自然语言**：输入一个明确时间得到可编辑标签；输入两个角色不清的时间不会机械误填，模型关闭时保留原文；
5. **批量转换**：便签五行只选择四行，预览修正一项后生成四条待办，四条都能回到原便签来源；
6. **momo 接线**：让 momo 新增和修改待办，界面立即可见且提醒真实注册；失败时不说“已经记住”；
7. **文件边界**：默认拖入普通文件只引用；副本模式保存到可见位置；外部文件移动后便签不损坏；
8. **迁移**：将存储位置从系统盘改到其他盘，已有托管附件真实迁移，失败时原路径仍可用；
9. **删除恢复**：删除便签后从回收站恢复，正文、来源和托管附件仍在，外部原文件从未被删除；
10. **后台任务**：关闭主窗口后任务继续，完成 / 等待 / 失败通知点击回到正确会话；真正退出后不再占托盘或响应快捷键；
11. **安静工作**：用户在完整便签或待办界面连续编辑，不出现未经召唤的 AI 回复、自动改写或强制分类；
12. **性能**：快捷窗口不挂载完整主应用，后台空闲不启动模型；长便签和大量列表下仍可正常输入、滚动和保存。
