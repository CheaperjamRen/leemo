## 0 · 为什么有这一片

S2 目验① 暴露了**设计模型问题（非皮）**，用户 7/22 反馈定案：
1. **折叠错位**（真 bug）：`RunGroup` 把过程卡抽到组顶、输出沉底 → 用户消息排在折叠过程下方，像"上一轮的过程"。破坏「一个回合」的因果叙事。（S2 终审曾标记，当时误判为穿衣拍简化——实为 bug。）
2. **「完成」卡无意义**：成熟 agent 不盖"完成"章。`run.finished` 该产出**消息结束展示**（复制 + token 统计），默默收尾。
3. **计划卡该拎出来常驻**：Claude Code / Kimi / NewMax 都把当前任务的 todo+进度做成常驻可查面板。计划应钉在输入框上方（默认折叠，随手点开看"做什么、做到哪"）。
4. **缺"活着感"**：干活时无实时状态 + 无打断。
5. **缺智能滚动**：流式内容滚出视野无跟随；用户想安静看历史时无法暂停跟随。

## 1 · 核心渲染模型：严格时序自然叠加

**一条对话流 = items 按时序从上往下自然叠加**，第一条在顶，之后一条你一条我地往下排（普通聊天记录）。**不做"用户消息置顶成块"**——用户第一条自然在顶，后续 send 往下叠，不重新定位。

**一个回合（turn = 一个 runId）的结构**（完成态，默认折叠）：
```
                              帮我整理第五章的复习笔记      ← 用户气泡(右,在它发送的时序位置)
  😊 momo
     好，我先通读一遍，列个计划再动手。                    ← momo 开场文字
     ▸ 查看过程 · 计划 + 3 个工具                          ← 过程折叠条(原位,run 完成→默认折叠)
     草稿好了。第五章主线是「遍历」…                       ← momo 最终回答
     ⧉ 复制    ↑2.4k ↓0.6k                                ← 消息页脚(替掉「完成」卡)
```

**进行中态**（展开 + 活着感）：
```
                              帮我整理第五章的复习笔记
  😊 momo   ⟳ 正在读取 第五章.pptx…                 ◼ 停止   ← liveness 状态行 + 打断
     好，我先通读一遍…
     [计划 2/4] [Read 完成] [Grep 完成] [Write 进行中…] 分身·1  ──压缩──  (过程原位展开)
```

**渲染规则**（`TurnBlock`，纯时序单遍）：按 items 顺序渲染；`text` 按 role 出气泡；**连续的过程项（tool/plan/activity/compact）就地聚成一个折叠段**（run 完成→默认折叠，进行中→展开）；`result` 渲染为**页脚**（非"完成"卡）；`usage` 被同 run 页脚消费；错误 inline 显示。过程折叠**长在它真实发生的位置**，绝不浮顶。

## 2 · runId = 回合 id（store 改动）

S2 用固定 `RENDERER_RUN_ID_INITIAL`，导致所有 items 同 run（用户+momo 混在一组，正是折叠错位根因）。本片：**每次 `send` 起一个新 runId**（`run-1`/`run-2`…）。一个 turn = 用户消息(runId N) + momo 对它的响应 items(runId N)。`groupByRun`（S2 已建，forward-compat）由此真正区分回合。

**gate#1 不碰**：`client.subscribe` 结构原样（top-level、无 unsubscribe）；只把 callback 读的 runId 从 const 改为工厂作用域的可变（`send` 更新，callback 读当前值）。

## 3 · reducer 补缺（停止丢弃）

S2 reducer 在 `default` 丢弃了 `usage.final`（token 数据）和 `error`（报错）。本片：
- `usage.final` → 追加 `{ kind:"usage"; runId; usage: UsageRecord }` 项（页脚读它出 token 统计）。
- `error` → 追加 `{ kind:"error"; runId; message }` 项（inline 显示，不静默）。
- `result` 项**保留**（carrier of finalText/pathAudit/isError），但**渲染为页脚**（复制读 finalText、token 读同 run 的 usage 项、路径越界警示读 pathAudit），不再是「完成」卡。
- `thinking.delta` 继续 defer（thinking 折叠段留后续片，YAGNI）。

新增两个 `TimelineItem` variant：`usage`、`error`。

## 5 · liveness + 打断（store + fixture）

- store 新增 `activeRunId: string | null`（send 设、run.finished 清）+ `interrupt(): Promise<void>`（invoke `bridge:interrupt`）。
- `InputBox`：`activeRunId !== null` 时发送键变**停止键**（调 interrupt）。
- fixture：`invoke("bridge:interrupt")` → 清待发定时器 + emit `run.finished{subtype:"interrupted"}` 让 UI 收敛。**gate#2 不碰**：新增 `case "bridge:interrupt"` 在 default 之前，`default: return undefined` 原样。
- `LiveStatusBar`：读 activeRunId 对应回合的最新进行中工具名出状态（如"正在读取 X"），配停止按钮。

## 6 · 智能滚动（用户 7/22 明确细节）

`Timeline` 外层为滚动容器（固定高度区）。行为：
- 贴底时**自动跟随**流式边缘。
- 用户**手动上划 → 中断自动跟随**（安静看历史输出，即使 agent 在继续输出）。
- 右下角悬浮**「回到底部」按钮**（样式做好看：圆形/胶囊 + 阴影 + 图标，出现有淡入）。
- 点按钮 → 回到最新消息底部 + **重开自动跟随**，直到用户再次上划中断（按钮再现）。

## 7 · 明确不做（S2.5 边界）

- 审批条 / 问询卡（回投）= **S3**。
- 可视化卡 / 真产物卡 = **S4**（契约现无 artifact 事件，硬造是臆测；产物留 S4）。
- thinking 折叠段 = 后续（YAGNI）。
- token **费用**（¥）= 不显示（gate#1 costSource 未修）；页脚只显示 token 数（fixture ↑2.4k↓0.6k），不显示 live cost。
- 真 bridge / Electron / SQLite = Phase-1。

## 8 · 硬约束（继承，全适用）

- hexagonal 铁律：组件经 context hooks 读 store，禁直连端口（`guard.test.ts` 守卫）。Timeline/TurnBlock/PinnedPlan 经 `useConversations`；纯卡读 props。
- **两个 Phase-1 gate 不碰**：gate#1 store 订阅生命周期（只改 runId 来源，不动 subscribe 结构/不加 unsubscribe）；gate#2 fixture invoke default（新增 interrupt case，不动 default 分支）。
- TDD：reducer/store/逻辑=严格测试；纯视觉=用户目验（穿衣拍）。
- 只 `import type` from contract；不改 `src/bridge/**`、`src/gateway/**`。
- 命名仅 Leemo/momo；用户可见名词只 本子/成果。
- 不回归：S2 的 262 基线全绿；typecheck 三段 exit 0。
