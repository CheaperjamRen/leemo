# Leemo 英语学习看板设计

> 日期：2026-08-02
> 状态：方案已获用户确认；P0 数据闭环已完成 Integrated 验收，P1 原生看板待开发
> 目标：让用户每天打开 Leemo 后，立刻知道今天学什么、能当场练习、能看到自己是否真的进步。

## 一、结论

英语学习适合做看板，但不是因为可拖拽卡片新鲜，而是因为它同时包含四种需要长期保持可见的认知任务：追踪计划、主动回忆、比较前后表现、进入下一次练习。

首版采用 **英语专用的原生学习面板**，复用现有 `LearningSnapshot`、FSRS 复习队列和 momo 学习工具。暂不建设任意 HTML、任意数据绑定、任意拖拽编排的通用 Canvas 平台。只有当真实用户反复提出自定义、固定或组合组件的需求，再把同一套学习组件升级为通用的“对话内组件 -> 固定到看板 -> 全屏查看”协议。

看板不是聊天的替代品：目标澄清、水平诊断、开放讨论和陪伴仍由 momo 在对话里完成；看板只承接已经收敛、需要重复操作或长期追踪的内容。

## 二、从 Kimi 学到什么

以下结论来自 2026-08-02 对 Kimi Work、Kimi Chat、本机 Blueprint 数据和客户端打包代码的只读核验。

### 2.1 产品原则

- 信息载体服务于用户当前的认知动作，而不是为回答增加装饰。
- 表格适合比较，时间线适合追踪，树适合理解层级，交互组件适合探索和反复操作。
- 组件不是更高级的答案，而是更昂贵的答案。只有节省的认知成本大于界面、开发和维护成本时才使用。
- 情绪陪伴、尚未收敛的探索、保留歧义的表达不应被强行切成卡片。
- 好的结构让用户只感到“很清楚”，而不是感到自己在学习一套界面。

### 2.2 工程原则

Kimi 的实现将四个概念分开：

1. Canvas 只保存摆放、尺寸、层级和每个挂载点的视图状态。
2. Widget 只负责显示数据和发出结构化事件。
3. Automation 独立执行 Python 或 Agent 任务，返回有 schema 的 artifact。
4. Binding 只描述 Automation 结果如何进入 Widget。

静态内容不创建 Automation；需要运行或刷新的内容才创建 Automation + Binding。Widget 位于隔离 iframe，第三方请求由 Automation 处理；运行失败时保留上一次成功结果。对已有看板的修改优先更新现有组件，不重复创建。

Leemo 首版不照搬四套通用资源模型，但保留这个边界：**学习记录、任务执行、页面视图互不拥有彼此的数据**。

## 三、英语看板的用户旅程

### 3.1 首次使用

1. 用户填写真实目标、重点方向和每天可投入时间。
2. 点击“开始诊断”，进入一段由 momo 主持的短对话；一次只给一个小任务。
3. momo 通过学习工具记录基线、错误和可复测证据。
4. 用户回到英语学习页，看到由真实记录生成的第一份计划和复习队列。

首屏不要求用户理解 FSRS、技能分类、Automation 或模型角色。

### 3.2 每日使用

1. 打开英语学习页，第一视线看到“今天要做什么”和预计用时。
2. 先在看板内完成到期回忆，不跳转、不先展示答案。
3. 再进入一个贴近目标的小任务；需要开放表达时进入 momo 对话。
4. 完成后回到看板，看到今天新增的证据和下一次复习时间。

### 3.3 一周后

用户看到同型任务的前后对比，而不是只看到连续打卡天数。进步必须能回答：“以前哪类任务做不到，现在能做到什么？”

## 四、首版信息架构

页面保持工作台现有左侧导航，内容区采用稳定的 12 列响应式网格。桌面宽度下主列 8、辅列 4；窄屏单列。每个组件是独立工具，不在卡片里再套卡片。

### 4.1 今日练习

主组件，显示今天的任务顺序、预计总时长和一个主按钮。未开始、进行中、已完成三个状态共用稳定尺寸；中断后显示“继续今天的练习”，不重新生成一份任务。

首版任务由到期复习数量、用户目标、每日分钟数和最近一次表现派生。任务细节仍由 momo 生成，页面不复制一套教学 Agent。

### 4.2 到期复习

这是首个值得在看板内直接交互的组件：

- 一次只显示一个题面；
- 用户先口述或输入自己的答案，再揭示纠正与解释；
- 用户按“没想起 / 有点难 / 记住了 / 很轻松”评价；
- 评价直接写入现有 FSRS 账本，切换页面和重启后仍然一致；
- 显示当前进度，例如 `3 / 8`，不显示会诱导刷数的夸张动画。

若题目来源于某次对话，可从细节进入原对话，但默认不暴露内部 ID。

### 4.3 进步证据

按词汇、语法、阅读、写作、表达展示最近可比任务的变化。只有存在基线和后测时才画变化；样本不足时明确写“完成一次同类练习后可比较”，不得用零值伪装成绩。

首版采用紧凑的数值与短说明，不上复杂图表。积累到至少三个可比时间点后再启用趋势线。

### 4.4 阅读练习入口

提供“选择本地材料”和“让 momo 推荐一段”两个动作。首版只负责建立带材料上下文的真实练习对话，不在页面里另造一个阅读器。以后可把选句解释、词汇回收和段落复述升级为对话内交互组件。

### 4.5 学习节奏

辅组件只显示下一次复习、最近完成和计划时间，不用连续打卡作为主价值。等定时任务与英语计划完成接线后，再提供“每天几点提醒”的轻量入口。

## 五、数据和职责边界

```text
SQLite 学习账本
  -> LearningService：计划、错题、FSRS、会话证据
  -> leemo-learning MCP：供 momo 读取和写入真实记录
  -> IPC LearningClient：供页面读取和完成直接复习
  -> Learning store：只保留当前快照与请求状态
  -> 原生 React 组件：今日练习、复习、证据、入口
```

- SQLite 是学习状态真源；对话 Markdown 和组件本地状态都不是。
- momo 负责教学内容和开放任务，看板负责稳定呈现与短交互。
- 页面完成复习时调用与 MCP 相同的 `LearningService.rateReview`，不实现第二套算法。
- 组件只消费面向界面的 view model，不读取数据库、不直连 Electron IPC。
- 请求失败时保留上一次成功快照并标记“暂时没有更新”，不把失败渲染成空数据。

## 六、与通用交互可视化的关系

现有 `leemo-visualization` 适合一次性的解释、模拟和图表产物；英语看板适合长期状态与重复练习。二者暂时不合并。

后续只有满足以下条件才进入通用组件协议：

1. 同一个学习组件确实需要同时出现在对话、看板和全屏视图；
2. 用户有固定、移除或重排组件的真实需求；
3. 组件能声明输入、输出、加载、错误和上次成功状态；
4. 沙箱、权限、文件引用和持久化已有明确边界；
5. 安装体积和启动性能没有明显退化。

这时可抽象最小资源模型：`Artifact` 保存内容与数据契约，`Placement` 保存位置和视图状态，`Task` 产生结构化结果。不要先照搬一个完整低代码平台。

## 七、分期

### P0：完成现有英语入口并发布工程内测

- 保持当前目标设置、基线诊断、今日练习入口、复习数量和进步摘要；
- 完成响应式、错误态、返回刷新和重启恢复验收；
- 修复创建空对话、发送失败、输入遮挡等用户路径问题；
- 不加拖拽、不加任意组件创建。

**2026-08-02 结果**：以上 P0 已完成开发态 Electron 用户路径验收。真实走过可见配置、momo 工具写入、返回刷新、长文本双视口和整进程重启；最终安装包复验仍需在 Office bundle ACL 阻塞解除后统一执行。

### P1：原生英语看板

- 加入可直接操作的到期复习；
- 将页面重排为今日练习、复习、证据、阅读入口和学习节奏五个组件；
- 保留固定布局，允许隐藏非核心辅组件，不提供自由拖拽；
- 与定时任务接线后增加每日轻提醒。

### P2：同一组件跨载体

- momo 可在对话中返回一张紧凑学习组件；
- 用户可将它固定到英语看板；
- 紧凑、常规、展开三种尺寸改变信息密度，不维护三份内容；
- 支持对组件中的具体内容留下修改意见。

### P3：通用看板平台

仅在 P2 被真实用户持续使用后评估拖拽、任意 HTML Widget、Automation、Binding 和多看板。它不作为首批内测阻塞项。

## 八、视觉与交互约束

- 看板使用工作台的冷静中性色，学习状态用少量绿色、琥珀色和蓝色区分，不做单色主题。
- 页面标题保持工具面尺度；不做营销式大标题或欢迎语。
- 卡片圆角不超过 8px，阴影只用于浮层和拖起状态，默认组件依靠边框、留白和层级。
- 所有按钮、计数器和复习卡有稳定尺寸；长目标、长单词和解释必须换行，不得撑破布局。
- 练习中的主动作永远只有一个；次要动作使用图标或低强调文本。
- 加载、无记录、失败、离线、已完成都必须有独立语义，不能都显示为空白。
- 不在用户界面出现 Kimi、Blueprint、Claude Code、FSRS、Automation 或 Binding 等实现名。

## 九、验收标准

1. 新用户完成目标设置后能进入真实基线诊断；发送失败时不会留下看似可用的空对话。
2. momo 记录一次错误后，回到英语页即可看到复习项；无需重启或手动刷新。
3. P1 加入页面内复习后，完成一次评价并确认刷新、切换页面和重启应用后的复习状态与到期时间一致。
4. 同型基线和后测都存在时显示真实变化；样本不足时不伪造成绩。
5. 1440x900、1024x768、720x640 下无横向溢出、遮挡或被底部输入区截断。
6. 页面使用键盘可完成目标设置和复习；图标按钮有可读名称。
7. 数据读取失败时仍保留上次成功内容，并给出轻量、可理解的状态。
8. 全量测试、类型检查、构建和 Electron 重启恢复通过；新增运行依赖对安装体积的影响有记录。
