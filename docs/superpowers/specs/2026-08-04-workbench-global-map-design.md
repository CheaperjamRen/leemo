## 一、结论

Leemo 工作台正式定义为：

> **AI 原生工作工具栏 + 可展开的本地文件工作区。**

它不再用顶部下拉框把用户困在单个本子里，而是在一个稳定壳层中同时提供：

1. 左侧全局地图：看见所有本子，以及不属于本子的“与 momo 的对话”；
2. 中央当前现场：对话、任务过程、文件预览与产物；
3. 右侧工作工具栏：文件、概览、搜索三个元能力入口。

搭子态和工作台共享同一套 Agent 执行、记忆、文件、模型、权限与对话数据，但不是同一套界面的换皮：

- 工作台常驻全局地图与工作工具栏，强调执行、资料和持续工作；
- 搭子态保持温暖、轻松、关系优先，工作工具按需打开，不常驻压迫聊天；
- 每日塔罗、占星、随机决定吃什么等未来能力只可能作为搭子专属模块出现，不进入工作台，也不改变通用 Agent 底座。

当前实施卡完成全局地图、作用域、会话工作集、模式入口、中央对话/文件双表面和右侧工具壳层。完整文件管理能力紧随其后单独完成；真正的对话弹出窗口作为下一阶段增强；搭子特色、学习看板和全产品视觉总关卡继续留在后续路线中。

## 二、产品心智

### 2.1 用户只需要理解这些概念

| 用户看到的概念 | 含义 | 明确不是什么 |
| --- | --- | --- |
| 本子 | 一个真实本地文件夹，也是一个项目、课程或长期主题的工作范围 | 仅用于筛选对话的标签 |
| 与 momo 的对话 | 不属于任何本子的全局聊天 | 默认本子、隐藏工作区或另一套人格 |
| 当前对话 | 当前正在进行的一段工作或交流 | 整个本子的唯一对话 |
| 本次文件 | 无本子对话中，本轮或本对话明确接触过的文件 | 隐藏默认工作区的完整文件树 |
| 文件 | 当前本子的真实本地文件树 | 上传附件列表或只读装饰 |
| 概览 | 当前范围内的目标、进展、待办和执行状态摘要 | 第二套任务数据库 |
| 搜索 | 查找当前范围或全部范围的对话、文件和成果 | 独立重复建立的索引系统 |

底层仍可使用兼容字段区分全局范围、Leemo 管理本子和外部文件夹，但普通界面只说“本子”和“未选择本子”。隐藏的默认工作区仍只是无本子产物的物理兜底，不拥有独立人格、记忆或对话范围。

### 2.2 稳定的三栏职责

```text
┌────────────────────┬──────────────────────────────────┬──────────────┐
│ 左：全局范围地图   │ 中：当前工作舞台                 │ 右：工作工具 │
│ 本子               │ 对话 ↔ 文件预览/编辑             │ 文件         │
│ 与 momo 的对话     │ 任务过程 / 产物 / 输入区         │ 概览         │
│                    │                                  │ 搜索         │
└────────────────────┴──────────────────────────────────┴──────────────┘
```

- 左侧回答“我有哪些事、现在在哪件事里”；
- 中央回答“我正在和 momo 做什么、正在查看或修改什么”；
- 右侧回答“这件事有哪些资料、进展和可查内容”。

文件树不再挤进左侧全局地图。这样既保留 Codex 式多项目总览，也让本地文件拥有一个长期、可展开、可操作的位置。

## 三、双壳边界与模式切换

### 3.1 模式入口

`搭子 / 工作台` 使用紧凑分段控件，和 Leemo 品牌并排固定在左上角。它是全应用稳定锚点，而不是藏在设置或内容页中的临时入口。

- 工作台展开左栏时显示完整分段控件；
- 工作台收起左栏时保留紧凑模式入口；
- 搭子态在相同位置保留一致入口，切换不需要重新理解导航；
- 切换模式不清空草稿、附件、当前模型或当前对话。

### 3.2 工作台

- 左侧全局地图常驻；
- 右侧工具图标栏常驻；
- 工具面板只在用户选择后展开；
- 视觉以冷静、清晰、可扫描为主，momo 的暖色只作为关系和品牌信号。

### 3.3 搭子态

- 不常驻右侧工作工具栏，不把聊天压缩成 IDE；
- 顶部右侧提供一个低干扰的工具入口，按需以覆盖层打开同一套文件、概览和搜索能力；
- 搭子对话仍能读写文件、调用工具、执行任务和进入本子，不成为能力缩水版；
- 未来的每日塔罗、占星、随机决定、轻量陪伴和生活仪式属于搭子模块，不出现在工作台导航；
- 娱乐性或象征性内容必须按其真实性质表达，不伪装成确定事实，也不自动写入长期记忆，除非用户明确要求记住相关偏好或习惯。

## 四、左侧全局地图

### 4.1 区域顺序

左栏中部固定分成上下两块：

1. `本子`；
2. `与 momo 的对话`。

本子在上，因为它代表持续工作和稳定文件归属；全局聊天在下，因为它承接临时讨论、关系聊天和尚未归入项目的事情。

两块各自拥有固定标题和独立滚动容器，不用一个长列表把本子与全局对话混在一起。

### 4.2 动态高度

- 本子较少时，本子区高度随内容自然增长，`与 momo 的对话`紧接其后并占据剩余空间；
- 本子增多时，本子区最多占可用列表区域约 55%，之后在内部滚动；
- `与 momo 的对话`始终至少保留标题和约三条对话的可见高度，更多内容内部滚动；
- 两个标题在各自区域内固定，不随列表项滚走；
- 第一版不提供上下区域手动分隔拖拽，避免用户管理布局而不是管理工作。

55% 和三条对话是首轮实现基线；只能根据真实多视口截图调整数值，不能改变“上方按内容增长、双方独立滚动、下方保留语义最小高度”的产品规则。

### 4.3 本子层级

- 所有本子始终可见；
- 只有当前本子展开并显示其对话，其他本子保持单行；
- 点击本子恢复该本子上次真正打开的对话；
- 本子行显示名称和必要状态，不用路径、副标题和多枚标签制造噪声；
- 本子新增、打开已有文件夹和本子级菜单都从本子标题或本子行进入；
- 当前本子、悬停和键盘焦点必须由背景、文字和标记共同表达，不能只靠颜色。

### 4.4 与 momo 的对话

- 这里只出现不属于任何本子的对话；
- 它不拥有本子文件树或本子记忆；
- 它可以有搜索、置顶、重命名、归档、移动和删除等既有对话管理能力；
- 将一段全局对话移动进本子是显式动作，不能因为用户打开了某个文件而静默改变归属。

## 五、新对话与作用域

### 5.1 默认跟随

顶部主入口统一叫`新对话`，默认跟随用户当前所在范围：

- 当前在某本子时，新对话先属于该本子；
- 当前在`与 momo 的对话`时，新对话不属于任何本子；
- 本子标题和`与 momo 的对话`标题旁的小型加号可直接在对应范围新建。

### 5.2 首条消息前可取消跟随

在本子中创建的空白对话，其输入区上方显示紧凑的本子范围标签和关闭图标。用户点击关闭图标后：

- 标签立即变为`未选择本子`；
- 不弹确认框、不显示 Toast、不出现“已改为与 momo 的对话”等回执；
- 草稿、附件、模型和输入焦点全部保留；
- 左栏不因这个动作自动跳动；
- 只改变当前尚未发送的草稿，不影响其他对话；
- 点击`未选择本子`可重新选择一个本子。

第一条消息发送成功后，对话作用域固定。之后若要改变归属，使用明确的“移动到本子”动作，不再提供容易误触的关闭图标。

### 5.3 失败保护

- 首次发送失败时仍保留草稿、附件和原作用域；
- 新建过程中切换模式不改变草稿作用域；
- 本子失效或目录不可用时，不把消息偷偷发往默认工作区，而是保留草稿并提示重新定位、移除本子或改为未选择本子。

## 六、每个范围自己的对话工作集

每个本子和`与 momo 的对话`分别记住：

- 上次打开的对话；
- 当前打开的对话标签集合；
- 当前激活标签；
- 对应草稿和附件状态。

中央顶部的对话标签栏规则：

- 当前范围只有一段打开对话时不显示标签栏；
- 两段及以上时显示，最多同时保留五个；
- 关闭标签只从工作集中移除，不删除、不归档对话历史；
- 切换本子后看到的是该本子自己的工作集；
- 切回时恢复上次激活对话和标签顺序；
- 超过五个时，打开新对话优先替换最久未激活且无未保存草稿的标签；有草稿的标签不得被静默挤出。

历史对话列表是完整资料库，顶部标签只是近期工作集，两者不能混为同一状态。

### 6.1 克制的会话状态信号

会话列表不再把`已完成`、`等待继续`、`等你确认`、`等你回答`等内部过程逐条写成可见文字。普通用户只需要识别三种信号：

1. `进行中`：使用轻量转圈，表示 momo 仍在处理；
2. `报错`：使用克制但明确的红色错误图标，表示最近一轮没有正常完成；
3. `未读`：使用一个小圆点，表示这里有内容或动作等用户回来处理。

三者互斥显示，优先级固定为`进行中 > 报错 > 未读`。同一段对话不能同时堆叠多个状态标记，也不在标记旁显示文字；具体含义只通过悬停提示和无障碍名称提供。

`未读`统一覆盖：

- 后台完成的新结果；
- 待用户审批；
- 待用户回答；
- 用户在对话菜单中主动选择`标记未读`。

菜单在已读对话上显示`标记未读`，在未读对话上显示`标记已读`。这个动作不弹确认框、不发 Toast；用户重新打开该对话或显式标记已读后清除。手动标记未读对当前正在查看的对话也有效，不能因为它处于激活态就立刻消失。

`报错`与`未读`不是同一件事：打开失败对话只表示用户看到了它，不自动把错误伪装成普通已读状态。错误标记由最近一轮真实时间线派生，在后续一轮成功完成后自然清除，不新增容易漂移的数据库字段。待审批和待回答同样从当前真实待办派生为未读点，不各自发明新标签。

当前对话标题区和中央折叠后的`对话`入口复用同一套三态规则，不再显示一串状态文字。置顶、归档等列表组织属性不进入这组三态，也不得与运行信号挤在同一个尾部区域。

## 七、右侧 AI 原生工作工具栏

### 7.1 三个初始元能力

工作台右侧常驻一条窄工具栏，只提供三个已经有真实数据和用户价值的入口：

| 界面名称 | 内部职责 | 默认范围 |
| --- | --- | --- |
| 文件 | Explorer：当前本子的真实文件树，或无本子对话的本次文件 | 当前本子或当前对话 |
| 概览 | Dashboard：目标、摘要、计划、待办、运行任务与 subagent 状态 | 当前本子或当前对话 |
| 搜索 | Search：查找对话、文件和成果，可切换到全部范围 | 当前范围 |

未来只有在能力已经可用时才新增图标，不提前放空入口“撑场面”。工具栏不是插件坞，也不放设置、通知、搭子特色或编码专用按钮。

### 7.2 交互

- 同时只能打开一个工具面板；
- 再次点击当前图标会收起面板；
- 切换图标直接替换面板，不叠加卡片；
- 图标使用统一的 Lucide 体系，视觉尺寸 17-18px，点击区域 38-40px；
- 悬停显示简短中文名称；
- 激活状态同时使用浅背景和侧边标记，不只靠颜色差异；
- 每种工具分别记住用户上次设置的宽度和内部浏览位置。

### 7.3 文件

有本子时：

- 展示当前本子的真实文件树；
- 单击受支持文件优先在 Leemo 中预览；
- 不支持内嵌预览的文件可用系统默认应用打开；
- 当前卡复用既有预览、引用和“在资源管理器中显示”能力，不冒充完整文件管理器。

未选择本子时：

- 标题为`本次文件`；
- 只展示当前对话明确附加、读取、生成或修改过的文件；
- 不展示隐藏默认工作区的完整目录树；
- 文件可以在后续通过显式动作移入某个本子，不能静默归类。

### 7.4 概览

概览从既有真实数据聚合当前范围的：

- 对话或本子摘要；
- 已明确的目标与下一步；
- 当前计划和待办；
- 正在运行、等待用户和已经完成的任务；
- subagent 的角色、任务、状态和明确产出。

概览只做派生视图，不新建第二套任务引擎、记忆库或状态账本。没有真实数据时显示克制的空状态，不让模型凭空生成“进度”。

### 7.5 搜索

- 默认只搜索当前本子或当前全局对话范围；
- 提供清楚但低干扰的`全部`切换；
- 复用现有搜索索引和作用域过滤，不维护重复索引；
- 搜索结果必须显示真实归属，点击后先切到正确范围再打开目标；
- 路径失效、索引损坏和无结果分别呈现，不能把错误伪装成“没有找到”。

### 7.6 中央对话与文件双表面

中央工作舞台只允许两个主表面竞争空间：

1. 当前对话，包括消息、任务过程和输入区；
2. 当前文件，包括预览、编辑和同组文件标签。

右侧 Explorer 是临时工作工具，不是第三个中央表面。打开文件时按以下状态运行：

- 没有打开文件：对话占满中央；
- 中央可用宽度不少于约 920px：对话与文件默认左右并排，对话约 42%，文件约 58%；
- 中央可用宽度不足，或用户主动进入专注状态：顶部使用`对话`与文件标签互斥显示一个表面；
- 多个文件只在文件表面内部形成标签，不复制对话；
- 并排和标签状态引用同一个对话、草稿、附件、任务和文件实例，切换布局不重新建会话、不重复执行任务。

互斥标签不等于 momo 消失。`对话`入口在中央顶部始终可见，并显示运行、等待用户或未读状态；文件被收起时，当前文件标签同样保留。用户点击即可恢复，不使用占据整行的底部聊天条。

完整对话不做遮挡文档的应用内漂浮卡片。后续“弹出对话”使用真正的独立子窗口：共享同一对话状态，可移动到第二块屏幕；关闭后重新停靠主窗口；不默认置顶；主窗口保留`对话已弹出`入口用于聚焦或重新停靠。当前卡只冻结共享状态和恢复边界，不展示尚未实现的入口。

## 八、空间仲裁、拖拽与窄窗退化

### 8.1 基线尺寸

| 区域 | 默认 | 最小 | 最大或折叠 |
| --- | --- | --- | --- |
| 左侧全局地图 | 288px | 252px | 360px；折叠后 52px |
| 右侧工具栏 | 44px | 44px | 44px |
| 右侧工具面板 | 320px | 280px | 520px 或窗口宽度 45%，取较小值 |
| 中央对话表面 | 并排时约 42% | 400px | 用户拖拽决定 |
| 中央文件表面 | 并排时约 58% | 500px | 用户拖拽决定 |
| 主窗口外框 | 1280x860 | 960x680 | 可继续放大 |

这些是首轮工程基线。实现时可以依据截图和文字可读性在小范围内校准，但不得压缩到破坏三栏职责，也不得用随视口缩放的字体掩盖空间不足。

### 8.2 冲突优先级

空间不足时严格按以下顺序处理，不能让各组件自行决定：

1. 左侧全局地图和最右工具栏保留为定位锚点；
2. 右侧工具面板先由停靠改为覆盖抽屉，停止挤压中央；
3. 中央仍不足约 920px 时，对话/文件由左右并排切为互斥标签；
4. 左侧地图只响应用户主动折叠，不因打开文件或工具被系统静默收起；
5. 不缩小字体、不压低输入区、不产生对话 + 文件 + Explorer 三个窄栏。

并排状态下，右侧工具面板只有在停靠后中央仍能满足两个表面最小宽度时才保持停靠；否则以覆盖抽屉打开。覆盖抽屉不改变用户保存的面板宽度，点击栏图标、空白区或按 Esc 可关闭。

右侧工具面板进入聚焦状态时，暂时接管中央工作舞台；原对话/文件布局只暂停、不销毁。退出聚焦后恢复原来的并排比例、活动文件、滚动位置和输入草稿。

### 8.3 拖拽与折叠

- 左栏和右面板都可横向调整宽度；
- 对话与文件之间提供独立横向分隔边界，并按 400px / 500px 的最小宽度约束；
- 分隔线视觉为 1px，命中区域约 8px，避免难抓；
- 拖拽期间关闭布局过渡，指针与边界保持一比一，不让消息、输入区或标题跳动；
- 双击分隔边界恢复默认宽度；
- 各工具面板分别保存宽度，重启后恢复；
- 中央分隔线拖到一侧折叠阈值时只显示预览，松开后才收起对应表面；
- 对话被收起后，中央顶部保留`对话`入口和状态；文件被收起后保留当前文件标签；
- 点击入口恢复上次并排比例，不使用底部状态条；
- 右侧工具面板拖到工作区约 55% 时显示聚焦预览，松开后才进入聚焦状态；拖动经过阈值但未松手不能突然跳变。

聚焦状态只占满左侧地图和右侧工具栏之间的中央工作区，不遮住全局地图，也不移除右侧工具栏。用户始终能知道自己在哪个本子，并能一键退出聚焦。

### 8.4 响应式规则

- 中央可用宽度按实际容器测量，不用单一窗口宽度猜测；
- 只要中央无法同时保留 400px 对话和 500px 文件，右面板先从停靠改为覆盖层；
- 去掉右面板后仍不足约 920px 时，中央切为互斥标签；
- 1024x768 仍保留完整左侧范围地图和右侧工具栏，工具面板按覆盖层打开；
- 应用不允许缩到低于 960x680，避免已知组件在无意义窄窗中互相遮挡；
- 布局分别记录用户偏好和当前有效形态：用户主动选择专注后，即使空间变宽也保持专注；只有因窄窗被系统临时降为标签时，空间恢复后才回到用户保存的并排偏好；
- 输入区保持既有最大宽度和悬浮视觉，不随右面板展开横向铺满或被推出窗口；
- 所有文本允许合理换行，用户关键文字不小于 12px。

### 8.5 联动、动效与性能

- 打开文件时沿用当前对话和文件树实例，只改变工作舞台布局，不重新读取整棵文件树或重放对话；
- 对话/文件切换保留各自滚动位置、选区、Markdown 草稿和输入焦点；
- 工具覆盖抽屉使用位移和透明度过渡；并排/标签切换只做克制的 120-180ms 过渡，不使用弹跳、缩放或大面积模糊；
- 拖拽期间完全关闭 easing，每个动画帧最多提交一次尺寸更新，持久化只在松手后或防抖结束时执行；
- 窗口缩放不触发文件系统重扫、搜索重建、Markdown 全量重解析或会话重新订阅；
- 切换模式、工具、对话和文件时不得因布局动画阻塞输入、停止任务或权限操作；
- 支持系统“减少动态效果”设置，关闭非必要动画；
- 后续独立对话窗口关闭、崩溃或显示器断开后必须回到主窗口可见范围，不遗留重复订阅、后台渲染器或不可找回的草稿。

## 九、视觉约束

当前卡先把结构和尺寸做正确，不借机重画整个产品。实现仍必须遵守这些下限：

- 正文 14-15px，导航 13px，辅助文字 11-12px；
- 图标视觉尺寸 16-18px，交互热区 36-40px；
- 面板和重复项圆角 6-8px，阴影克制；
- 不用渐变光球、装饰大卡片或一整屏同色；
- 当前项、悬停、焦点、禁用和错误状态都有一致表达；
- 对话、文件和工具区域不互相套装饰卡片；
- 中文名称优先，Explorer、Dashboard 等只作为内部设计术语，不进入普通界面。

全产品的字体、图标、颜色、动效和视觉精修仍在独立视觉总关卡中完成，并以真实 Leemo 界面、成熟 Agent 参考、多视口截图和一次严格视觉评审验收。

## 十、状态与数据架构

### 10.1 单一真源

新界面必须从现有数据层派生，不另造平行实体：

- 本子列表与当前本子继续来自既有本子/工作区登记；
- 对话列表、归属、置顶、归档和最近打开继续来自既有对话存储；
- 文件树来自真实本子路径；`本次文件`来自当前对话的附件和已确认文件活动；
- 概览读取现有计划、工具运行、定时任务和 subagent 事件；
- 搜索复用现有索引；
- 草稿、附件和首次发送失败恢复沿用现有按对话/范围保存机制。

界面层只新增“如何看这些数据”的状态，例如：

- 当前壳层；
- 每个范围的打开标签集合与激活标签；
- 当前右侧工具、宽度和聚焦状态；
- 中央是对话全屏、文件全屏还是左右并排，以及用户保存的分隔比例；
- 左栏折叠状态。

### 10.2 作用域键

内部以稳定的范围键区分：

- 全局 momo 范围；
- 每个 Leemo 管理本子；
- 每个外部文件夹本子。

显示名称可以修改，范围身份不能依赖名称或绝对路径字符串临时拼接。移动、移除和重新定位本子时必须更新引用或进入可恢复状态，不能把历史串到同名本子。

### 10.3 持久化

重启后恢复：

- 上次壳层；
- 当前范围；
- 每个范围最后打开的对话；
- 每个范围最多五个打开标签及其顺序；
- 左栏折叠状态；
- 每个右侧工具的宽度；
- 当前工具是否打开；
- 每个范围的中央表面状态、活动文件和并排比例。

窗口宽度不足时，可以暂时以覆盖层呈现已打开工具，并把中央并排态暂时呈现为互斥标签，但不能覆盖用户保存的桌面宽度与表面偏好。窗口恢复后回到用户上次明确选择的布局，不能在断点附近来回闪跳。

## 十一、失败与恢复

- 本子目录不存在：保留本子和对话记录，显示“文件夹暂不可用”，提供重新定位和移除登记；不删除用户数据，不静默切到另一本子；
- 对话被移动：从原范围的工作集移除，在目标范围可找到并按规则打开；
- 对话被删除或归档：关闭对应标签，选择同范围内最后有效对话；没有时进入该范围的新对话空态；
- 文件被外部删除：文件树刷新，已打开预览显示明确失效状态；未保存 Markdown 草稿继续保留；
- 搜索索引异常：显示可重建或重试状态，文件和对话真源不受影响；
- 概览某一数据源失败：只降级对应区块，不让整个面板空白或伪造完成状态；
- 拖拽中应用失焦或窗口变化：取消未完成布局变更，回到上一个稳定宽度；
- 由并排切到标签或从工具聚焦返回：保留对话和文件滚动位置、草稿、选区与当前文件；
- 后续独立对话窗口意外关闭：同一对话立即可在主窗口重新停靠，不能留下“仍在弹出”的假状态；
- 模式切换或重启：草稿、附件、作用域、标签和面板状态不串范围、不丢失。

## 十二、分期边界

### 12.1 当前卡：工作台全局地图与工具壳层

必须完成：

1. 左栏`本子`与`与 momo 的对话`双区域；
2. 当前本子展开、其他本子总览和上次对话恢复；
3. 新对话默认跟随、首发前`未选择本子`切换；
4. 每个范围独立的最多五个对话标签；
5. 左上模式切换；
6. 工作台右侧`文件 / 概览 / 搜索`工具栏及单面板容器；
7. 本子文件树与无本子`本次文件`的正确边界；
8. 无文件时对话全宽，有文件时标准窗口左右并排、窄窗或专注时互斥标签；
9. 中央和工具面板拖拽、折叠恢复、聚焦、窄窗覆盖和重启恢复；
10. 联动过程中不重新加载数据，过渡流畅且不阻塞输入；
11. 复用现有真实数据，不造空卡片和假状态。

### 12.2 下一卡：真正的本地文件工作区

在当前壳层稳定后，紧接着补齐：

- 从文件树拖入输入区形成引用，不复制、不移动原文件；
- 把系统文件拖进文件树时复制到明确目标位置；
- 新建 Markdown、普通文件和文件夹；
- 重命名、复制路径、移动、使用回收站删除；
- `打开`与`在资源管理器中显示`两个清晰动作；
- Markdown 预览、编辑、保存与工具栏继续可用；
- PDF 使用已有内嵌预览；Office 等暂不支持的格式使用系统默认应用打开；
- 外部变化刷新、重命名后引用更新、键盘操作与右键菜单；
- 文件工具动作继续经过 Leemo 权限和路径边界。

这张文件卡的目标是让用户多数时候不用反复切换 Windows 资源管理器，而不是把 Leemo 变成完整代码 IDE。

原生 XLSX 内嵌预览/编辑不是首发文件工作区的完成条件。视觉重构期间已保留未来目标稿 `docs/design-audition/visual-redesign/workbench-spreadsheet-editor-v1.png`，但在真实编辑器、公式语义、保存与恢复链路实现前，产品仍必须诚实走系统默认应用，不显示这套尚不存在的界面。

### 12.3 紧随其后的对话弹出窗口

在中央双表面稳定后实现真正的独立子窗口：

- 从对话标题菜单选择`弹出对话`；
- 新窗口与主窗口共享同一对话、草稿、附件、运行状态和权限流程；
- 主窗口显示`对话已弹出`并可聚焦或重新停靠；
- 关闭子窗口默认重新停靠，不结束对话或任务；
- 记住窗口大小和位置，显示器变化时收回可见范围；
- 不默认置顶，不复制任务流，不让两个窗口同时提交同一审批；
- 完成跨窗口拖入附件、停止任务、权限卡、重启恢复和资源释放验收后才可见。

### 12.4 后续关卡

- 搭子态关系仪式、人格与关系选择、每日回顾；「心迹」首发隐藏，后续成熟后再评估；
- 搭子专属的塔罗、占星、随机决定等轻量模块；
- 英语学习、论文理解与 AI 原生交互看板；
- 全产品视觉总关卡；
- 代码本子自适应出现 Git、diff、测试等增强入口；
- 真正多 Agent 编排与更重的 AI 原生工作界面。

## 十三、当前明确不做

- 不在工作台加入塔罗、占星、随机决定或学习打卡组件；
- 不在右栏放尚未实现的空图标；
- 不建立任意嵌套的对话文件夹；
- 不建立第二套任务、记忆、文件或搜索数据库；
- 不把工作台做成 Git、终端、LSP 常驻的纯编程 IDE；
- 不在当前卡实现完整文件增删改移动；
- 不在当前卡显示或实现尚未通过跨窗口验收的`弹出对话`；
- 不把完整对话做成遮住文件的应用内漂浮卡片；
- 不用一次结构调整冒充全产品视觉升级；
- 不把隐藏默认工作区包装成用户可见本子。

## 十四、验收标准

### 14.1 全局地图

- 同时准备至少 8 个本子和 20 段全局对话；本子区增长到上限后独立滚动，全局对话区仍至少显示标题与三行；
- 任意时刻都能看见多个本子，并在一次点击内进入另一项工作；
- 只有当前本子展开，其对话归属清楚；
- 点击本子恢复该本子上次真正打开的对话，重启后仍一致；
- 全局对话不会被误显示在本子下，本子对话不会泄漏到其他本子。

### 14.2 新对话与工作集

- 在本子内点`新对话`默认跟随该本子；首发前可改为`未选择本子`；
- 取消跟随后没有弹窗、Toast 或多余回执，草稿和附件不变；
- 首发失败、切换模式、切换范围和重启均不丢草稿或串作用域；
- 每个范围独立恢复打开标签和激活对话；关闭标签不删除历史；
- 超过五个标签时不静默挤掉带未保存草稿的对话。
- 会话列表只出现转圈、红色错误标记、未读点三种运行信号，且严格按`进行中 > 报错 > 未读`互斥显示；
- 后台完成、待审批、待回答和手动标记都显示同一个未读点，不出现对应文字标签；
- 菜单可在`标记未读 / 标记已读`之间切换，手动未读重启后仍保留，打开对话后清除；
- 报错不会因打开对话而消失，只有后续真实成功轮次才能清除；
- 三态在左栏、当前标题区和中央折叠入口含义一致，悬停提示与无障碍名称完整。

### 14.3 右侧工具

- 工作台始终看见三个图标，搭子态只看见按需工具入口；
- 三个工具互斥打开，各自记住宽度；
- 有本子时`文件`显示真实文件树，无本子时只显示当前对话的`本次文件`；
- `概览`只显示已有真实状态，任务失败不会被呈现为完成；
- `搜索`默认限制当前范围，切换`全部`后结果仍显示归属并能正确跳转；
- 中央左右并排时，工具面板只有在剩余宽度满足双表面下限时才停靠，否则稳定地覆盖；
- 聚焦工具面板后左侧全局地图和右侧工具栏仍可见。

### 14.4 中央双表面

- 未打开文件时对话占满中央，不保留空预览栏；
- 1280x860 和 1440x900 有足够中央宽度时，打开文件默认形成可拖拽的左右并排；
- 对话和文件分别不小于约 400px / 500px；达到下限后使用折叠预览，不能继续挤压；
- 1024x768 和 960x680 下自动呈现`对话 / 文件`互斥标签，两个入口始终可见；
- 收起对话后仍能看见运行、等待用户或未读状态；点击一次恢复上次比例；
- 对话/文件切换及并排/标签退化前后，消息滚动、文件滚动、Markdown 草稿、附件、输入草稿和当前选区保持一致；
- 连续打开多个文件只增加文件表面内的标签，不复制对话或任务；
- 不出现底部矮宽聊天条、遮挡文件的完整聊天浮层或对话 + 文件 + Explorer 三个窄栏。

### 14.5 布局、动效与性能

- 在 1440x900、1280x860、1024x768 和 960x680 四个窗口尺寸逐一截图；
- 所有尺寸下输入区完整可见，标题、按钮、标签、工具提示和长中文不重叠、不裁切、不产生横向页面滚动；
- 1024x768 和 960x680 下工具面板按规则覆盖，不把中央对话压成不可读窄列；
- 窗口不能缩到设计下限以下；最大化、恢复和重启后布局稳定；
- 左右拖拽边界易命中，拖动时无 easing，超过阈值只显示预览，松开才折叠或聚焦，双击可恢复默认；
- 打开文件、切换表面、展开工具和恢复折叠的动效方向一致、时长克制，没有闪白、跳位或多余弹跳；
- 开启系统“减少动态效果”后，非必要过渡关闭且功能完整；
- 连续拖拽 5 秒、快速切换 20 次工具/表面时，输入、停止任务和权限操作仍可响应，renderer 无未捕获错误；
- 调整窗口和面板尺寸不会触发文件树重扫、搜索索引重建、对话重新订阅或任务重复执行；
- 重复打开/关闭工具与文件后，活动监听、文件监听和 renderer 内存不无界增长；
- 键盘焦点、屏幕阅读名称、悬停提示和选中状态完整。

### 14.6 数据、失败与发布

- 本子目录失效、文件外部删除、搜索索引异常和概览局部失败都有可理解且可恢复的状态；
- 切换本子、移动对话和重新定位目录不会混淆同名范围；
- renderer 不持久化或输出不必要的绝对路径，凭据不跨 IPC、不进日志；
- 聚焦单元和组件测试覆盖作用域、标签、尺寸和失败状态；
- typecheck、全量测试、内置 Skill 校验、renderer/main 构建通过；
- 涉及主进程窗口下限或持久化后，在最终安装包中完成成功、失败、重启恢复和普通用户理解度验收；
- 对比上一候选包的安装体积、解包文件数、冷启动和空闲内存，没有无法解释的明显回退。

## 十五、完成判据

这张卡的完成不是“左边多了本子、右边多了三个按钮”，而是用户打开 Leemo 后能稳定回答：

1. 我有哪些本子和全局对话；
2. 我当前正在哪个范围、哪段对话里；
3. 这段工作关联了哪些文件、目标和进展；
4. 我如何在不丢现场的前提下切到另一项工作；
5. 我如何回到搭子态聊天，同时仍保留调用完整 Agent 能力的路径。
