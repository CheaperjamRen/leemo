# Leemo“开始”静态工作区与本地文档库设计

> 日期：2026-08-18
> 状态：用户已确认的产品设计；“开始”壳层已落地，本地文档库继续实施。
> 权威范围：覆盖“开始”顶层静态工作区、其中的便签 / Todo 关系、便签层级与便签间引用。搭子态、工作台态及 Human 文件访问与 Agent 授权边界由各自规格约束。

## 一、结论

“开始”不是通往便签库之前的中转页，而是 Leemo 的顶层静态工作区。它把轻量首页、Todo 行动视图和本地文档库放在同一个稳定外壳里：

- 左侧始终提供首页、收集箱、待办、置顶、最近、位置、文档树、归档和回收站等入口；
- “首页”是默认选中项，只显示待完成事项、今天、收集箱和最近四类必要信息；
- 选择文档或系统视图后，右侧切换为相应列表、Markdown 阅读 / 编辑或文件预览；
- 桌面端的文档工作面采用左侧 Explorer + 右侧 Markdown 阅读 / 编辑区；
- 每条便签既能书写，也可以成为父节点容纳子便签；
- 树形归属负责“主要放在哪里”，正文引用负责“还与什么有关”；
- Todo 保留为行动与承诺视图，不承担长期文档存储；
- 整个“开始”工作区可以在没有模型、Provider、API Key 和网络时完整使用。

本设计不是把 Notion、飞书云文档或完整 IDE 复制进 Leemo。它只解决个人长期写作、随手捕捉、整理、引用和找回。

## 二、在应用中的层级

```text
开始（静态工作区外壳）
├─ 首页（默认）
│  ├─ 待完成事项
│  ├─ 今天
│  ├─ 收集箱
│  └─ 最近
├─ 收集箱
├─ 待办
├─ 置顶
├─ 最近
├─ 本子与文件 / 位置
├─ 我的文档（可折叠树）
├─ 已归档
└─ 回收站

搭子
└─ 温暖对话

工作台
└─ 文件、对话与 Agent 执行
```

“开始”是一个稳定外壳，不为文档库再增加额外导航层。首页和文档库共享同一套左侧导航；用户点选不同对象时只替换右侧工作面。它也不是工作台聊天栏旁边的新面板，不携带常驻 AI 输入框。

## 三、用户心智

用户只需要理解：

1. Alt+N 或“新建便签”产生一条本地便签；
2. 尚未整理的便签先进入收集箱；
3. 任意便签都可以收纳子便签，并继续拥有自己的正文；
4. 一条便签主要归属一个位置；
5. 与其他主题的联系通过正文引用表达；
6. 只有主动选择明确 AI 操作，或事先启用模型自动化，才调用 AI。

不向用户暴露 `parentId`、link index、SQLite、managed / external 等内部术语。

## 四、页面布局

### 4.1 桌面宽屏

```text
┌────────────────────────┬─────────────────────────────────────┐
│ 首页 / 收集箱 / 待办   │ 标题 / 面包屑        阅读 / 编辑    │
│ 置顶 / 最近 / 位置     │                                     │
│ 搜索                   │                                     │
│                        │                                     │
│ 我的文档               │ Markdown 正文                       │
│                        │ 附件                                │
│ 自定义分组树           │ 引用的便签 / 被引用                 │
│ 已归档 / 回收站        │                                     │
└────────────────────────┴─────────────────────────────────────┘
```

- 左树建议初始宽度约 `260–320px`，允许在合理边界内拖动；
- 右侧编辑区是视觉主体，不增加常驻聊天栏；
- 富文本工具栏置于正文顶部，沿用已定的紧凑单行与渐进披露；
- 阅读 / 编辑切换复用现有 Markdown 工作面能力；
- 打开位置、滚动、选择和未保存草稿按当前便签恢复，不因左树操作丢失。

### 4.2 窄窗口

- 左树变成覆盖层或独立页面；
- 打开便签后正文占满可用宽度；
- 通过明确返回入口重新打开树；
- 不能为了常驻层级把编辑区压到无法写作。

## 五、两种组织关系

### 5.1 结构父子关系

- 任意便签可以拥有子便签；
- 父便签不是空文件夹：它保留标题、Markdown 正文、附件、引用、版本和时间；
- 一条便签最多只有一个结构父节点；
- 没有父节点的便签可以是顶层已整理文档，也可以仍处于收集箱；
- 父子关系与“是否在收集箱”是两个独立维度；
- 同级便签有稳定手动顺序；
- 不能把便签移动到自身或自己的后代；
- 移动父便签时，子树整体移动。

### 5.2 便签间引用

- 正文输入 `@`打开本地便签选择器；
- 从左树拖一条便签到正文，插入引用；
- 引用使用稳定 noteId，不依赖标题或层级路径；
- 标题修改、父节点变化和同级排序不破坏引用；
- 点击引用在当前便签文档库打开目标；
- 提供在新标签打开与返回来源；
- 被引用便签显示紧凑反向引用列表；
- 引用关系不改变结构父节点，也不产生副本；
- `@便签`只做本地引用，不调用模型。

推荐 Markdown 持久形式使用标准链接外观和 Leemo 稳定目标，例如 `[显示标题](leemo-note://<noteId>)`；最终协议名在实现规格中冻结。可重建的反向引用索引不得成为第二正文真源。

## 六、“开始”导航与文档 Explorer

### 6.1 固定入口

- **首页**：轻量鸟瞰，只显示待完成事项、今天、收集箱和最近；“待完成事项”是最近一次成功的全局梳理快照，不复制完整文档树和 Todo 列表；
- **收集箱**：通过 Alt+N、快速记录或普通新建产生且尚未整理的便签，默认按创建 / 更新时间排列；
- **待办**：今天、无期限、已计划和已完成的行动视图；Todo 是任务承诺，不是文档容器；
- **置顶**：用户主动钉住的便签；
- **最近**：最近打开或编辑；
- **本子与文件 / 位置**：用户主动打开、固定或导入的真实位置；具体 Human 文件边界见独立规格；
- **已归档**：退出日常工作面但仍可搜索恢复；
- **回收站**：沿用现有 30 天恢复路径。

收集箱、置顶、最近、已归档和回收站是同一批便签的查询镜头。同一便签可以同时出现在“置顶”和自己的结构位置，但不产生两个副本。首页和待办是独立工作面，不伪装成便签查询。

### 6.2 我的文档树

- 父便签有折叠箭头与子项数量；
- 选中父便签时，右侧打开它自己的正文；
- 树内拖到另一便签上，表示成为其子便签；
- 拖到两个条目之间，表示同级排序；
- 拖到顶层空白区，表示移到顶层；
- 搜索结果保持原层级路径提示，但不在结果页复制树；
- 当前选中、拖拽目标、置顶、归档和失效引用状态需要清楚但克制。

### 6.3 删除与归档安全

- 归档或移入回收站的父便签若有子项，必须显示受影响数量；
- 默认按子树处理，确保恢复后结构仍然成立；
- 另提供“仅移除这个父节点并把子项提升到上一级”的明确操作；
- 永久删除继续走回收站二次动作，不在树中直接永久清理；
- 托管附件仅在永久删除对应便签时清理，外部引用文件永不由 Leemo 删除；
- 引用目标进入归档或回收站时，引用保留并显示状态；恢复后自动重新可用。

## 七、右侧文档工作面

- 标题、正文、富文本工具栏、保存状态继续使用现有便签能力；
- Markdown 阅读与编辑复用工作台的统一渲染语义；
- 支持数学公式、表格、清单、代码、Mermaid 等全局 Markdown 能力时，应与聊天和文件预览同源；
- 低频格式进入“更多”，避免工具栏挤压正文；
- 附件以紧凑条目显示，不占据大块正文；
- 正向引用与反向引用位于正文后的轻量区域，可折叠；
- “问 momo / 交给 momo”只在选区、更多菜单或明确操作中被动出现。

## 八、附件和外部文件兼容

本设计不能改变既有附件语义：

1. 粘贴或拖入图片继续复制到 Leemo 管理的持久附件目录；
2. 普通外部文件默认保持“仅引用”；
3. 用户开启“拖入文件时保存副本”后，未来新增普通文件复制到托管目录；
4. 切换设置不追溯改变已有附件；
5. 每条附件继续显示“仅引用 / 已保存副本”；
6. 用户选择的附件存储根、打开目录和迁移流程保持有效；
7. 迁移失败时原存储继续可用，不能形成两套不完整真源；
8. 软删除和归档不清理托管附件；永久删除时才清理对应托管文件；
9. 外部原文件永不由 Leemo 删除。

文件打开行为复用工作台：

- Leemo 支持的格式在统一 PreviewPane 打开；
- Markdown 可阅读和编辑；
- 不支持的格式调用系统默认应用；
- 所有仍存在的真实文件提供“在资源管理器中显示”；
- 路径失效时显示文件已移动 / 删除等真实状态，不跳转到网页或应用首页。

## 九、既有功能兼容与迁移

必须保留：

- Alt+N 快速窗口与草稿；
- 创建、更新、revision 冲突保护；
- 搜索、归档与恢复；
- 从便签创建关联待办，便签原文保留；
- 图片与普通文件附件；
- 存储位置选择、打开与迁移；
- 30 天回收站、彻底删除与附件清理；
- 重启后的正文、附件、归档与删除状态恢复；
- momo 已有的便签读取与明确 CRUD 工具，但默认不主动调用。

### 9.1 便签与 Todo 的最终关系

旧的“转换”式叫法不再作为用户心智。产品中的确定性行为是**从便签创建关联待办**：

- 用户可以选择便签中的一行或多行，预览后创建一条或多条 Todo；
- 原便签的标题、正文、层级、附件、引用和 revision 全部保留，不被转换、移动或删除；
- 新 Todo 保存来源便签 ID，并显示“来自「便签名」”，可一键返回原文；
- 原便签显示紧凑的关联待办入口，可查看对应状态；
- 创建完成后两边不做正文自动同步，避免一处修改静默覆盖另一处；
- Todo 是否完成由用户定义；模型的任务回执和进展摘要不能自动完成父级 Todo；
- 用户文案统一为“创建待办”“从便签创建待办”“创建 N 条待办”和“已创建 N 条待办 · 便签原文保留”。

历史迁移：

- 所有现有便签正文和附件原样保留；
- 未有层级元数据的旧便签进入未整理 / 顶层查询视图；
- 不使用模型自动生成分组、标签或引用；
- 迁移必须可重跑、幂等，并在失败时保留旧库可读；
- 层级与引用加入后继续沿用 revision 乐观并发，不能让拖拽静默覆盖另一窗口中的正文更新。

## 十、数据模型方向（实现前冻结）

当前 `Note` 已包含 id、title、markdown、revision、时间、归档 / 删除与附件。实现层建议最小增加：

- `parentId: string | null`：唯一结构父节点；
- `sortKey`：同级稳定顺序；
- `pinnedAt: number | null`：置顶视图；
- `organizedAt`或等价 Inbox 状态：区分未整理与顶层已整理；
- Markdown 中的稳定 noteId 引用；
- 可由正文重建的反向引用索引。

现有 Task 的 `noteId` 或等价稳定外键继续作为便签与待办的关联真源，不新增第二套同步正文。

不新增 folder-only 实体，不让同一便签拥有多个 parentId，不让引用索引成为第二份正文。

## 十一、AI 与费用边界

以下操作均为零模型调用：

- 打开“开始”、首页或文档库；
- 搜索、展开、折叠、移动和排序；
- 新建分组便签；
- 编辑、预览、归档、置顶与恢复；
- `@便签`与拖入正文引用；
- 添加、打开、定位和移除附件；
- 从便签创建关联待办的确定性本地路径。

只有用户发送消息、点击明确标示会调用 momo 的操作，或运行事先启用的模型自动化时才启动模型。便签文档库不能为了自动标题、摘要、分组或关联推荐在后台调用 API。

首页“待完成事项”是唯一在本规格内明确允许的模型梳理例外：用户手动点击“为我梳理待完成事项 / 重新梳理”，或事先启用“每天指定时间后首次进入前台自动梳理”，才生成新的全局快照。未触发时继续展示最近一次成功快照；模型不能完成 Todo、修改便签或覆盖事实状态。完整语义见 `docs/superpowers/specs/2026-08-18-global-pending-overview-design.md`。

## 十二、首版范围与非目标

### 首版

- “开始”顶层静态工作区外壳与默认首页；
- 手动生成、可选每日自动生成并可跳回真实来源的全局待完成事项快照；
- 首页、收集箱、待办、置顶、最近、位置、文档树、已归档与回收站的稳定导航；
- 系统视图：收集箱、置顶、最近、已归档、回收站；
- 自定义父子便签树；
- 展开 / 折叠、移动与排序；
- `@便签`、拖入正文引用与反向引用；
- Markdown 阅读 / 编辑；
- 附件预览、默认应用打开与资源管理器定位；
- 现有功能迁移和重启恢复。

### 不在首版

- 标签系统；
- 多父节点；
- 知识图谱画布；
- Notion 式数据库；
- 未经用户触发或授权的 AI 自动分类、摘要或关联推荐；
- 多人协作、权限与公开分享；
- 自建云同步服务；
- 把所有便签强制映射成用户可见的本子 Markdown 文件。

## 十三、验收旅程

1. **静默捕捉**：无 Provider 时 Alt+N 创建便签，保存后进入收集箱，API 调用为 0；
2. **建立分组**：新建可书写的父便签，把三条现有便签拖入，重启后结构和顺序不变；
3. **交叉引用**：在一条便签中 `@`另一条便签，重命名和移动目标后仍能打开，并显示反向引用；
4. **拖拽语义**：树内拖拽改变归属，拖入正文插入引用，两个操作不会混淆；
5. **历史迁移**：现有平铺便签正文、附件、revision、归档和删除状态全部保留，不被 AI 自动整理；
6. **附件兼容**：分别验证图片托管、普通文件仅引用、开启设置后的普通文件副本；重启后状态一致；
7. **存储迁移**：更改附件存储根，托管文件成功迁移；失败时原路径仍可打开；
8. **文件打开**：支持格式在 Leemo 预览，不支持格式用默认应用打开，资源管理器定位正确，失效路径不误开网页；
9. **归档与删除**：父便签子树归档、恢复、移入回收站和恢复后结构成立；仅移除父节点时子项正确提升；
10. **窄窗**：左树覆盖而非压缩正文，草稿、滚动和选区不丢失；
11. **AI 边界**：浏览、编辑、分组、引用全过程零模型调用；明确点击“问 momo”后才产生一次可见调用。
12. **便签创建待办**：从便签选中两行创建两条关联 Todo；原文原位保留，两条 Todo 均可返回来源，后续编辑互不静默同步。
13. **全局待完成事项**：首次打开零模型调用；手动梳理后生成带真实来源的全局快照；不刷新时重启仍显示旧快照；启用每日自动化后每天最多调用一次，失败时旧快照不丢。

## 十四、实施纪律

- 先写迁移与域规则测试，再改页面；
- 不把 OrganizerPage 的现有功能推倒重写，可拆解复用但必须保持用户路径；
- FileTree、PreviewPane、Markdown 编辑器和系统文件打开能力优先复用现有组件；
- 不在同一实施卡中加入标签、Kanban、云同步或 AI 自动整理；
- 完成必须包含真实 Electron、真实 SQLite、真实附件目录和整进程重启验收；
- 视觉以已确认的云文档 / IDE 双栏心智为准，但最终设计图仍需用户逐步确认。
