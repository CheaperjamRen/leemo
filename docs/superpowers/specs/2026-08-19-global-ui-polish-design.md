# Leemo 全局 UI / UX 精修设计规格

> 日期：2026-08-19
> 状态：基于现有已批准设计稿的实施规格；不重定向产品心智。
> 目标：让当前真实 Electron 页面在信息密度、层级、排版、交互反馈和响应式上稳定达到设计稿 90–95% 的完成度。

## 1. 不变的产品与视觉锚点

- “开始”仍是静态 Human Space；浏览、记录、整理、引用不触发模型。
- 搭子仍是温暖陪伴界面；进入搭子零 API 调用，用户说话或明确操作后 momo 才回复。
- 工作台仍是专业 Agent 工作面；对话、工具轨迹、文件与概览使用真实状态，不制造进度。
- 使用同一 Leemo 深墨蓝 + 琥珀铜识别系统，但三种表面保持气质差异：
  - 开始：冷白、瑞士信息设计、安静而高密度；
  - 工作台：冷灰工具骨架、细分隔、低层次阴影；
  - 搭子：暖燕麦底、柔和曲面与小幅 momo 表情。
- 不加入新的常驻 AI 入口、图表、装饰性大卡或用户未确认的工作流。

## 3. 全局排版与构件规则

### 3.1 字体层级

- 正文基准 `13px/1.55`；中文内容不得长期低于 `12px`。
- 页标题 `22–28px/600`；模块标题 `16–18px/600`；行标题 `13–14px/500–600`。
- 元数据 `11.5–12px`，只允许时间、计数、路径和次级说明使用。
- 同一行图标与文字光学居中；16–18px 图标不得把 12px 文字顶偏。
- 等宽字体只用于命令、代码、路径和数字事实。

### 3.2 密度与留白

- 顶栏保持 64px；页面首屏主要内容应在顶栏下 20–28px 内开始。
- 普通列表行 36–44px；复杂双行条目 52–64px。
- 卡片内边距 14–20px；同级卡间距 12–16px；禁止空内容卡占据 250px 以上高度。
- 空态优先使用 96–160px 的紧凑提示区；只有需要解释和主动作时才放大。
- 工作区视觉主体必须占剩余画布，不因装饰栏或大标题被压缩。

### 3.3 圆角、阴影和颜色

- 控件圆角 6px；普通卡片 8–10px；输入框/弹层 10–14px；不把所有对象都做成胶囊。
- 静态卡片无投影或仅 1px 边界；输入框、菜单、弹层才使用中性短阴影。
- 琥珀色只标记当前表面、主动作、真实进行状态和 focus；不能让整页卡片泛黄。
- 大面积工作画布使用冷白或浅灰；搭子允许一层已批准暖色氛围背景。
- 不用渐变数量作为自动质量指标；渐变是否保留以对应设计稿与整屏观感为准。

### 3.4 交互质感

- Hover：120ms 背景/边界变化；不缩放整卡。
- Pressed：最多 `translateY(1px)`，不做弹跳。
- Focus-visible：2px 半透明琥珀 ring，2px offset；不能只靠颜色差。
- 菜单和选择器覆盖现有空间并向可用方向展开，不能推动主布局。
- 所有复制、保存、重试、打开和切换动作必须有可见状态回执。
- `prefers-reduced-motion` 下取消位移和循环动画，保留文本状态。

## 4. 当前实机差距与修复边界

### 4.1 开始首页

当前四张卡在空态仍维持满态高度，造成无意义的大面积空白。修复为内容自适应：

- 有数据时保持定稿的三行预览与 footer；
- 无数据时使用紧凑说明区和现有真实入口，不生成示例内容；
- 1440×900 仍能看到四卡，但空态网格高度应明显低于满态；
- 当前概览只有一行时不强行撑满 300px。

文档库保持 72px 外层 icon rail + 248px Explorer + 大幅正文，不缩成便签卡。加强选中、focus、toolbar baseline 和状态文字，不减少写作面积。

### 4.2 工作台

- 空态只作为首次进入状态，不可代替真实任务视觉验收。
- 必须新增当前版本的运行中、工具展开、失败重试、成果回执和文件预览截图。
- 输入框保持 820–900px 主宽，`+ / @ 模型 权限 助手`同一基线；窄宽逐项退化为图标。
- 左栏继续保持 288px，空本子/空对话提示压缩为安静行，不使用大卡。
- 冷灰画布可保留极弱空间层次，但正文区、文件区和工具面板必须有明确边界。

### 4.3 搭子

- 保留暖色、momo 与宽松聊天节奏；不把工作台侧栏带入。
- 空态允许呼吸感，但邀请卡、场景提示和输入框应形成一个连续下部操作组。
- 已有对话时不保留首屏巨型问候；消息轨道约 820–900px。
- 发送按钮使用成熟的深墨/低饱和强调，不做糖果或小游戏式高光。

### 4.4 Skill Hub

- 保留三列和当前功能密度。
- 降低整页同色泛黄：卡片使用白/冷白主体，只在精选、安装态或 hover 给琥珀微层次。
- 强化名称、来源、描述、状态/动作四级层级；按钮保持单行且不抢标题。
- 详情页继续展示真实 Skill Markdown，不增加虚构简介。

### 4.5 定时任务

- 当前空态大白卡改为 120–160px 紧凑空态，主动作与说明靠近。
- 有任务时继续使用 64px 左右的重复任务行；不恢复日历视图。
- 创建/编辑弹窗保持中型单列，频率、日期和范围分组清楚。

### 4.6 搜索与右侧工具面板

- 搜索是工作台右侧工具面板，不是覆盖整个应用的第二设置弹窗。
- 宽度约 360–480px；输入框、范围、类型三层节奏清晰。
- 空结果提示靠近搜索控制区，不悬在面板中下部形成断层。
- 960px 以下成为 overlay，不挤压中央内容；关闭后焦点返回原按钮。

### 4.7 设置

- 1440px 保持约 1040×720 中心弹窗与单列设置行。
- 720px 当前横向溢出 40px，必须改为 `max-width: calc(100vw - 24px)` 并重排导航/内容。
- 选中分区、switch、select、文本框使用同一 focus/hover 语法。
- 内容区只允许自身纵向滚动，footer/保存状态不遮挡字段。

## 5. 验收截图矩阵

### 宽屏 1440×900

- 开始：首页空态、首页有快照、文档编辑、文档源码。
- 工作台：空态、运行中、工具详情、失败恢复、文件预览。
- 搭子：空态、普通对话、问询/失败/成果回执至少一项复杂状态。
- Skill Hub：发现页、详情页。
- 定时任务：空态、有数据、创建弹窗。
- 设置：通用、模型、连接器、权限、数据与存储。
- 搜索：当前范围空态和有结果。

### 窄宽

- 960×680：开始文档库、工作台右侧工具 overlay、设置。
- 720×640：搭子输入、工作台输入、设置；不得横向溢出或裁切操作。

每张截图必须检查整屏平衡、信息密度、父布局在删除/隐藏组件后的重新分配、文字/图标基线、交互焦点和真实可点击入口。组件测试通过不能替代整屏通过。

## 6. 实施顺序

1. 共享顶栏、模式选择、输入/focus 与响应式基础；
2. 开始首页空态与文档库细节；
3. 工作台真实任务/输入/工具面板；
4. 搭子对话与复杂状态；
5. 定时任务、Skill Hub、设置；
6. Kimi K3 Max 截图审查；
7. 唯一独立视觉/UX 审计与最终干净提交。
