# Leemo 运行可靠性与搭子连续性设计 v1.0

> 日期：2026-08-27
>
> 状态：方案已确认，进入实现
>
> 承接：`docs/superpowers/plans/2026-08-26-leemo-cost-and-momo-continuity.md`

## 一、目标

本轮要恢复 Leemo 最基础的可信感：模型运行时，窗口仍然可操作；失败后，用户知道问题发生在哪一层并有可执行的恢复入口；换模型、重启和短句续接后，momo 仍沿着用户刚刚在做的事继续；上下文圆环、停止按钮、设置页和文档读取都反映真实运行状态。

这组问题共享同一条产品约束：

> 长期历史可以完整保存，当前上下文必须有界、可解释、可恢复；失败的运行不能改写上一份可信状态。

本轮保留已经确认的搭子单一关系流、内部章节、C 主题、顶部导航、工作台多会话与现有本地数据结构。修改集中在运行状态、恢复语义、性能背压和基础交互契约。

## 二、已验证的问题与根因

### 2.1 “继续”接回更早任务

当前搭子关系流的可见会话为 `ad90923c-d037-45dd-af29-edacf96e8928`。正确的近期工作是读取简历、三份实习材料和 AI 日报 Skill，准备面试故事与 AI 内容质量判断方法。连续多次 TokenFlux 失败后切换 GLM，新的运行只收到了“继续”和一个已经失真的 SDK session。模型明确判断当前缺少上文，随后扫描工作区并捡起了更早的流程图任务。

根因有三层：

1. `ConversationMeta.sessionId` 同时承担“最近见过的 session”和“可以信任的续接 session”两种语义；
2. 失败运行返回的 session 仍可能覆盖上一份可信 session，且没有记录 session 所属 provider；
3. 本地没有一份与模型无关的当前章节检查点，session 失效后只能依赖模型猜测或扫描工作区。

### 2.2 502 被统一显示成网络或服务端错误

对 TokenFlux 当前模型进行最小连接测试后，服务返回的是模型权限失败。Gateway 把上游 401/403 统一转换为 HTTP 502，renderer 只看到通用 server error，用户因此反复重试网络。

同时，Windows 当前启用了 `127.0.0.1:10801` 系统代理。Electron、Node 主进程、Gateway fetch 和 provider 子进程没有共享一套代理语义，从桌面图标启动时可能出现系统浏览器可用、Leemo 直连失败的差异。

### 2.3 运行时界面冻结

模型每个 `text.delta` 和 `thinking.delta` 都立即写入全局 store。搭子页订阅了较宽的状态范围，每次增量都会重新分组关系章节、重建时间线、重新解析历史 Markdown、触发滚动测量，并在安静间隔把完整会话同步写入 SQLite。

这条同步渲染与持久化链路占满 renderer 主线程后，顶部页面切换、设置、执行过程展开和停止按钮虽然仍有事件处理器，点击事件无法及时调度。设置页卡在“正在打开设置…”也是同一类主线程饥饿表现。

### 2.4 停止反馈延迟

renderer 点击停止后等待主进程完成中断、进程树清理和结果验证，IPC 才返回。用户看不到“停止请求已接受”的即时状态，重复点击又被本地 stopping 状态挡住。

### 2.5 上下文上限显示失真

设置里的目标上限、provider 实际模型上限和当前 session 的精确窗口属于三类数据。旧的 Claude 前缀模型别名会让 Harness 套用 200K 内建配置；模型切换后，renderer 还可能短暂显示上一模型的 snapshot。界面曾把运行时 200K 当成设置已生效后的唯一答案，用户无法判断配置、传输还是服务商哪一层存在差异。

### 2.6 31.7MB PDF 走错工具

Leemo 文档引擎支持 64MB PDF，模型却调用了 Claude 原生 Read；原生工具的 20MB 限制直接暴露给用户。Prompt 中的工具偏好无法保证模型每次都选对路径。

### 2.7 临时菜单行为不一致

部分菜单使用 `AnchoredLayer`，已有点击空白处关闭、Escape 和焦点恢复；输入框模型、权限、加号等菜单及少数页面菜单各自维护开关，只实现了部分键盘逻辑。相邻菜单还能同时处于打开态。

## 三、设计原则

### 3.1 可信状态单向推进

会话、章节检查点、上下文 snapshot 和运行结果都区分“候选状态”与“已确认状态”。服务商拒绝、连接失败、未产生有效进展的重试保留诊断记录，同时维持上一份可信状态。

### 3.2 完整历史与工作上下文分层

- 本地时间线保存完整关系历史；
- 当前章节承载最近的工作意图与承诺；
- 发送给模型的窗口由近期消息、稳定关系记忆和相关召回片段组成；
- provider session 可复用时作为快速路径；
- provider session 丢失时由本地章节检查点恢复。

### 3.3 用户动作即时可见

设置、页面切换、展开执行过程、打开菜单和停止请求必须在模型流式输出期间保持响应。后台清理和持久化可以继续运行，界面先确认用户动作已被接收。

### 3.4 错误按恢复动作分类

用户需要看到当前可采取的动作。错误分类至少覆盖：网络、密钥、模型权限、模型名称/接口兼容、余额或额度、频率限制、上游临时故障和本地运行故障。界面保留可展开的技术详情，主文案使用用户语言。

### 3.5 设置与运行共用语义来源

网络模式、上下文目标、provider/model 和运行时 transport 从同一份主进程配置读取。设置改变后，下一次运行必须使用新 transport；界面可验证设置值与当前运行值是否一致。

## 四、搭子连续性

### 4.1 会话所有权

`ConversationMeta` 增加明确的 session 所有者：

```ts
type ConversationSessionRef = {
  sessionId: string
  providerId: string
  modelId?: string
  committedAt: number
}
```

现有 `sessionId` 迁移为最后一份可信 session，兼容旧数据库读取。运行过程中捕获的新 session 先保存在 host 的候选状态，满足以下任一条件后才提交：

- 运行正常完成；
- 用户主动中断，运行此前已经产生可辨认的 assistant 内容或成功工具结果，且 SDK 明确支持从该 session 续接。

鉴权、权限、连接、模型配置和零进展失败均不提交候选 session。provider 切换后，旧 session 仍归原 provider 所有；新 provider 不尝试恢复不属于自己的 session。

### 4.2 本地章节检查点

每个搭子章节保存一份有界、可追溯、无需调用模型生成的检查点：

```ts
type RelationshipContinuationCheckpoint = {
  version: 1
  chapterId: string
  updatedAt: number
  basisRunIds: string[]
  currentGoal?: string
  latestUserIntent: string
  assistantCommitment?: string
  progress: string[]
  attachmentNames: string[]
}
```

检查点只从当前章节的本地事实派生：

- 最近一条包含实际意图的用户消息；
- 最近一次 assistant 对下一步的明确承诺；
- 当前运行中成功的工具动作与停留位置；
- 用户本轮附加的文件显示名；
- 用户明确设置的工作目标或概览。

“继续”“重试”“接着来”等纯续接短句不会替换 `latestUserIntent`。失败且无有效进展的运行不会推进检查点。工作区里的旧文件和旧成果只有在当前章节中被用户或模型明确引用后才进入检查点。

### 4.3 恢复消息

稳定 session 可用时，Leemo沿用 provider session，保持静态前缀逐字节稳定。出现 provider 切换、重启后 session 无法恢复、候选 session 未提交，或用户用弱指代短句续接时，在最新用户消息末尾追加一个有界内部块：

```text
[Leemo 章节续接]
当前目标：准备数据分析岗位面试故事
最近请求：结合简历和三份实习材料梳理故事，并说明如何判断 AI 内容是否可靠
上一步：momo 已承诺先读取材料
材料：AI产品简历…、有效获客泛化.pdf…
[/Leemo 章节续接]
```

这段内容只在恢复边界注入，长度设硬上限，放在消息末尾以保护缓存前缀。模型正常回复和 UI 都不显示内部块。

如果本地没有足够证据形成可靠检查点，momo 会询问用户希望继续哪一件事。此时不扫描工作区寻找可能的旧任务。

### 4.4 单一关系流与章节

搭子页继续呈现一条 momo 关系流。用户点击“新话题”时开启内部章节、清理当前装配窗口并保留完整历史与关系记忆；旧章节仍可召回。工作台继续管理多条任务会话，两种表面通过显式附件、成果或摘要引用连接。

## 五、网络、Gateway 与错误恢复

### 5.1 网络模式

设置新增“网络连接”：

- 自动：读取 Electron session/系统代理，作为默认值；
- 直连：绕过代理；
- 手动代理：用户填写协议、主机和端口。

主进程生成统一 `NetworkRuntimeConfig`，供 Electron 请求、Gateway 请求和 provider 子进程使用。子进程通过受控环境变量接收代理地址，并固定 `NO_PROXY=127.0.0.1,localhost`。手动代理首版不接收嵌入 URL 的账号密码，避免凭据进入 renderer、日志或普通配置。

设置页提供“测试当前连接”和“测试所选模型”两层检查：前者验证代理/DNS/TLS 可达性，后者执行极小模型请求并返回结构化分类。

### 5.2 结构化上游错误

Gateway 对上游响应保留经过清洗的元数据：

```ts
type ProviderFailureKind =
  | "network"
  | "authentication"
  | "permission"
  | "model_not_found"
  | "quota"
  | "rate_limit"
  | "server"
  | "local_runtime"
```

401 映射密钥/鉴权，403 优先映射模型或账号权限，404 映射模型或接口地址，429 根据可用字段区分额度与频率限制。原始上游正文、请求头和 key 不进入 IPC 或日志。

失败卡片根据 kind 给出对应入口：检查密钥、切换模型、打开网络设置、测试连接或稍后重试。重复自动重试对权限和鉴权错误直接停止。

## 六、运行时性能与停止语义

### 6.1 流式事件背压

- `text.delta` 与 `thinking.delta` 按动画帧或约 33ms 合并；
- 工具开始/完成、审批、错误、终态等结构事件立即刷新；
- 只有活动 run 的气泡随 delta 更新；
- 已完成 TurnBlock、Markdown 和关系章节投影使用稳定 key 与 memo；
- 搭子页改用窄 selector，避免订阅整个 conversation map；
- 自动滚动测量合并到帧边界，用户向上阅读时维持位置。

### 6.2 持久化节奏

- 用户消息与附件引用立即保存；
- 活动 run 的增量检查点按低频节流保存；
- 结构事件和终态立即保存；
- renderer 发给主进程的内容使用增量 upsert 或脏段写入，避免每次清空并重建完整时间线；
- 应用崩溃后的可接受损失限制在最近一个短节流窗口内。

### 6.3 停止协议

第一次点击停止后，renderer 立即显示“正在停止”，主进程完成 abort/fence 后快速返回 `accepted`。会话保持运行锁，直到进程树和 transport 清理完成。清理成功后发送 `run.finished: interrupted`；清理失败时保留锁并显示可恢复错误。

重复点击不会并发启动多次清理，界面会持续显示当前停止状态。停止期间，设置、页面切换、历史查看和执行过程展开保持可用。

## 七、上下文用量

界面同时维护三类值：

1. 设置目标，例如 1M；
2. 所选模型宣称的上限；
3. 当前 session 返回的精确 snapshot。

圆环以当前 session 的精确 snapshot 为主。新模型尚未产生 snapshot 时显示“等待首轮确认”，不会沿用旧模型数字。设置目标和运行值不一致时，提示中并列显示：

```text
设置目标 1M
当前运行 200K
当前模型 deepseek-v4-flash
```

并提供“检查模型配置”入口。改变上下文设置后，下一轮强制重建相关 transport，防止旧环境继续运行。Gateway 与直连路径都使用原始第三方模型 ID，避免触发 Claude 内建 200K 配置。

## 八、文档工具路由

`.pdf`、`.docx`、`.pptx`、`.xlsx` 及同族格式统一进入 Leemo 文档引擎。模型调用原生 Read 读取这些格式时，Tool Governance 在执行前改道或返回明确的结构化重定向，引导同一轮调用 `mcp__leemo-documents__read_document`。

附件授权仍以用户本轮明确添加的路径和受控工作区为边界。31.7MB PDF 作为回归样本，验证提取、分页、失败提示和停止行为。

## 九、基础交互契约

所有临时菜单共享同一行为：

- 点击菜单外区域关闭；
- Escape 关闭并把焦点还给触发按钮；
- 再次点击触发按钮切换开关；
- 同一交互区只保留一个菜单；
- 菜单内操作完成后按动作语义关闭；
- Tab 顺序和 `aria-expanded` 反映真实状态。

输入框加号、模型、权限、引用/提及，概览、计划任务、PDF 更多菜单和顶部通知均纳入检查。模态窗口继续使用模态交互，不套用临时菜单的点击外部关闭规则。

README 面向第一次接触 Leemo 的普通 Windows 用户，开篇采用中性、可验证的描述：

```markdown

本地优先的 Windows AI Agent

把长期对话、本地文档和真实文件夹里的执行放在一个桌面应用里。基于 Claude Agent SDK，支持工具调用、Skills、MCP、子 Agent 与多模型。
```

现有使用场景、真实截图和工作流继续保留。功能对照栏目改为“Agent 执行”和“长期对话”等具体标题。正文不出现个人求职项目定位，也不向普通用户堆叠内部工程术语。

## 十一、验收

### 11.1 真实连续性链路

复现以下时间线：添加简历和三份材料，其中包含 31.7MB PDF；TokenFlux 因模型权限失败；切换 GLM；输入“继续”。momo 必须回到面试故事与材料读取，引用正确附件，且不能扫描并接回流程图任务。

覆盖应用重启、provider 切换、连续三次失败、停止后续接、新话题后回忆旧章节。检查数据库中可信 session 所有者、检查点依据 run 和 UI 可见历史一致。

### 11.2 响应性

以 40 轮长历史、高频 delta、长 Markdown 和工具过程进行压力测试。运行中顶部“开始/工作台/搭子”、设置、执行过程折叠、历史查看与停止可点击，交互反馈目标在 100ms 内出现。renderer 不出现长任务冻结，内存与 CPU 在流结束后回落。

### 11.3 网络与错误

自动模式识别当前 `127.0.0.1:10801` 系统代理；直连、手动代理和无效代理分别产生正确结果。TokenFlux 模型权限失败显示权限分类，GLM 成功链路不受影响。敏感 key、代理信息和上游原始正文不进入日志与 IPC。

### 11.4 上下文与文档

1M 设置在直连和 Gateway 模型上都完成首轮 snapshot 验证。出现 200K 运行值时，界面准确显示配置与运行差异。31.7MB PDF 经 Leemo 文档引擎读取，停止、错误和分页可用。

### 11.5 交互、视觉与恢复

逐个检查临时菜单的外部点击、Escape、焦点恢复和互斥。设置页在模型运行中打开，关闭后输入焦点恢复。1440×900、当前用户窗口和窄窗口检查父级布局；最新截图保存到 `.tmp-visual-audit`，不提交仓库。

### 11.6 工程与发布

聚焦测试通过后运行：

```bash
npm run typecheck
npm test
npm run verify:bundled-skills
npm run build
npm run build:main
```

随后完成 Electron 真机、重启恢复、安装包验收、版本号更新和 Git 清理。安装包、截图、个人路径、密钥、日志和测试用户数据不进入提交。
