# Leemo 工作台连续性概览设计 v1.0

> 日期：2026-08-22
>
> 状态：产品方案与书面规格已确认，等待按实施计划执行
>
> 上游：`docs/superpowers/specs/2026-08-04-workbench-global-map-design.md`、`docs/specs/02-已定决策清单.md`
>
> 适用范围：工作台右侧“概览”面板中的“本次会话 / 当前本子”视图
>
> 替代关系：本规格细化并替代上游规格 §7.4“概览”的字段、更新与真实性规则；不改变工作台三栏职责、Todo/Run 分离、用户 Todo 完成权和目标模式定义。

## 一、结论

Leemo 的概览不是标题摘要、成果列表或项目管理仪表盘，而是：

> **帮助用户在长会话、长任务和任务切换后，重新找回工作目标、当前位置、已知剩余工作和已完成证据的连续性快照。**

它必须让用户在十秒内回答：

1. 这段工作最初为什么开始；
2. 现在处于整体过程中的哪里；
3. 这一轮 Agent 正在做或刚做完什么；
4. 已经确认完成了什么；
5. 目前明确还剩什么；
6. 是否有阻塞、等待或需要用户决定的事项；
7. 有哪些真实成果可以直接打开。

概览采用双层更新：

- **事实层**从真实 Plan、Task、Tool、AskUser、审批、Run 和 Artifact 事件持续派生，不消耗模型 Token；
- **语义层**复用当前模型所在轮次，在真正发生目标、阶段、约束或结果变化时写入一个有界增量，不额外启动后台摘要请求。

打开概览本身绝不调用用户 API。模型缺席、离线或漏写语义增量时，事实层仍能独立工作。

## 二、问题定义

### 2.1 当前失效方式

当前 `WorkOverviewData` 只有：

- `theme`；
- `summary`；
- `currentPosition`；
- `nextStep`；
- `focus`。

现有模型工具说明只要求在用户主动提出“强调、记住、重定向概览”时更新。没有语义概览时，renderer 使用会话标题、通用运行状态和最近成果拼出 fallback。因此当前产品会稳定退化为：

```text
这个本子在做什么
原生工具能力验收
最近产出了 package.json
```

这段文字不能回答用户在整体过程中的位置，也不能帮助用户恢复工作。

### 2.2 结构性缺口

1. `theme` 只是标题，不是工作目标或完成条件；
2. 当前本子视图选择本子内最新的一条会话概览，未聚合本子的活跃工作；
3. 当前 Run 结束后，本轮计划不再被视为当前计划，已做步骤与剩余步骤容易消失；
4. 没有字段级来源、更新时间、更新原因和历史 revision；
5. 没有区分稳定信息、动态状态、事实证据和推断；
6. 没有规定何时值得调用模型更新，何时必须跳过；
7. 没有防止模型虚构完成度、剩余范围或 Todo 完成。

## 三、产品边界

### 3.1 概览是什么

- 一张当前状态快照；
- 一个任务恢复入口；
- 对真实事件和有界语义检查点的只读投影；
- 当前会话与当前本子的连续性辅助层。

### 3.2 概览不是什么

- 不是第二套 Todo 数据库；
- 不是工作脉络、WorkThread 等用户可见的新概念；
- 不是目标模式；
- 不是由模型自动判定用户 Todo 完成的地方；
- 不是每轮生成一篇摘要文章；
- 不是团队项目管理中的负责人、健康度、工期和燃尽图集合；
- 不是打开面板就触发的 AI 功能。

### 3.3 与三类相邻对象的关系

| 对象 | 概览如何使用 | 不能做什么 |
| --- | --- | --- |
| 用户 Todo | 仅在会话明确绑定该 Todo 时显示引用 | 模型不得自动完成或改写用户 Todo |
| Agent Run Plan | 显示本轮真实步骤、状态与已知进度 | 不把本轮 `2/4` 冒充总体目标完成 50% |
| 目标模式 | 可显示目标模式的持久目标和当前状态 | 普通概览不会创建、恢复或延长目标模式 |

## 四、研究依据与产品推论

任务恢复研究表明，中断后用户需要重新激活原目标，并依赖环境或语义线索恢复；编程任务中的中断会导致用户反复检查任务要求、当前代码状态和下一步操作。因此 Leemo 的恢复线索必须覆盖“目标、当前位置、下一步”，而不是只保留标题。

成熟项目工具还提供三条适用于 Leemo 的原则：

1. 稳定状态与阶段性更新分开；
2. 当前快照与历史更新分开；
3. 项目阶段与阶段内任务分开。

Leemo 只吸收这些信息结构，不复制团队项目管理的重量。个人任务恢复面板的首要目标是减少重新翻阅，而不是提供管理指标。

## 五、信息模型

### 5.1 两类信息

概览把数据分成“语义锚点”和“实时事实”。

#### 语义锚点

由当前模型在有意义的检查点提交，并按字段增量合并：

| 字段 | 用户含义 | 更新特性 |
| --- | --- | --- |
| `objective` | 这段工作的目标 | 稳定；只有明确改向时更新 |
| `successCriteria` | 怎样才算达到目标 | 稳定；允许为空，不凭空补齐 |
| `currentPhase` | 当前处于整体过程的哪个阶段 | 随阶段变化覆盖 |
| `currentFocus` | 眼下正在解决什么 | 随当前工作覆盖 |
| `nextKnown` | 目前明确的后续行动 | 有界列表，随状态覆盖 |
| `blockers` | 当前阻塞、等待或不确定性 | 有界列表，解除后显式清空 |
| `decisions` | 影响后续工作的关键决定 | 追加，有来源与去重 |
| `completedHighlights` | 值得跨轮记住的完成事实 | 追加，有证据与去重 |

输入上限固定为：`objective` 160 字；`currentPhase`、`currentFocus` 各 120 字；其余数组每次最多 5 项、每项最多 120 字。单次 patch 的用户可见文字总量不得超过 800 字。

Patch 语义必须明确：

- 字段缺失表示沿用上一 revision；
- 数组字段显式传入空数组表示清空；
- 单值字段通过 `clearFields` 显式清空，不能用空字符串表达；
- `completedHighlights` 与 `decisions` 按证据 ID 去重追加，其余数组覆盖；
- `updateReason` 只允许 `objective-set`、`objective-changed`、`phase-changed`、`blocked`、`recovered`、`run-completed`、`manual-refresh`。

#### 实时事实

不由模型复述，直接从现有事件派生：

- 当前 Run 状态；
- 本轮 Plan/Task 步骤及 `done / active / todo`；
- 审批、AskUser、失败、重试和恢复；
- Subagent 活动；
- 文件变化与 Artifact；
- Run 完成、中断与失败；
- 用户 Todo 的只读绑定关系。

### 5.2 版本与来源

每个语义检查点保存：

- `revision`；
- `scopeConversationId`；
- `sourceRunId`；
- `updatedAt`；
- `updateReason`；
- `basisEventIds`；
- 本次 patch 的字段。

字段按 patch 合并，未提交的稳定字段继续保留。任何“已完成事实”必须能追溯到真实事件、成功工具或成果；不能只以助手正文作为证据。

### 5.3 历史保留

- 当前 UI 只显示最新快照；
- “自上次更新”显示最近一次有意义变化；
- 旧 revision 保留在会话时间线中，用于恢复、调试和未来历史查看；
- 不建立第二套独立任务数据库；
- 不把每次工具调用复制成语义历史。

## 六、更新策略

### 6.1 事实层：持续、零模型成本

以下事件到达后，界面立即重新派生：

- Plan/Task 创建与状态更新；
- Tool/Activity 开始、完成、失败；
- AskUser 和审批出现或解决；
- Retry 状态变化；
- Run 开始、完成、失败或中断；
- Artifact 和文件变化。

事实层不生成自然语言长摘要，不调用模型，也不等待语义层。

### 6.2 语义层：有意义的检查点

默认只在以下时刻由当前轮模型顺手提交 patch：

1. 用户首次明确本段工作的目标；
2. 用户显式改变目标、范围、关键约束或完成标准；
3. 长任务进入一个新的工作阶段，且当前 Plan 无法单独表达这个变化；
4. 出现阻塞、等待用户决定、重大失败或恢复；
5. 一轮任务结束，并且确实产生新进展、关键决定或成果；
6. 用户主动选择“更新概览”。

### 6.3 必须跳过的情况

- 普通闲聊；
- 纯解释、无工作状态变化的回答；
- 重复读取、搜索或探测；
- 无净变化的重试；
- 单个内部工具调用；
- 只改变展示元数据；
- 已有事实层足以表达的细小步骤流转；
- 打开、关闭或切换概览面板。

### 6.4 成本规则

- 不新增默认后台摘要请求；
- 同轮 patch 会产生少量工具参数 Token，但必须有字段和长度上限；
- 一轮任务通常最多在终态提交一次语义 patch；
- 只有目标改向、阻塞或真正跨阶段的长 Run 才允许在终态前追加一次；
- 手动“更新概览”是用户明确触发的模型操作；
- API 不可用时只保留事实层，不显示失败大卡，也不清空旧语义锚点。

## 七、真实性规则

### 7.1 进度

- 有真实有限 Plan 时显示：`已完成 2/4 个已知步骤`；
- 不把已知步骤比例换算成总体目标百分比；
- Plan 增减时，分母可以变化，并保留“当前计划”语义；
- 没有有限 Plan 时不显示百分比或伪进度条；
- “还剩什么”只列用户明确要求或真实 Plan 中的已知项；
- 模型推断但未确认的后续必须标成“可能需要”，不能混入确定清单。

### 7.2 完成

以下任一证据可以支持“已完成事实”：

- 成功 Tool/Task 结果；
- 已保存 Artifact；
- Run 终态与对应输出；
- 用户显式确认。

助手正文中的“完成了”不能单独作为证据。失败、拒绝、取消和中断均不能投影为完成。

### 7.3 用户权利

- 用户 Todo 的完成权始终属于用户；
- 用户可以编辑工作目标和完成标准；
- 用户编辑后的字段优先于模型推断；
- 模型只有在用户后续明确改变方向时才能更新用户固定的工作锚点；
- 所有语义 patch 都可被用户纠正，纠正产生新 revision，不重写历史。

## 八、范围设计

### 8.1 本次会话

存在当前会话时，打开概览默认进入“本次会话”。内容顺序固定为：

1. 工作目标；
2. 当前阶段与当前重点；
3. 本轮执行；
4. 接下来；
5. 阻塞或待用户决定；
6. 已完成；
7. 相关成果。

“工作目标”是当前会话的任务锚点，不等于目标模式。

### 8.2 当前本子

当前本子不再展示最新会话的一段摘要，而是聚合本子内会话快照：

- 本子的稳定主题或用户固定目标；
- 最多五条活跃会话；
- 每条会话的当前阶段、下一步和阻塞；
- 最近完成的重要结果；
- 需要用户处理的事项。

本子视图不把不同会话合成为一段无来源的大摘要。每一项都可以跳回来源会话。

### 8.3 无当前会话

- 有当前本子：默认当前本子；
- 无本子：显示当前全局范围内的活跃会话；
- 完全无工作事实：显示克制空状态，不调用模型生成内容。

## 九、界面结构

### 9.1 顶部

- 范围切换：`本次会话 / 当前本子`；
- 最近更新时间；
- 低干扰的更多菜单，包含“更新概览”和未来的历史入口；
- 不把进行中数量、成果数量作为最强视觉元素。

### 9.2 主体

```text
工作目标
完成本轮原生工具验收，并保留可复现证据。

当前阶段
正在验证文件操作与恢复链路
本轮执行  2/4 个已知步骤

接下来
○ 验证 Explorer 拖入输入框
○ 完成安装包重启恢复

阻塞或待决定
需要确认失败重试后的文件状态

已完成  3
✓ 已完成 MCP echo 验收
✓ 已生成并打开测试文件

相关成果  6
package.json · cart.test.js · notes.md
```

### 9.3 视觉与密度

- 这是信息侧栏，不使用一组高卡片堆叠；
- 标题、当前阶段和下一步优先于成果；
- 每区默认最多显示三到五条，历史折叠；
- 使用分组、缩进、状态符号和细分隔建立层级；
- 不用大面积进度色、仪表盘数字或虚构健康度；
- 进行中、阻塞、失败使用已有语义 Token；
- 视觉与工作台现有 C 主题一致，不新增页面私有颜色；
- 右侧面板宽度不足时文字换行，动作不挤压正文；
- `本次会话`有当前会话时是默认选项，降低用户恢复当前任务的操作成本。

## 十、降级与恢复

### 10.1 模型漏写语义 patch

- 保留上一版稳定工作目标；
- 当前阶段、Plan、等待、失败和成果继续由事实层更新；
- 显示真实更新时间；
- 不自动发起补写请求。

### 10.2 语义 patch 无效

- 拒绝超长、空值、错误类型和越界字段；
- 当前快照保持不变；
- 工具错误只进入折叠过程，不在概览展示错误大卡；
- 事实层继续工作。

### 10.3 重启与旧数据

- 旧五字段概览在迁移时映射到兼容字段，不丢失；
- 旧 `theme` 只作为候选目标标题，不能冒充完整 objective；
- 旧会话无语义锚点时使用事实层与克制空态；
- revision、来源事件和更新时间随会话时间线持久化；
- 重启后不得重新调用模型重建概览。

### 10.4 跨会话与本子

- 会话级 patch 只与同一会话的历史合并；
- 本子聚合保留每一项的 conversationId；
- 不允许另一条会话的 partial patch 与当前会话 fallback 拼成混合事实；
- 会话移动、归档或删除后，本子聚合按真源重算。

## 十一、测试设计

### 11.1 数据与归一化

- 接受合法 patch 并保留未更新稳定字段；
- 显式清空 blocker/nextKnown 的语义明确；
- 拒绝空值、超长列表、错误类型和无来源完成事实；
- 旧字段兼容迁移；
- 同一会话 revision 合并，跨会话禁止混合。

### 11.2 事实投影

- Plan 创建、步骤推进和 Plan 扩展；
- Run 成功、失败、中断和恢复；
- AskUser 与审批进入、解决；
- Artifact 创建、修改和删除；
- Subagent 运行与终态；
- 旧 Run Plan 不再显示为当前执行，但其已完成事实可保留；
- 用户 Todo 不被 Agent Run Plan 修改。

### 11.3 更新策略

- 普通聊天不调用概览工具；
- 无净变化的读取/搜索不调用；
- 目标改向、阻塞和有成果的 Run 终态允许提交 patch；
- 打开面板不调用模型；
- API 不可用时事实层仍可用；
- 一般 Run 不超过一次终态语义 patch。

### 11.4 界面旅程

- 有当前会话时默认“本次会话”；
- 切换当前本子后显示多会话聚合，不显示最新会话冒充本子摘要；
- 点击活跃项、阻塞项和成果可回到真实来源；
- 没有有限 Plan 时不出现百分比；
- 计划为 `2/4` 时明确写“已知步骤”；
- 用户修正目标后重启仍保留，模型普通更新不能覆盖；
- 1440×900、1280×860、1024×768、960×680 下层级可读且无横向溢出；
- 面板窄宽与聚焦宽度都完成真实截图；
- 当前主题、失败、重启恢复均使用真实安装包路径验收。

## 十二、实施边界

本规格只授权设计，不自动授权代码实现。获用户书面复核后，下一步实施计划应限定在：

1. 扩展现有 work-overview contract 与 MCP，不新建第二套数据库；
2. 在现有 timeline/event projection 上增加 revision、来源和事实派生；
3. 修正本子聚合与会话默认范围；
4. 重构 WorkbenchOverview 信息层级；
5. 增加有意义检查点的模型语义约束；
6. 完成 focused tests、全量类型检查、真实页面和安装包重启验收。

不在本卡内：

- 重做开始页 Todo；
- 改变目标模式语义；
- 自动完成用户 Todo；
- 引入后台摘要服务；
- 建立完整项目管理系统；
- 改写搭子态视觉；
- 修复快速记录编辑器。快速记录光标/占位错位与正文占比优化继续保留为本卡之后的独立任务。

## 十三、完成判据

准备一段至少包含五轮用户指示、两个 Run、一次 Plan 修改、一次等待用户、一次失败恢复和三个成果的真实会话。用户在不翻阅历史消息的情况下，打开概览后应在十秒内准确回答：

1. 原始工作目标；
2. 当前阶段；

- 面板打开不产生模型请求；
- 普通工具噪声不产生语义更新；
- 概览没有虚构百分比、完成事实或用户 Todo 状态；
- 重启后快照、来源与用户修正保持一致；
- 当前本子视图能区分多个活跃会话；
- 概览失败不会使 Agent 主任务失败；
- 用户不需要理解新的内部对象或维护第二套任务卡。
