# Leemo 模型接入、排序与路由设计 v1.0

> 日期：2026-07-30
> 状态：已实现并完成发布包用户路径验收
> 上游：`docs/plans/2026-07-30-r9-trustworthy-continuity-design.md`、`docs/NewmaxAI逆向报告/NewMax-预置Provider与模型接入全量整理.md`
> 后续卡：原生 Auto Memory + Leemo 记忆治理层
> 验收证据：`docs/research/2026-07-30-model-onboarding-verification.md`

## 一、目标

让第一次接触桌面 Agent 的用户，不需要理解 Claude Code、Provider、模型别名或环境变量，也能在一个连续页面内完成：

```text
选择服务商 -> 填写凭据 -> 获得或手动添加模型 -> 调整顺序
-> 测试连接 -> 保存 -> 在聊天中使用
```

模型设置页只负责模型接入、可用模型和默认顺序。余额、Token 与费用迁移到独立的“用量”一级设置页，不再混入模型接入心智。

本卡同时修正一个运行时语义错误：未显式选择子任务模型时，Leemo 不再强制写入 `CLAUDE_CODE_SUBAGENT_MODEL`，而是保留 Claude Code 原生继承和子 Agent 自身选模规则。

## 二、已经确认的产品决策

| 决策 | 结论 |
|---|---|
| 设置外壳 | 保留现有中型弹窗、左导航右内容，不改成侧栏抽屉 |
| 模型接入结构 | Provider-first：左侧服务商，右侧单页配置 |
| 添加入口 | 预设服务商和“自定义 Provider”都使用可点击小卡片 |
| 编辑结构 | 移除“连接 / 模型与角色 / 高级”三页签；必需步骤在一张连续页面 |
| 默认顺序 | 服务商第一项 + 该服务商模型第一项 = 应用默认模型 |
| 排序交互 | 支持拖拽；同时提供“设为默认”和键盘可操作的顺序调整 |
| 子任务模型 | 用人话表达并藏入高级设置；默认自动继承 |
| 能力识别 | 测试连接自动以最低成本探测图片和深度思考，不要求用户勾选 |
| 图片发送 | 能力探针只提供证据，不作为权限；任何探测结果都不能硬拦截图片选择或发送 |
| 底层边界 | 设置界面不出现 Claude Code、环境变量或 Fable/Sonnet/Opus/Haiku 等底层心智 |
| 用量 | 设置左侧独立一级标签；本卡迁移现有真实能力，不造复杂仪表盘 |
| 视觉 | 延续 Leemo 的 Swiss utility panel：中性表面、细分隔线、单一橙色强调、紧凑信息密度 |
| 依赖 | 不引入拖拽库，不增加不必要的小文件和安装包负担 |

## 三、为什么不采用另外两种结构

### 方案 A：Provider-first 单页接入（采用）

服务商是密钥、端点、协议和模型列表的共同所有者。用户先选服务商，再在同一编辑面完成模型接入，符合现有数据结构，也接近 NewMax 的 Provider 管理方式。

### 方案 B：全局模型列表

把每个 `providerId + modelId` 都变成左侧一行，默认模型排序更直接，但同一服务商的 Key、地址和模型会被拆散；多模型服务商会重复出现，维护成本和信息噪声更高，因此不采用。

### 方案 C：首次向导 + 日常编辑器

向导对第一次接入友好，但会形成两套交互、状态管理和验收路径。当前阶段应把单页编辑器本身做到足够顺滑，不建设第二套界面。

## 四、信息架构

设置左侧一级导航调整为：

```text
01 通用
02 模型
03 用量
04 个性化
05 连接器
06 权限
```

“模型”页不再出现用量与费用。“用量”页不承担接入和 Key 配置。

设置搜索同步遵守这条边界：搜索“费用 / Token / 余额”进入用量页；搜索“API Key / 模型 / 服务商”进入模型页；搜索“快速任务 / 后台任务 / 子任务模型”进入模型页并展开对应的人话高级设置。底层别名不进入搜索词表。

## 五、模型页设计

### 5.1 服务商侧栏

模型页左侧只显示“已接入服务商”，不再把所有未配置预设混进主列表。

每行显示：

- 服务商名称；
- 已连接、已配置、需修复或测试中的真实状态；
- 该服务商第一模型；
- 首位服务商的“默认”标识；
- 拖拽手柄。

行为：

- 拖拽改变服务商使用顺序；
- 首位服务商成为默认服务商；
- 行内“设为默认”动作可把该项移到首位；
- 键盘操作可完成同样的上移、下移和设为默认；
- 切换服务商时继续沿用现有未保存修改保护；
- 未配置服务商只出现在“添加服务商”入口，不参与排序。

空状态只提供一个明确动作：“添加模型服务商”。

### 5.2 添加服务商入口

点击“添加模型服务商”后，右侧或其上的选择面展示小卡片网格。卡片不是装饰，点击后必须进入真实配置页面。

首批卡片：

- DeepSeek；
- GLM（智谱）；
- Kimi（月之暗面）；
- 通义千问（百炼）；
- 项目中其他已有预设；
- 自定义 Provider。

每张预设卡片显示品牌名称、连接方式和一句必要说明；不放虚构模型、价格或连接状态。自定义 Provider 卡片与预设并列，使用加号图标和“自定义 Provider”名称。

点击预设卡片后：

- 预填服务商名称、协议、Base URL、模型发现地址和获取 Key 地址；
- 普通用户首先看到 API Key 与模型选择；
- 预设协议不要求用户理解或再次选择；
- 允许有需要的用户展开高级设置修改地址。

点击“自定义 Provider”后：

- 名称、兼容协议、Base URL、API Key 都是主流程字段；
- 不把完成自定义接入所必需的协议和地址藏进高级设置；
- 模型发现失败时仍可在同一页面手动添加模型。

### 5.3 连续配置页面

移除当前“连接 / 模型与角色 / 高级”三个编辑页签。右侧采用一张可滚动页面，底部操作栏固定可见。

页面顺序：

1. **连接信息**：名称、API Key，以及该服务商完成连接所需的地址/协议；
2. **可用模型**：拉取模型、筛选勾选、手动输入、自动能力结果和排序；
3. **高级设置**：默认折叠，存放非首次接入必需的能力；
4. **连接结果**：固定在操作栏上方，清楚区分成功、失败和未测试；
5. **操作栏**：取消、测试连接、保存设置。

模型拉取失败时，错误和“手动添加模型”必须同时处于当前视野，不要求用户换页。

### 5.4 模型顺序

服务商内已启用模型使用有序列表：

- 第一项是该服务商首选模型；
- 支持拖拽、上移、下移和“设为首选”；
- 新增第一个模型时自动成为首选；
- 删除首选模型后，下一项成为首选；
- 长模型 ID 必须截断但可通过 title/tooltip 查看完整内容；
- 图片与深度思考能力只展示自动探测结果，不提供要求用户自行判断的复选框。

应用默认模型由“首位已接入服务商 + 该服务商首位模型”推导。设置页不再另放一个会与顺序打架的全局下拉框。

当前对话中用户手动选择的模型不会因设置页拖拽而中途切换；新对话和没有显式选择的对话使用新的默认顺序。

### 5.5 自动能力探测

“测试连接”固定测试当前服务商的首选模型，按顺序执行：

1. **最小文本请求**：验证地址、凭据、模型和基础响应，记录延迟与实际回显模型；
2. **图片请求**：发送 Leemo 内置的 32x32 红蓝测试图和极短问题，验证模型是否真的看懂图片；
3. **深度思考请求**：使用该协议可表达的最低思考档位或最小预算，并设置严格输出上限，检查真实的 thinking/reasoning 信号。

这三项都由主进程直接请求上游，不启动完整 Agent 会话，不带系统人格、历史对话或用户文件。文本请求失败时跳过后两项，避免对错误地址或无效 Key 继续发请求。

自动探测结果采用三态，但 UI 使用审慎文案：

- **已验证支持**：得到真实图片识别结果或可验证的思考信号；
- **本次检测未通过**：上游明确拒绝该探针，或图片请求成功但模型在这次测试中表示无法看图；
- **未确认**：请求异常、上游忽略能力参数，或返回内容不足以形成可靠结论。

不得把“本次检测未通过”改写成绝对的“模型不支持”。“没有看到思考内容”也不能直接判定为不支持。图片测试不能只看 HTTP 200；必须检查模型是否正确描述测试图。结果区只展示“图片”和“深度思考”，不探测文档和视频：文档通常属于应用侧解析能力，视频在当前产品中既没有稳定输入链路，也没有低成本通用探针。

一次测试最多产生三个短请求。按钮附近说明会自动测试“连接、图片、深度思考”，但不要求用户逐项选择。探测结果写入当前草稿，用户保存后才进入该模型的持久化能力记录；未保存离开时继续走草稿保护。

为控制成本，普通“测试连接”只探测首选模型，不自动遍历全部备用模型。其他模型只显示“未确认”；当它被设为首选后，下次测试自动验证它。本卡不增加逐模型探测按钮，也不能恢复人工能力勾选。

预设目录携带的能力元数据只用于提供初始兼容提示，不能伪装成实测结果。只有本机探针成功才显示“已验证支持”。“未确认”不得等同于“不支持”，也不得仅因此移除图片附件入口；真实发送失败时再给出可操作错误。

### 5.6 能力证据不是发送权限

用户选择图片时，Leemo 只把本机文件加入当前草稿，并没有理由因为模型能力判断而拒绝。即使任务使用的模型不能识图，用户仍可能要求移动、重命名、归档图片，或让 momo 使用工具处理它。因此：

- 图片选择入口始终可用；
- 图片可以在“已验证支持 / 本次检测未通过 / 未确认”任一状态下发送；
- 不弹阻断式确认框，不要求用户先去设置页修改能力；
- “未确认”显示中性提示；“本次检测未通过”显示琥珀色提示“模型仍可能支持图片”；
- 提示提供“选择其他模型”动作并打开模型选择器，但 Leemo 不擅自替用户切换模型；
- 本卡不建设自动图片 Fallback，也不偷偷把图片交给另一家服务商。

能力结果必须记录来源，而不是只有一个没有上下文的布尔值。至少区分：

```text
已验证支持 · 自动探测
本次检测未通过 · 自动探测
未确认
用户已确认支持
```

当用户认为检测错误时，结果旁提供“重新检测”和“我确认这个模型支持图片”。用户确认后，显示“用户已确认支持”，其优先级高于后续自动探针；除非用户选择“恢复自动判断”，后台测试不能静默覆盖。这个纠错入口只在结果存在争议时出现，不恢复首次配置中的人工能力复选框。

若真实任务请求被上游以图片能力错误拒绝：

- 不把图片静默删除或降级为纯文本请求；
- 保留用户文字、附件路径和本轮重试上下文；
- 显示真实上游原因；
- 提供“选择其他模型”和“仍用当前模型重试”；
- 一次真实失败不能永久封禁该模型的图片发送能力。

## 六、高级设置与模型路由

高级设置默认折叠，使用人话分组：

- **快速与后台任务**：自动推荐 / 指定模型；
- **子任务使用的模型**：自动继承 / 指定模型；
- **高级连接参数**：模型发现地址、获取 Key 地址、自定义请求头。

默认值均为“自动”。普通用户不需要打开此区才能完成接入。

### 6.1 产品边界

Leemo 是建立在现有 Agent Harness 上的独立产品。设置界面、搜索词、帮助文案和错误提示都不得要求用户理解底层 Harness 的品牌、模型别名或环境变量。用户只需要理解：当前聊天模型、快速与后台任务模型、子任务模型。

### 6.2 运行时内部翻译

- “子任务使用的模型 = 自动继承”时，Leemo 不写入 `CLAUDE_CODE_SUBAGENT_MODEL`；
- 用户明确指定时才在内部翻译为相应的子任务模型覆盖；
- 底层需要的模型别名全部由 Leemo 根据首选模型、快速任务模型和子任务模型自动生成，不提供原始槽位编辑器；
- 自动生成的兼容值不能覆盖子 Agent 自己更具体的选模规则；
- OpenAI 兼容网关仍负责把 UI 中的真实模型 ID 转换为 Claude Code 可接受的网关 ID，再在上游恢复；
- 旧配置中的快速模型和子任务模型尽可能迁移到新的人话字段；其余原始别名仅用于向后兼容读取，不再出现在 UI 或继续要求用户维护。

## 七、用量页

“用量”成为设置左侧一级标签。本卡迁移当前已存在的真实数据能力：

- 今天 / 近 7 天；
- 输入 Token、输出 Token；
- 可计价费用；
- 按服务商汇总；
- 服务商支持时的余额查询；
- 未知价格显示“未定价”，不估算或伪造。

模型编辑器头部不再放余额入口。余额、Token 和费用都进入用量页。

本卡不做：趋势图、月报、预算提醒、价格编辑、多币种换算、智能成本建议。后续增强不得迫使模型页再次改信息架构。

## 八、数据与迁移

### 8.1 服务商顺序

新增持久化的服务商顺序，只保存服务商 ID，不复制 Provider 配置。未知或已删除 ID 在读取时过滤，新接入服务商追加到末尾。

### 8.2 兼容旧默认模型

首次读取新结构时：

1. 原 `defaultProviderId` 对应的服务商移到首位；
2. 原 `defaultModelId` 在该服务商模型列表中移到首位；
3. 若旧值不存在，保持当前稳定列表顺序；
4. 迁移后继续兼容旧字段一段版本周期，避免回退版本时立即丢配置。

排序变化时同步现有默认字段，使尚未迁移的消费者仍得到一致结果。不得维护两套彼此独立的默认真源。

### 8.3 密钥与草稿

- API Key 和秘密请求头继续只进入主进程加密配置；
- Provider 卡片、排序和用量页不得读取或显示明文密钥；
- 切换服务商、搜索设置、关闭弹窗和 Escape 都继续保护未保存草稿；
- 测试使用当前草稿，保存与测试保持两个动作。

## 九、错误与边界状态

- 无服务商：显示添加入口，不显示空编辑器；
- 有预设但未接入：只在卡片目录显示“待配置”；
- 模型发现失败：保留错误，同时开放手动模型输入；
- 测试失败：显示端点、认证、模型不存在、限流、网络或未知错误中的可靠分类；
- 保存成功但列表刷新失败：保留已确认保存结果和错误提示，不伪装为未保存；
- 默认服务商被删除：下一可用服务商接替；没有可用服务商则默认模型为空；
- 排序中关闭页面：仅已持久化的排序生效，草稿仍走离开保护；
- 窄窗口：侧栏变为横向紧凑列表，但操作栏、模型输入和错误信息始终可达。

## 十、验收标准

### 10.1 全新用户路径

在干净配置中完成：

```text
设置 -> 模型 -> 添加服务商 -> 点击 DeepSeek 卡片 -> 粘贴 Key
-> 拉取或手动添加模型 -> 调整首选 -> 测试 -> 保存
-> 关闭设置 -> 新建对话 -> 默认模型正确
```

整个过程不能切换编辑页签，不能看到底层模型别名、环境变量或 Agent Harness 内部术语。

### 10.2 现有用户路径

- 升级前默认 Provider/模型在升级后仍为默认；
- 重启后服务商和模型顺序保持；
- 设置页顺序与对话模型选择器顺序一致；
- 当前对话手动模型不会因拖拽立即改变；
- 快速任务模型和子任务模型以人话保存、重启和运行，旧原始映射不会重新暴露给用户。

### 10.3 子任务路由

- 默认“自动继承”时，子 Agent 前置定义和逐次 model 参数仍可生效；
- 显式指定子任务模型时，运行时使用该模型；
- 普通用户路径不展示原始变量名。

### 10.4 自动能力探测

- 普通测试连接自动发送最小文本、内置测试图片和最低档深度思考探针；
- UI 不存在“思考能力”“视觉能力”人工复选框，也没有测试图片/思考的额外开关；
- 文本失败时不发送能力探针；首选模型测试最多三次短请求；
- 图片能识别红蓝测试图才显示“已验证支持”，仅 HTTP 200 不算；
- 图片探针失败或回复无法看图时显示“本次检测未通过”，不显示绝对的“模型不支持”；
- 深度思考有真实 thinking/reasoning 信号才显示“已验证支持”，没有信号但也没有明确拒绝则显示“未确认”；
- 探测失败不影响已经成功的基础连接结论；
- 结果区只出现“图片”和“深度思考”，不出现文档或视频能力。

### 10.5 图片发送与纠错

- `未确认` 和“本次检测未通过”都不能隐藏附件入口或拒绝发送；
- 提示非阻断，用户无需先改设置；
- “我确认这个模型支持图片”会覆盖自动探针，并在重启后保持；
- “恢复自动判断”删除用户覆盖，重新显示最新探测证据；
- 图片实际请求失败后，文字和附件仍可用于切换模型或原模型重试；
- Leemo 不静默去图、不自动跨服务商切换，也不因一次失败永久封禁。

### 10.6 用量

- 模型页不存在用量、费用或余额区块；
- 一级“用量”页展示当前真实 today / last7d 数据；
- 未定价和不支持余额时如实显示；
- 不存在假图表或占位统计。

### 10.7 工程与视觉

- 每项行为先写失败测试并确认按预期失败；
- 定向测试、全量测试、三套 typecheck、renderer/main 构建通过；
- 涉及 host/env 的变更在打包应用中完成真实子 Agent 路由验证；
- 1440x900、1280x720、1024x768 和较窄设置窗口截图无横向溢出、遮挡或不可达操作；
- 无新拖拽依赖；安装包文件数、解包体积和主渲染 chunk 与基线对比，无无法解释的明显增长；
- 设置搜索能分别定位模型接入、用量和人话任务模型设置，不再把所有关键词都塞回模型主页；
- 设置页生产代码与可见文案扫描不得出现底层模型别名、原始环境变量或底层 Harness 品牌入口；
- 测试截图、日志和提交中无 API Key。
