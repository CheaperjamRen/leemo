# 让 momo 认识你：关系仪式与用户理解设计

- **日期：** 2026-08-05
- **状态：** 已按 `docs/specs/02-已定决策清单.md` I4-I7 定案并实现；2026-08-05 加厚用户理解地图
- **范围：** 搭子态关系仪式、用户理解覆盖地图、确认与记忆写入；不重做底层记忆库

## 一、结论

“让 momo 认识你”不是注册问卷、人格测试或一次性资料卡。它是一段可跳过、可随时回来继续的真实对话，帮助用户一次性把大量零散背景、偏好和合作方式交代清楚，再由 momo 整理成一份可确认、可修改、会随时间更新的理解。

流程必须同时做到四件事：

1. **足够快地有用**：第一次聊三到五个高价值问题，就能明显改善后续相处和做事方式；
2. **足够深和全面**：用户愿意继续时，有覆盖生活、人格、目标、习惯、价值观和人机协作的完整地图；
3. **不像填表**：一次只问一个问题，顺着用户真正关心的内容追问，不展示完成度或缺项清单；
4. **不污染记忆**：先整份确认，再把少量、耐久、可复用的结论写进现有治理账本。

## 二、产品形态

- 复用一段普通的全局搭子对话，不创建第二套聊天协议、画像数据库或独立人格。
- 模型连接成功后可轻邀请一次；搭子态始终保留“认识我”入口。
- 用户关闭邀请只是暂时不聊，不等于关闭记忆或永久完成。
- 用户再次进入时，先读取 momo 已有的认识，从变化、冲突或空白处继续，不从姓名重新问起。
- 用户可以直接碎碎念、回答引导问题、粘贴文字或附上简历等材料。材料只是理解线索，不整份写进长期记忆。
- 认识流程可以随时停下。普通聊天和普通任务仍然可用，不把用户锁在流程里。

## 三、四种自然开场

首次进入时只问“你想从哪里开始”，提供轻量选项并始终允许自由输入：

| 开场 | 适合谁 | 第一轮目标 |
|---|---|---|
| 最近的我 | 希望快速进入状态 | 当前阶段、最近重点、眼前压力 |
| 怎么和我配合 | 想立刻改善 Agent 手感 | 关系定位、表达方式、主动程度、权限边界 |
| 我随便说，你来整理 | 思路跳跃或不喜欢答题 | 接住碎片叙述，归纳线索，只追问一个关键空白 |
| 从一份资料认识我 | 已有简历、自述、日记或作品 | 区分原文事实与 momo 推断，再追问材料无法回答的部分 |

重复进入时不再展示首次开场，优先问用户想更新“最近状态”“目标计划”“相处与做事方式”“生活与性格”还是继续自由聊。

## 四、由浅入深的层次

### 4.1 第一层：先能相处

目标是在三到五轮内建立最小有用画像：

- 希望 momo 怎么称呼自己；
- 当前主要身份和人生阶段；
- 最近最重要的一两件事；
- 希望 momo 更像朋友、搭档、学长学姐还是导师；
- 哪种回答或做事方式最有帮助，哪种最烦。

这一层完成后，即使用户停止，momo 也应已经能改变称呼、语气、重点和协作方式。

### 4.2 第二层：一起把事做好

围绕真实任务逐步理解：

- 目标、成功标准、截止时间和现实约束；
- 计划、执行、拖延、注意力和精力节奏；
- 学习、阅读、写作、表达和修改习惯；
- 做决定时需要事实、直觉、讨论还是反方挑战；
- 希望 momo 多主动，什么时候先做、什么时候先问；
- 对成本、速度、质量、隐私和权限的取舍。

这一层不必在关系仪式里一次问完。后续真实协作中出现明确反馈，也应继续更新。

### 4.3 第三层：更像认识一个人

只有用户愿意深入时才进入：

- 人格自我理解、MBTI 风味、典型优势和容易卡住的地方；
- 看重的价值、对成功和好生活的理解；
- 偏理性、感性、唯物、玄学或开放探索的世界观倾向；
- 兴趣、食物、城市、旅行、媒体、审美和日常仪式；
- 重要关系、支持系统、边界和不想被触碰的话题；
- 对现在仍有影响的重要经历、转折和愿望。

这不是诊断。MBTI、星座等只能作为用户喜欢的自我描述语言，不能替代具体行为和用户当下反馈。

## 五、完整覆盖地图

覆盖地图只供 momo 选择下一条高价值问题，不向用户展示为完成清单。

| 主题 | 可以理解什么 | 记忆类型 | 时间处理 |
|---|---|---|---|
| 称呼与基本身份 | 姓名或昵称、称谓、语言、愿意公开的身份标签 | profile | 高稳定，可纠正 |
| 人生阶段 | 年龄或年龄段（可跳过）、年级、专业、求学/求职/工作状态 | state/profile | 当前状态必须带时间 |
| 地理与环境 | 当前城市、家乡、常见活动地点、是否准备搬迁 | state | 区分“现在住”和“来自” |
| 当前焦点 | 最近在做什么、最占心力的事情、眼前压力 | state | 短期，过期后不当现在时 |
| 目标与成功标准 | 近期目标、中长期方向、什么算做成 | goal | 记录起点，完成或变化后更新 |
| 现实约束 | 时间、预算、设备、资源、家庭或学校限制 | state/goal | 只保存仍会影响后续的约束 |
| 人格与自我理解 | MBTI、自述特质、优势、盲点、被误解之处 | profile | 自我描述，不做诊断 |
| 关系定位 | 把 momo 当朋友、搭档、学长学姐或导师 | preference | 高稳定，可按场景变化 |
| 沟通与反馈 | 先结论还是先共情、篇幅、语气、挑战程度、禁忌表达 | preference | 记录可执行的偏好 |
| 工作态度与执行 | 对质量、速度、责任和截止的取舍；拆解颗粒度、提醒频率、拖延触发、完成感来源 | preference/state | 区分长期习惯与当前状态 |
| 注意力与精力 | 高效时段、切换倾向、压力下的降级方式 | preference/state | 不作医疗判断 |
| 学习与理解 | 喜欢例子、类比、推导、测验、复述或视觉解释 | preference | 记录能改变教学方式的结论 |
| 写作与表达 | 常见读者、语气、结构、长度、改写边界、常用格式 | preference | 按工作/私人场景区分 |
| 决策方式 | 重视数据还是直觉、需要几个方案、风险容忍、是否要反方 | preference | 不把一次选择泛化为人格 |
| 人机协作 | 先做后报、先问再做、进度回执、工具使用、完全访问边界 | preference | 只存用户明确确认的规则 |
| 价值与世界观 | 重要价值、唯物/玄学倾向、对意义和成功的看法 | preference/profile | 可跳过；不用标签替代原话 |
| 生活纹理 | 食物、兴趣、运动、游戏、音乐、影视、城市与旅行偏好 | preference | 只存以后真的会用到的偏好 |
| 社交与关系 | 重要人物、社交能量、支持方式、关系边界 | profile/episode | 人名和关系信息谨慎、按需保存 |
| 重要经历 | 仍影响当下的转折、成就、挫折和关键决定 | episode | 保留事件时间，不存流水账 |
| 隐私与雷区 | 不愿回答、不要主动提及、不要长期保存的主题 | preference | 优先级高，明确可删除 |

### 5.1 可执行的 29 维理解地图

上表是产品层的摘要。随 `meet-momo` 分发的
`references/user-understanding-map.md` 进一步预制为 29 个可执行主题，每个主题都包含：

- 这项信息为什么会改变后续帮助；
- 适合第一次聊的浅问；
- 用户愿意深入时的深问；
- 哪些内容可以成为长期记忆候选；
- 哪些结论不能从这条信息推出。

29 个主题分为三组：

1. **生活坐标**：称呼与语言、身份阶段、城市环境、求学求职与工作、当前焦点、目标、现实限制和关系定位；
2. **个人工作模型**：沟通、反馈与反对、决策、工作态度与执行、注意力、提醒、学习、写作、审美、工具习惯和人机协作；
3. **真实的人**：人格自述、动机、价值、世界观与玄学态度、兴趣和食物、身体节奏、关系支持、重要经历、未来自我和记忆边界。

这是一张后台选择地图，不是 29 道题。完整意味着“momo 知道还有哪些角度可以理解用户”，不意味着“用户必须把每一格填满”。模型每轮仍只选择一个能立即提高相处或执行质量的问题。

### 5.2 四种信息不能混在一起

| 信息身份 | 例子 | 处理 |
|---|---|---|
| 明确事实或偏好 | “我现在在东京”“先给结论” | 可以进入整份确认稿 |
| 用户自我描述 | “我是 ENTP”“我三分钟热度” | 保留为用户语言，不升级为诊断 |
| 行为与材料线索 | 多次临近截止启动、一篇文章很长 | 先形成观察，再问用户是否认可 |
| momo 推测 | “你可能害怕失败” | 单独标出，确认前不持久化 |

这项区分是认识流程最重要的质量门槛。简历和旧资料还要额外带材料日期：过去的年龄、城市、学校和职业目标不能静默变成当前事实。

### 5.3 深度来自追问层次，不来自问题数量

同一主题按“开放入口 -> 具体情境 -> 取舍对比 -> 行为例子 -> 边界例外 -> 时间更新”逐步深入。例如用户说自己是 ENTP，momo 不继续做人格测试，而是根据当前任务追问一个可行动的问题：用户更常卡在启动前，还是做一半被新想法带走；希望 momo 如何帮其守住主线。

两分钟快速认识只需形成最小可用画像；实用型认识重点理解做事方式；深度认识才进入价值、世界观、关系和重要经历。碎碎念与材料输入都走同一理解地图，但不要求用户先整理。

### 不主动收集

- 密码、API Key、身份证号、精确住址、银行卡、账户恢复信息；
- 与后续帮助无关的医疗、财务、政治、宗教、性与家庭隐私；
- 从照片、简历或文字中推断出的敏感身份；
- 用户只是举例、引用他人或讨论虚构人物时出现的信息。

用户主动谈到敏感经历时，可以正常陪伴和帮助，但“能聊”不等于“要永久记住”。只有用户明确要求、后续确实有价值且现有安全过滤允许时才保存。

## 六、提问策略

每轮根据以下顺序选择一个问题：

1. 用户刚刚表达的真实关切；
2. 能直接改善后续相处或任务质量的空白；
3. 近期容易变化、需要更新的信息；
4. 当前理解中的冲突或不确定处；
5. 更深但敏感度更高的主题。

具体约束：

- 一次只问一个主问题；最多带一个澄清点。
- 选项用于降低回答门槛，不用于限制答案；始终接受自由补充和“跳过”。
- 用户说了一大段时，先用一两句话接住和重述，再问最能推进理解的一点。
- 不为了覆盖率追问用户不感兴趣的主题，不显示“还差 37%”。
- 不重复已有答案。若新旧信息冲突，说明 momo 记得的旧版本并问现在以哪个为准。
- 每获得三到五个高价值信息点就到一个自然停靠点：可以先整理，也可以继续聊。
- 避免连续使用“为什么”。优先问具体情境，例如“你最喜欢我上次哪种处理方式”。

## 七、整份理解与确认

整理时只展示有内容的段落，不输出空字段或数据库表格。推荐结构：

1. **你现在的生活坐标**：身份、阶段、当前重点和目标；
2. **你在意的东西**：价值、兴趣、生活纹理和重要关系；
3. **我会怎样和你相处、一起做事**：关系定位、沟通、计划、学习和权限偏好；
4. **我目前的理解**：明确标出仍属于 momo 推断、需要确认的少量内容。

最后只做一次整体选择：

- 就按这份理解记住；
- 我想改一改；
- 先留在这段对话里，不写长期记忆。

用户确认整体后，仍可在“momo 记得的”中编辑、删除、钉住或查看来源，也可以在任意对话中自然语言纠正。

## 八、写入与上下文预算

- 未确认的推断不进入持久记忆。
- 快速认识一次确认优先写入 8-12 条原子结论，每条只表达一个事实或偏好；深度认识可以保存更多已确认且真正耐久的内容，但不为覆盖率凑数，也不把整份画像散文复制进账本。
- 使用稳定主题更新同一事实，例如 `profile.preferred-name`、`state.current-stage`、`goal.near-term`、`preference.communication`、`preference.ai-collaboration`。
- 姓名、自述人格等放 `profile`；做事、表达、生活喜好放 `preference`；当前城市和求职状态放 `state`；目标放 `goal`；关键转折放 `episode`。
- 当前状态写入 `validFrom`。只知道“现在”时使用本轮日期，不伪造精确起始时间。
- 年龄会变化；若用户只说“我 21 岁”，作为带时间的当前事实，不推算生日。
- 材料原文、长摘要、聊天流水、普通任务和一次性情绪不进入画像。
- 继续遵守全局当前视图 600 tokens 的预算；完整来源、时间和版本只留在账本中，按需查询。

## 九、重复进入、纠正与失败

### 重复进入

先回忆已有画像，再让用户选择更新主题。若用户只想聊一件变化，只更新相关主题，不重新生成整套档案。

### 纠正

用户明确纠正高于旧记忆和 momo 推断。新记录替代旧记录但保留历史有效区间；回答当前问题时只用有效版本。

### 拒绝与停止

“不想说”“跳过”“以后再聊”立即生效，不追问理由，也不把拒绝本身解释成人格特征。用户可直接转去做普通任务。

### 写入失败或记忆关闭

不显示“记住了”，不假装成功。整份理解仍保留在专属对话中，说明目前只留在这里，之后可重试。失败不得复制专属对话。

### 重启恢复

关系对话 ID 和邀请状态持久化。重启后继续原对话；若对话被用户删除，则下次从已有长期记忆创建新对话。

## 十、验收场景

1. 首次快速认识：三到五轮后能形成可用理解并写入少量记忆；
2. 碎片输入：用户连续讲很多，momo 不打断成问卷，能归纳并只追问一个关键点；
3. 材料输入：从简历和文字提取事实候选，推断单独标示，原文不进入记忆；
4. 深度对话：用户愿意时能覆盖人格、世界观、生活纹理和重要经历；
5. 重复进入：读取已有认识，只更新最近状态或指定主题；
6. 冲突更新：从“正在读书”更新到“已经工作”，旧事实不再以现在时使用；
7. 拒绝敏感问题：立即跳过，无追问、无错误画像；
8. 整体不确认：长期记忆不变化，对话内容仍可继续；
9. 写入失败：人话说明、无虚假成功、原对话可重试；
10. 重启恢复：入口回到同一对话，邀请关闭状态不反复弹出。

## 十一、当前明确不做

- 不接入 MindMemOS、向量库、Neo4j、Kafka 或新的常驻服务；
- 不做心理诊断、临床量表或用 MBTI 决定用户的一切；
- 不把认识流程做成独立表单、完成度系统或收集隐私的注册门槛；
- 不做后台付费模型静默整理；
- 遗忘曲线、后台 LLM 整理和语义副索引继续留在长期记忆 TODO，等待真实内测失败触发。

## 十二、研究依据

- [LongMemEval](https://arxiv.org/abs/2410.10813)：长期记忆要同时处理信息提取、跨会话推理、时间推理、知识更新和克制回答；
- [Letta Context Hierarchy](https://docs.letta.com/guides/core-concepts/memory/context-hierarchy)：少量关键事实常驻，大量低频信息外置并按需检索；
- [Generative Agents](https://arxiv.org/abs/2304.03442)：经历记录、反思和动态召回有价值，但不能用自动归纳绕过用户确认；
- [OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq)：可查看的整体摘要、来源、局部纠正、关闭与临时对话是用户控制记忆的重要产品面；
- [MindMemOS](https://github.com/mindscale-noah/MindMemOS)：反馈驱动演化和跨 Agent 复用值得吸收，但当前完整依赖栈不适合 Leemo 的本地 MVP。
- [LaMP](https://aclanthology.org/2024.acl-long.399/)：个性化不是把整份画像塞进每次回答，而是从用户历史中取回与当前任务真正相关的内容；
- [Personalized Response Generation via Generative Split Memory Network](https://aclanthology.org/2021.naacl-main.157/)：把用户明确的画像属性与用户产生的历史内容分开，有助于避免从材料和行为线索直接跳成人格事实；
- [Temporal User Profiling](https://arxiv.org/abs/2508.08454)：短期状态与长期偏好需要分开建模，支持 Leemo 对城市、学校、工作和近期目标使用时间版本；
- [Schwartz basic human values](https://spssi.onlinelibrary.wiley.com/doi/pdf/10.1111/j.1540-4560.1994.tb01196.x)：价值可以从自主、稳定、成就、关系等取舍中理解，但 Leemo 只借鉴提问切面，不对用户做量表评分或理论标签化。
