# 02 · 已定决策清单（宪法，不得重新讨论）

> 汇总自：7/14 三层哲学定版、7/16 CC SDK 引擎决策（与 Opus 4.8）、7/16 前端双模式定版（与 Fable 5）。
> 地位：新会话的最高约束。除非用户本人主动推翻，任何一条都不进入 brainstorming 议程。

## A. 产品定位（7/14 定版，继续有效）

- A1. 产品第一身份 = **通用 Agent 工作台**（对标 Claude Code/Codex/NewMax）；学习是 Harness/Skills/前端皮肤层的 overlay，不是前置定位。
- A2. 三层架构：引擎层（通用 agent，零学习逻辑）→ Harness 层（Lulu 身份卡 + Skills + Modes，用户可选不强制）→ 前端层（通用工作台 UI）。
- A3. 目标用户：中国大学生（大一大二为核心）；产品一句话 = **"像 Claude Code 一样能干的 AI 学习搭子"**。
- A4. 商业化 = **纯 BYOK**。不做鹿卡/内置配额/订阅/付费。
- A5. Lulu = 有灵魂、跨会话不失忆的 AI 搭子（"懂你的 AI 学长/学姐"），人设/说话温度可调。
- A6. 名词预算 = 2：用户可见名词只有「本子」「成果」。Topic/Skill/RAG/Agent 等永不要求用户学习。
- A7. 定位纪律："对话即操作""文件即真相"两原则保留；不做题库/拍照搜题、不做 Notion/Obsidian/Zotero 复刻、不代写规避查重。

## B. 引擎（7/16 定版）

- B1. 底层引擎 = **`@anthropic-ai/claude-agent-sdk`，锁定 0.3.210**（CC CLI 2.1.210 同代）。升级窗口=每月一次，新分支跑评测后才升。
- B2. claude.exe 由 npm 平台分包 `@anthropic-ai/claude-agent-sdk-win32-x64`（~253MB）自动带入；Electron 打包 asarUnpack 该目录。不自己搞二进制。
- B3. 国产模型经 `ANTHROPIC_BASE_URL` 接入。7/16 实测存活端点：DeepSeek `api.deepseek.com/anthropic`、GLM `open.bigmodel.cn/api/anthropic`、Kimi `api.moonshot.cn/anthropic`、通义 dashscope claude-code-proxy。**DeepSeek 为默认推荐**（学生获取 key 门槛最低）。
- B4. 需设模型别名映射：`ANTHROPIC_MODEL` / `ANTHROPIC_DEFAULT_SONNET_MODEL` / `ANTHROPIC_DEFAULT_HAIKU_MODEL` / `CLAUDE_CODE_SUBAGENT_MODEL`。
- B5. 权限策略基线 `permissionMode: 'acceptEdits'` + `canUseTool` 回调桥接审批 UI。
- B6. Anthropic 合规风险用户已明确不担心（主做中国市场，NewMax 已验证此路）；技术上保留 Harness-agnostic 事件桥抽象即可，**不做双引擎并存**。
- B7. 已核验的技术事实（不必重查）：2.1.181 修复 custom BASE_URL prompt cache；2.1.126 网关 /v1/models 列模型；SDK peerDeps = zod^4 / @anthropic-ai/sdk / @modelcontextprotocol/sdk，Node>=18；近 40 版对第三方网关持续修 bug、无收紧迹象。

## C. 代码基线（7/16 定版）

- C1. **前端全新起盘重写，开新仓库**。不复用 fable5/app 改造。
- C2. 自研引擎（~5400 行）与 fable5/app **原地封存只读**；需要纯 UI 组件（PDF 阅读器、Markdown 渲染经验）时拷出。
- C3. 旧执行手册（08-通用Agent执行手册，E0-E2/F-A~J 任务队列）**整体作废归档**——E1.0 并发等 CC SDK 白送。
- C4. 技术栈锁定：**Electron + React + Vite + TailwindCSS + Zustand**。不用 Tauri。
- C5. 02-前端设计规格-终版 v1.1 **降级为底稿**；新权威 = 待产出的 v2.0（融合双模式 + 用户「我的意见.txt」+ CC SDK 现实），**出稿须用户过目才生效**。

## D. 前端双模式（7/16 定版，用户原创）

- D1. **双模式，显式切换，两套完整界面壳**：搭子模式（类 ColaOS 纯聊天陪伴）⇄ 工作台模式（类 NewMax/Kimi Work 多栏工作台）。
- D2. **铁律：一套共享数据层，两个渲染壳**。对话/记忆/文件/产物/Skills/通知全部打通（对话带 mode 标记但两边可见可续）；壳只分展示密度与语气。任何新功能先落共享 store，壳只做展示。
- D3. 搭子模式 = **全能力轻展示**：不阉割工具能力；工具过程显示一行人话微提示；产出为轻卡片，点击跳工作台打开。
- D4. 记忆 = **复用 CC 分层 memory**：全局 `~/LuckyDeerAI/CLAUDE.md` + `memory/`（Lulu 人格、用户画像、学习进度）+ 本子级 `<本子>/CLAUDE.md`（课程进度、本子内约定）。零自研记忆库。搭子态挂全局层；工作台态 = 全局 + 本子叠加。
- D5. 视觉方向 = **冷工具 + 暖人格**：界面骨架学 Linear 的克制精密（工作台冷灰基调）；Lulu 的温度只通过头像、文案、完成时刻微动效渗出；搭子模式暖色比重更高。
- D6. 双模式进首发：**终态设计、基础实现**——骨架按双模式设计，搭子态首发只做基础版（大留白聊天+记忆），重心仍在工作台闭环。

## E. 首发范围（7/16 定版）

- E1. 首发形态重心 = **对话 + 文件工作台**：对话流、本子（=工作区目录）、文件拖入/@引用、预览区（Markdown + PDF.js 含选区）、多对话并发标签页。
- E2. **弹窗小 wiki 首发带简化版**：预览区选中→"问一下"→小弹窗、独立轻量 query()、强制简短回答；不进主对话历史但写入全局搜索索引。历史与原文超链接绑定回跳 = 二期。
- E3. 首设向导：选 Provider（DeepSeek 默认推荐）→ 输 API Key → 测连通 → 进入。目标 <2 分钟。
- E4. 预置学习 Skills 首发 2-3 个：费曼导师、期末速通先行（`.claude/skills/` 标准格式）。
- E5. CC SDK 事件渲染：工具卡片（统一灰阶）/ 结果卡片 / TodoWrite→计划进度卡 / 子 agent→活动卡 / canUseTool→对话内嵌审批条。
- E6. **不进首发（backlog）**：目标模式（长期放养任务+单次复杂任务工作区）、定时任务、自定义 MCP 学习工具（错题本/kb-search RAG/学习计划）、Bloom 完整动画、全局悬浮球、番茄钟/成就系统、Skills 市场、React Flow 画布。

## F. 流程与分工（沿用）

- F1. **执行者 ≠ 验收者**，铁律。多模型分工：GLM 5.2 = 规格写死的自包含卡；GPT 5.6 Sol = 前端重卡；Opus 4.8 = 高风险执行 + 独立对抗审查（永不审自己的代码）；本会话（设计负责人）= 设计书/任务卡/system prompt 亲写/全部验收。
- F2. 任务卡必须自包含：文件清单 + 禁改清单 + 验收命令，执行者不通读全库。
- F3. 验收只认可复现证据（脚本+结果），typecheck/截图不能收卡。
- F4. 新想法一律先过"通用性检验"（删掉'学习'二字还成立吗？不成立→overlay backlog），不插队当前里程碑。

## G. 里程碑顺序（7/16 定版）

1. **Phase 0 可行性验证（3-5 天）**：SDK 0.3.210 × DeepSeek/GLM/Kimi × 五项验证（流式/工具调用/多轮/子 agent/上下文压缩），产出 `smoke-cc-sdk.mjs` + 报告。PASS 才继续。
2. 新仓库初始化（git init 先行）。
3. 02-前端设计规格 v2.0 重写（含双模式），用户过目定稿。
4. CC SDK Bridge + IPC 契约冻结 → 前端壳并行施工。
5. Lulu system prompt（人格）+ 首发 SKILL.md 初稿。
6. Phase 1 最小产品骨架（2-3 周）→ Phase 2 工作台体验（2-4 周）→ Phase 3 学习特化+打磨（持续，找 5-8 个大学生真实验收）。
