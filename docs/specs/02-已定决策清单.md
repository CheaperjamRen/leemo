# 02 · 已定决策清单（宪法，不得重新讨论）

> 汇总自：7/14 三层哲学定版、7/16 CC SDK 引擎决策（与 Opus 4.8）、7/16 前端双模式定版（与 Fable 5）。
> 地位：新会话的最高约束。除非用户本人主动推翻，任何一条都不进入 brainstorming 议程。

## A. 产品定位（7/14 定版，继续有效）

- A1. 产品第一身份 = **通用 Agent 工作台**（对标 Claude Code/Codex/NewMax）；学习是 Harness/Skills/前端皮肤层的 overlay，不是前置定位。
- A2. 三层架构：引擎层（通用 agent，零学习逻辑）→ Harness 层（Lulu 身份卡 + Skills + Modes，用户可选不强制）→ 前端层（通用工作台 UI）。
- A3. 目标用户：中国大学生（大一大二为核心）；产品一句话 = **"像 Claude Code 一样能干的 AI 学习搭子"**。
- A4. 商业化 = **纯 BYOK**。不做鹿卡/内置配额/订阅/付费。
- A5. Lulu = 有灵魂、跨会话不失忆的 AI 搭子（"懂你的 AI 学长/学姐"），人设/说话温度可调。
- A6. 名词预算 = 2：用户可见名词只有「本子」「成果」。Topic/Skill/RAG/Agent 等永不要求用户学习。
- A7. 定位纪律："对话即操作""文件即真相"两原则保留；不做题库/拍照搜题、不做 Notion/Obsidian/Zotero 复刻、不代写规避查重。

## B. 引擎（7/16 定版）

- B1. 底层引擎 = **`@anthropic-ai/claude-agent-sdk`，锁定 0.3.210**（CC CLI 2.1.210 同代）。升级窗口=每月一次，新分支跑评测后才升。
- B2. claude.exe 由 npm 平台分包 `@anthropic-ai/claude-agent-sdk-win32-x64`（~253MB）自动带入；Electron 打包 asarUnpack 该目录。不自己搞二进制。
- B3. 国产模型经 `ANTHROPIC_BASE_URL` 接入。7/16 实测存活端点：DeepSeek `api.deepseek.com/anthropic`、GLM `open.bigmodel.cn/api/anthropic`、Kimi `api.moonshot.cn/anthropic`、通义 dashscope claude-code-proxy。**DeepSeek 为默认推荐**（学生获取 key 门槛最低）。
- B4. 需设模型别名映射：`ANTHROPIC_MODEL` / `ANTHROPIC_DEFAULT_SONNET_MODEL` / `ANTHROPIC_DEFAULT_HAIKU_MODEL` / `CLAUDE_CODE_SUBAGENT_MODEL`。
- B5. 权限策略基线 `permissionMode: 'acceptEdits'` + `canUseTool` 回调桥接审批 UI。
- B6. Anthropic 合规风险用户已明确不担心（主做中国市场，NewMax 已验证此路）；技术上保留 Harness-agnostic 事件桥抽象即可，**不做双引擎并存**。
- B7. 已核验的技术事实（不必重查）：2.1.181 修复 custom BASE_URL prompt cache；2.1.126 网关 /v1/models 列模型；SDK peerDeps = zod^4 / @anthropic-ai/sdk / @modelcontextprotocol/sdk，Node>=18；近 40 版对第三方网关持续修 bug、无收紧迹象。

- C2. 自研引擎（~5400 行）与 fable5/app **原地封存只读**；需要纯 UI 组件（PDF 阅读器、Markdown 渲染经验）时拷出。

## D. 前端双模式（7/16 定版，用户原创）

- D1. **双模式，显式切换，两套完整界面壳**：搭子模式（类 ColaOS 纯聊天陪伴）⇄ 工作台模式（类 NewMax/Kimi Work 多栏工作台）。
- D2. **铁律：一套共享数据层，两个渲染壳**。对话/记忆/文件/产物/Skills/通知全部打通（对话带 mode 标记但两边可见可续）；壳只分展示密度与语气。任何新功能先落共享 store，壳只做展示。
- D3. 搭子模式 = **全能力轻展示**：不阉割工具能力；工具过程显示一行人话微提示；产出为轻卡片，点击跳工作台打开。
- D4. 记忆 = **复用 CC 分层 memory**：全局 `~/LuckyDeerAI/CLAUDE.md` + `memory/`（Lulu 人格、用户画像、学习进度）+ 本子级 `<本子>/CLAUDE.md`（课程进度、本子内约定）。零自研记忆库。搭子态挂全局层；工作台态 = 全局 + 本子叠加。
- D5. 视觉方向 = **冷工具 + 暖人格**：界面骨架学 Linear 的克制精密（工作台冷灰基调）；Lulu 的温度只通过头像、文案、完成时刻微动效渗出；搭子模式暖色比重更高。
- D6. 双模式进首发：**终态设计、基础实现**——骨架按双模式设计，搭子态首发只做基础版（大留白聊天+记忆），重心仍在工作台闭环。

## E. 首发范围（7/16 定版）

- E1. 首发形态重心 = **对话 + 文件工作台**：对话流、本子（=工作区目录）、文件拖入/@引用、预览区（Markdown + PDF.js 含选区）、多对话并发标签页。
- E2. **弹窗小 wiki 首发带简化版**：预览区选中→"问一下"→小弹窗、独立轻量 query()、强制简短回答；不进主对话历史但写入全局搜索索引。历史与原文超链接绑定回跳 = 二期。
- E3. 首设向导：选 Provider（DeepSeek 默认推荐）→ 输 API Key → 测连通 → 进入。目标 <2 分钟。
- E4. 预置学习 Skills 首发 2-3 个：费曼导师、期末速通先行（`.claude/skills/` 标准格式）。
- E5. CC SDK 事件渲染：工具卡片（统一灰阶）/ 结果卡片 / TodoWrite→计划进度卡 / 子 agent→活动卡 / canUseTool→对话内嵌审批条。
- E6. **不进首发（backlog）**：目标模式（长期放养任务+单次复杂任务工作区）、定时任务、自定义 MCP 学习工具（错题本/kb-search RAG/学习计划）、Bloom 完整动画、全局悬浮球、番茄钟/成就系统、Skills 市场、React Flow 画布。

## F. 流程与分工（沿用）

- F1. **执行者 ≠ 验收者**，铁律。多模型分工：GLM 5.2 = 规格写死的自包含卡；GPT 5.6 Sol = 前端重卡；Opus 4.8 = 高风险执行 + 独立对抗审查（永不审自己的代码）；本会话（设计负责人）= 设计书/任务卡/system prompt 亲写/全部验收。
- F2. 任务卡必须自包含：文件清单 + 禁改清单 + 验收命令，执行者不通读全库。
- F3. 验收只认可复现证据（脚本+结果），typecheck/截图不能收卡。
- F4. 新想法一律先过"通用性检验"（删掉'学习'二字还成立吗？不成立→overlay backlog），不插队当前里程碑。

## G. 里程碑顺序（7/16 定版）

1. **Phase 0 可行性验证（3-5 天）**：SDK 0.3.210 × DeepSeek/GLM/Kimi × 五项验证（流式/工具调用/多轮/子 agent/上下文压缩），产出 `smoke-cc-sdk.mjs` + 报告。PASS 才继续。

## H. 用户口径补充（2026-07-29，冲突时覆盖旧表述）

> 本节记录用户在 r7 接手时亲自补充的产品判断。它不是开发 agent 的推测；如与
> 上述早期范围或其他 agent 的 PRD 理解冲突，以本节和用户后续原话为准。

- H1. **通用 Agent 能力平齐是地基，不是差异化可替代项。** Leemo 要先对齐 WorkBuddy、ChatGPT/Codex 等桌面通用 Agent 和 local-first 本地工作台；Claude Code 原生已有且好用的能力（完整 tools、subagent、browser/chrome MCP、自定义 MCP、coding agent 等）在产品里一项都不能无故缺席或假接线。
- H2. **学习与求职特化叠在通用地基之上。** 差异化来自为学生的学习、科研和求职场景预装并产品化好用的 MCP、Skills、工作流和专属功能，而不是用“垂直”解释通用能力落后。
- H3. **momo 有主见，但不甩脸色。** momo 可以提出明确评价、指出代价、给更靠谱的建议；但不得曲解、说教或拒绝用户交付的合法任务。意见说清后仍要帮用户完成。只有真实安全边界、权限不足或技术上做不到时，才如实说明限制并给可行替代路径。
- H4. **双壳不是 Kimi 的 Chat / Work 复刻。** 工作台态是显式、密集、可控的通用 Agent 执行面；搭子态借鉴 ColaOS，更接近长期情感陪伴、聊天、共同思考和决策参考，是“回到一个认识我的人”，不是“功能少一点的任务聊天框”。
- H5. **同一个 momo、同一套完整能力，两种关系与透明度。** 搭子态需要温度、连续关系、可信记忆和轻过程；当用户要做事时仍能无缝调用完整 Agent 能力。工作台态提高结构、控制、并发和过程可见度。任何能力不得只因处于搭子态而消失。
- H6. **竞品功能默认进入候选池，不以“看起来无关”草率排除。** 用户对 NewMax、Kimi 等成熟产品的功能和界面有明确兴趣与野心。是否吸收要结合最初产品设计、目标人群、真实场景、功能冲突和维护成本判断；冲突时做取舍和排序，不把愿景直接删掉。NewMax/Kimi 的工程成熟度、信息架构和交互结果值得认真借鉴，但不能覆盖搭子态的关系型心智。
- H7. **产品判断优先问用户，技术判断由开发负责。** 涉及目标用户心智、功能边界、场景取舍或会改变产品方向的选择，尽量向用户确认；实现路径、技术选型和工程最佳实践由开发 agent 辩证判断，不要求用户替技术方案背书。
- H8. **验收必须走用户路径。** “代码存在”“零件单测通过”或用写死路径的脚本不能等同于产品打通；必须从用户可见入口完成操作，证明结果、状态、失败反馈和重启恢复都成立。
- H9. **能力底线不等于市场正面竞争。** 用户不打算以有限资源和 Kimi、WorkBuddy 抢通用办公 Agent 市场，也不打算在 NewMax 已走很远的通用工作台上逐项军备竞赛。正确策略是尽量复用 Claude Code 原生成熟能力，快速补齐会导致用户流失的通用底线；对各家优秀功能和交互做选择性吸收、重组与取舍，把主要产品投入放在搭子关系、学习/求职特化、本子资产和目标用户场景上。H1 的“平齐”指可信能力底座，不能被解释为复制所有竞品表层功能。
- H10. **“基于 Claude Code”必须在用户路径上成立。** Skills、MCP/自定义 MCP、subagent、原生 tools、计划/Todo、上下文压缩、权限、停止与恢复等白送能力都要复用并真正打通，不得只留 SDK 依赖或后端代码。模型私有原始 CoT 不直接暴露；用可审查的计划、工具轨迹、进度和阶段总结满足透明度。SDK 明确返回给产品的过程文字可以由用户按需展开，但必须位于结论和工具轨迹之后的第二层轻折叠，不能冒充或推断模型未返回的私有思维链。NewMax 的行为、架构和交互可深度逆向借鉴；未确认开放许可证的专有代码不逐段复制，采用独立实现，确认可复用许可证的部分才按许可证使用。
- H11. **安装与启动等待也是产品功能。** 用户不能接受安装包解压数分钟；开发阶段避免无意义的小文件和重复依赖，发布前必须测安装包体积、归档内文件数、安装/解压耗时、冷启动与基础内存。先保证核心路径，不为理论纯洁重写架构；但会让用户在安装门口流失的性能问题必须在成品验收前解决。
- H12. **设置采用独立信息架构，不回到侧栏抽屉。** 首选 NewMax 式中型居中弹窗（当前基线 1040×720），必要时可演进为 Codex 式全屏设置；内部固定为左侧分类导航、右侧单页内容，并提供搜索。模型、通用、个性化、连接器、权限等分类应让任何设置在两步内找到。

## I. 通用工作台与关系体验定案（2026-08-02，覆盖旧心智）

> 本节逐项记录用户对通用 Agent 基线产品访谈的回答。底层工程名可以继续使用
> workspace/notebook/cwd，但不得反向要求用户理解这些实现概念。

- I1. **用户只理解“本子”这一种工作范围。** 新建 Leemo 管理目录与挂载已有文件夹只是本子的两种来源；底层均把本子根目录作为 Agent 的 `cwd`。全局 momo 不属于本子；默认工作区只是无本子任务的物理落盘兜底，不进入本子列表、不拥有独立人格或记忆范围。未进入本子时，工作台标题使用“Leemo 工作台”，不展示“默认工作区”。
- I2. **一个本子直接包含多段对话，首版不增加任意嵌套的对话文件夹。** 先把新建、搜索、置顶、重命名、归档、删除、移动与重启恢复做完整；层级不是成熟感的替代品。
- I3. **十分钟价值感不是单选。** 用户应同时感到“不懂终端也能操作真实文件夹”“momo 真的越来越懂我”“一个软件替代多个 AI 工具”；竞争目标是在关系与人性化上超过 WorkBuddy/Kimi、在可靠执行上超过 ColaOS，并形成各自维度上的明确优势。
- I4. **“和 momo 认识一下”是可跳过的关系仪式，也必须有常驻明显入口。** 模型连接成功后轻邀请一次，第一次有价值对话后可自然提醒一次；用户之后可以随时主动重新进入，不把它做成只出现一次的首启问卷。
- I5. **用户可见个性化以 MBTI 风味与关系定位为主。** 可选 ENTP/INFJ 等风味，以及朋友/搭档/学长/导师等关系；直接程度、挑战程度、主动程度等行为参数不要求普通用户配置，由 momo 根据持续反馈在受治理的记忆中自适应，并允许用户随时纠正。
- I6. **认识流程结束时先确认整份理解，之后可细改。** 用户一次确认整体“momo 对我的理解”，并可随时针对某一条或某一段主动编辑、删除或纠正，避免逐条审批把关系仪式变成填表。
- I7. **事实与推断必须在数据层严格区分，在界面层轻量表达。** momo 内部保存来源与置信边界；呈现给用户的是一份连贯的整体理解，只用少量段落标记、文字颜色或短标签区分“你说过的”和“momo 的理解”，不展示枯燥的元数据表。
- I8. **电脑操作默认采用任务级连续授权，关键最终动作再询问；另提供“完全访问”。** 普通浏览、输入与连续步骤不逐项弹卡，发送、发布、删除、购买等不可逆或对外动作单独确认；用户可明确开启一次都不询问的完全访问模式，并能随时退出。
- I9. **首版可视化回答先做好安全的原生载体。** 表格、流程、时间线、对比卡和图表足够进入通用基线；模型生成可交互小应用后置。底层需预留可扩展的载体协议与受控运行边界，“AI 原生画布”作为独立架构研究与后续创新方向，不在当前通用主路径未完成时插队。
- I10. **双壳方向成立，但现有视觉不达标。** 工作台保持安静专业、搭子态保持温暖有关系感，并共享字体、颜色、间距与动效体系；现状仍像工程作品，后续视觉总改版必须以成熟 Agent 的真实界面和多视口截图验收，不能只换圆角与颜色。
- I11. **第一批内测同时覆盖普通学生与 Agent 重度用户。** 两类人分别验证上手门槛与能力下限；产品目标不是 Claude Code/Codex 的简化 GUI，而是让非程序用户也能使用完整能力、让重度用户没有降级感的上位替代。
- I12. **真实多 Agent 协作是远期重要能力，近期先增强 subagent 的可信可见性。** 终态应支持独立上下文、精细分工、Agent 间通信、并行执行、主 Agent 综合与分歧保留，可借鉴 Kimi Agent 集群、WorkBuddy 专家团及 Hermes/pi 的编排思路；不能用多个头像或动画冒充隔离上下文。当前先研究紧凑的 subagent 状态、角色、进度和可展开过程，但不得抢在会话管理、文件审阅撤销与预览编辑等通用主路径之前。
- I13. **本子与对话的默认路径保持直接。** 用户点进本子后回到该本子上次使用的对话；主入口统一叫“新对话”，不把“任务”再造为并列内容类型。
- I14. **subagent 默认是一条紧凑、可展开的协作状态。** 例如“调研助手 · 核对章节结构 · 已完成”，默认不铺满多张 Agent 卡；第一次展开查看角色、任务、产出和工具轨迹，SDK 明确返回的过程文字再放进“已思考约 xx 秒”第二层折叠。旧会话缺少父级状态时根据已保存的子步骤和明确产出兼容推断，不把完成记录误写成仍在运行。
- I15. **多 Agent 既可自动召集，也可由用户显式控制。** momo 可根据复杂度自动拆分并并行委派；输入区允许用户只对本轮关闭助手，运行时必须结构性移除助手工具，失败重试保持原选择，任务被接受后下一轮恢复自动。未来再提供主动“召集专家团”和真实多 Agent 编排；momo 保持固定关系身份，其他专家按任务动态生成角色，不伪造一组长期人格。
- I16. **专家分歧轻量保留。** momo 给出综合结论时标注存在的重要分歧，用户展开后可看各方理由；不吞掉少数意见，也不把完整内部辩论倾倒进主回答。
- I17. **完全访问是本机持续设置。** 用户明确开启后跨任务、跨重启保持有效，界面始终显示状态并提供一键关闭；开启状态下不再逐项询问。默认任务级连续授权仍按 I8 执行。
- I18. **编程强化自适应显露。** 检测到代码本子时自动出现相关入口，同时允许用户在设置中显式开启或关闭；普通资料与学习本子不被 Git、Worktree、LSP 等术语干扰。
