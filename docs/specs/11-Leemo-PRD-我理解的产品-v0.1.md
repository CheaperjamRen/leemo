# Leemo PRD —— 我理解的产品

> 日期：2026-07-28 ／ 作者：设计与验收负责人 ／ 状态：**待对齐草案**
> 用途：把我脑子里的 Leemo 写出来给你看，验证我们是不是在做同一个产品。
> 它不替代 06（那是已拍板的宪法），它是 06 的**产品侧解读**——为什么这些决策放在
> 一起会长成一个好东西，以及一个真实用户在里面会经历什么。
> **与 06 冲突处以 06 为准，并请指出**：那说明我理解错了，比我写得漂亮更重要。

---

## 〇、一句话

**Leemo 给一个不会用终端的人，配一个会用文件系统的搭子；交付物是长在他自己电脑上的一堆文件夹。**

---

## 一、我们在赌什么

三个赌注。前两个你已经赌赢了，第三个是产品真正的胜负手。

| # | 赌注 | 状态 |
|---|---|---|
| 1 | Claude Agent SDK 能被国产模型驱动，不用 Anthropic 的 key | ✅ 已验证（四家实测） |
| 2 | 协议翻译能保真，OpenAI 端点也进得来 | ✅ 已验证（网关 live 5/5） |
| 3 | **「工作区」这个开发者心智，能翻译成一个大二学生一眼就懂的东西** | ⬜ 没开始 |

赌注 3 就是**本子**。它成立，Leemo 是个新品类；不成立，Leemo 就是个套壳聊天框。

**为什么是新品类：**

- **ChatGPT 的资产是对话** —— 在别人云上，散成一条条记录，一学期下来什么也没沉淀。
- **Cursor / Claude Code 的资产是仓库** —— 但它要求你先懂工作区、终端、git、diff。
  大二学生不懂，也**不该被要求**懂。
- **Leemo 的资产是用户电脑上真实长出来的文件夹。** 一学期后他打开 `~/Leemo`，
  看到 `高等数学/` `数据结构/` `毕设/`，里面是 momo 陪他做出来的笔记、错题本、
  总结、简历。**他会想备份这个文件夹。他哪天不用 Leemo 了，东西也带得走。**

「文件即真相」不是技术选择，是**产品承诺**：我们不绑架你的东西。这条承诺，恰好也是
我们打不过 ChatGPT 的地方唯一能赢的地方 —— 我们不需要他信任我们的云，只需要他信任
自己的硬盘。

## 二、用户是谁

不写画像，写一个人。

> **小林**，大二，普通一本，非计算机专业。装过 ChatGPT，但只会用来问作业答案。
> 听说过 Cursor，打开看见命令行就关了。电脑 `下载/` 里有 47 个 PDF，
> 名字全是 `第三章(1).pdf`。期末周前一晚会通宵。
> 他不会说"我需要一个 Agent"，他会说"有没有什么东西能帮我把这堆玩意儿理一理"。

小林的三个真实时刻，就是产品的三根柱子：

1. **凌晨两点，一个人。** 他需要有个东西在。→ **搭子态**存在的理由
2. **下载文件夹里 47 个 PDF。** 他需要有人帮他分门别类。→ **本子**存在的理由
3. **两周后他忘了上次整理到哪。** 他需要对方记得。→ **记忆分层**存在的理由

**我们不是在做工具，我们在做"有人陪着把事做完"。** momo 的人格权重高不是为了卖萌 ——
小林凌晨两点需要的不是一个更快的搜索框。

## 三、用户可见的名词只有两个

| 名词 | 用户以为它是 | 它其实是 |
|---|---|---|
| **本子** | 一门课 / 一个项目 | 电脑上一个真文件夹 |
| **成果** | momo 帮我做出来的东西 | 那些文件夹里的文件 |

**永不出现在界面上的词**：工作区、会话、Session、Agent、Topic、RAG、上下文、
cwd、仓库、索引、沙箱。（Token 只在用量脚注出现，MCP 只在设置页深层出现。）

这不是文案洁癖，是定位纪律：**每多一个要学的词，小林就多一次关窗口的机会。**

> 本文后面为了跟你讨论架构会用"工作区"这个词。**它是我们的内部语言，永不外泄到界面。**

## 四、工作区模型 —— 你这轮纠正的那件事

你说得对，我上一轮的方案是错的。

我提议"cwd 统一改成 `~/Leemo` 根"，等于把整个 Leemo 当成**一个**工作区。而你要的是
**Leemo 统筹管理多个工作区**，每个本子就是其中一个 —— 这才是和 IDE / CLI 相通的模型，
也才让「本子」这个名词真正配得上它的位置。

差别不是技术细节，是**产品定位差别**：

- 我的版本：Leemo 是一个有文件功能的聊天软件。本子是它内部的分类标签。
- 你的版本：**Leemo 是你所有学习/项目文件夹的统一入口**，momo 是那个能进任何一个
  文件夹帮你干活的人。本子是**第一等公民**，不是标签。

第二个才撑得起「个人 AI OS 的起点」这句话。

### 4.1 目录形态

```
~/Leemo/                        ← 默认工作区 = momo 主人格的家
├── CLAUDE.md                   ← 长期记忆索引（每次对话都加载）
├── memory/                     ← profile / preferences / progress / moments
│   └── …
├── Inbox/                      ← 认不出归属的文件的落脚点
├── .leemo/                     ← 主人格对话的记录（隐藏）
│
├── 高等数学/                    ← 一个本子 = 一个文件夹 = 一个工作区
│   ├── CLAUDE.md               ← 这门课的约定与进度（本子级记忆）
│   ├── .leemo/                 ← 这个本子自己的对话记录
│   ├── 第五章笔记.md
│   └── 讲义.pdf
│
└── 毕设/                        ← 另一个本子，另一个工作区
    ├── CLAUDE.md
    ├── .leemo/
    └── …
```

### 4.2 五条规则

1. **cwd 是每对话一个，绑在它所属的本子上。** 在「高等数学」本子里开的对话，
   momo 的 cwd 就是 `~/Leemo/高等数学/`。它说"我写好了 第五章笔记.md"，
   那就是这个文件夹里的那个文件。**momo 说的路径和你看到的路径永远是同一个。**
2. **主人格对话的 cwd = `~/Leemo/` 根。** 所以它天然能看见所有本子（都是它的子目录），
   能跨本子搬东西、能回答"我这学期都攒了啥"。**根是它的视野，本子是它的工位。**
3. **文件夹就是本子本身，没有第二份元数据。** 用户在资源管理器里改名 → 本子改名；
   删掉 → 本子消失。永不产生孤儿元数据。（这是轮 3 卡 G 已经定的，我完全同意）
4. **对话记录落在它所属的文件夹里**（`<本子>/.leemo/`）。于是一个本子是**自包含**的：
   拷到 U 盘带走，笔记和"当时怎么聊出来的"一起走。SQLite 降级为**可重建的索引**
   （给搜索用），文件夹才是真相。
5. **没有沙箱。** 默认工作区就是 `~/Leemo` 根。旧 sandbox 里的东西迁进来当一个本子。
   —— 防乱写的闸是审批条，不是目录隔离。

### 4.3 由此自然长出来的两个东西（我想加进 backlog）

- **挂载外部文件夹为本子。** 小林电脑上早就有 `D:\大学\高数\`。让他把这个文件夹
  挂进来当本子，比让他把文件搬进 `~/Leemo` 现实得多。
  **这条让 Leemo 从"又一个要我搬家的软件"变成"管我已有东西的软件"**，
  我认为是本子模型最大的杠杆。
- **本子模板。** 新建本子时选"课程 / 项目 / 求职"，预置好目录结构与本子级 CLAUDE.md。
  二期求职工作台（06 §一）其实就是一个本子模板，不需要新做一个"工作台"。

## 五、双模式：同一个人，两种在场方式

我理解的双模式不是"简单版 / 专业版"，而是**同一个 momo 的两种在场方式**。

| | 搭子态 | 工作台态 |
|---|---|---|
| 隐喻 | 跟朋友坐着说话 | 站在朋友的桌子旁看他干活 |
| 你看见 | **他的脸和他的话** | **他的桌面**（本子、文件、成果、过程） |
| 过程 | 一行人话（"翻了翻你的高数课件…"） | 完整工具卡、计划卡、可展开 |
| 布局 | 单栏 720px 居中，大留白 | 侧栏 + 对话 + 按需预览/文件树 |
| 底色 | 暖白 | 冷灰 |
| 能力 | **完全一样** | 完全一样 |

**关键：能力不降级，只有透明度不同。** "搭子态不能做 X"是违宪的（02 §2.1）。

两态之间唯一的教育机制：聊出重活时 momo 自己说"这个去工作台看着我干更清楚 →"。
不做教程气泡、不做引导蒙层。**产品自己要会说话。**

**默认进搭子态**，因为第一印象必须是"我认识了一个人"，而不是"我打开了一个软件"。

## 六、四条主路径（这才是产品，不是功能清单）

### 路径 1 · 第一次打开 → 2 分钟内聊上第一句

```
选一家模型（DeepSeek 推荐 · 带"去哪申请 key"图文引导）
  → 贴 key → 一键测连通（报错说人话）
  → momo 露脸，说第一句话
  → 顺手预置一个示例本子「📘 例：高等数学」（含示例文件，可删）
```

**唯一的成功判据：2 分钟内他跟 momo 说上了第一句话。** 任何一步卡住 = 产品死在门口。
（这就是 06 §3.5「Provider 配置不能有任何卡点」的真正含义 —— 那是漏斗的全部。）

### 路径 2 · 47 个 PDF → 三个本子

```
小林把 12 个 PDF 拖进窗口
  → momo："这些看着像高数的讲义？给你建个「高等数学」本子放一起？"
  → 点「好」
  → 文件夹真的建好了，文件真的进去了，文件树里看得见，资源管理器里也看得见
```

**这一刻是产品的核心时刻**：他第一次意识到"这东西真的在动我的文件，而且我看得见"。

判据：**momo 说建好了，他就能在资源管理器里找到。** 一次对不上，信任就没了。
（这正是今天最严重的那个 bug —— 文件写进了他永远看不见的 sandbox。）

### 路径 3 · 期末周 → 一份真的能用的复习材料

```
进「高等数学」本子 → "帮我把这五章笔记整理成一份复习提纲，重点标出来"
  → 计划卡：4 步
  → 读文件 → 写文件（审批条就地出现，点一次）
  → 成果卡："📄 复习提纲.md · 覆盖 5 章 · 来源：你的 5 份笔记"
  → 点开 → 预览区打开 → 选中一段 → "问一下" → 小窗追问
```

判据：**他打印出来带进考场。**

### 路径 4 · 两周后回来 → 它记得

```
打开 Leemo
  → momo："上次把《数据结构》第五章整完了，第六章还空着。今天接着？"
```

判据：**他觉得被记住了。** 这是复访率的全部来源，也是 momo 与"一个聊天框"的全部区别。

## 七、什么叫"做好了"—— 可判定的验收线

不是功能清单，是**用户能不能走通**。每条都能一次实测判 PASS/FAIL。

| # | 判据 | 今天 |
|---|---|---|
| 1 | 全新电脑 → 2 分钟内跟 momo 说上第一句话 | ⬜ 首设向导未实测 |
| 2 | momo 说"写好了"，用户在资源管理器里找得到 | ❌ **写进 sandbox** |
| 3 | 拖 12 个文件进去 → 三个本子建好、文件到位 | ⚠️ 逻辑在，被 #2 拖累 |
| 4 | 任何设置项 ≤2 步找到（搜索或分区导航） | ❌ **3.2 屏盲滚不可搜** |
| 5 | 改任何设置 → 当前对话立刻生效；重启还在 | ❌ **不生效 + 不落盘** |
| 6 | 联网搜索开了就能搜 | ❌ **三重死锁** |
| 7 | 点本子 → 立刻看见它的东西 | ❌ **只变高亮** |
| 8 | 任何时候能停下正在跑的活 | ❌ **等审批时停止键消失** |
| 9 | 屏幕上没有一处假数据 | ❌ **假作业提醒 / 1970 时间戳** |
| 10 | 每个能点的地方都有可见后果 | ❌ **本子、部分死控件** |
| 11 | 关掉再打开，回到原来的地方 | ⚠️ 对话在，设置全丢 |
| 12 | 一学期后 `~/Leemo` 值得备份 | ⬜ 取决于 1-11 |

**1-11 全绿之前，任何纯视觉工作都是给残缺的东西上妆。**
（第 12 条不是我们做出来的，是用户用出来的 —— 但 1-11 决定他有没有机会用到那天。）

## 八、不做什么

- ❌ 题库 / 拍照搜题 / 查重规避（06 已定，我完全同意：那是作弊工具的生意）
- ❌ 云端存用户文件（我们唯一的信任优势就是"东西在你自己电脑上"）
- ❌ 自研 Agent 引擎（CC SDK 就是护城河，重写是自杀）
- ❌ 卖 token（纯 BYOK。用户自己的 key、自己的额度、自己的账）
- ❌ 逐版跟随 SDK（锁 0.3.210，月度升级窗口）
- ❌ 让用户学新词（名词预算=2）

## 九、和三个参照物的关系

| | 它强在 | 我们为什么不一样 |
|---|---|---|
| **ChatGPT** | 模型强、人人都有 | 它的资产在它云上；**我们的资产在你硬盘上** |
| **Cursor / CC** | Agent 能力顶级 | 它要求你懂工作区/终端/git；**我们把这些藏进「本子」** |
| **NewMax** | 成熟、迭代 30+ 轮、设置 42 个可搜索分区、完整设计系统（30 组件） | 它是**通用 Agent 桌面**；我们是**有人格的、面向学生的、以文件夹为资产的搭子**。它的工程成熟度我们要抄；它的定位我们不抄 |

**对 NewMax 我的判断**：它已经证明了这条路（CC SDK + 多 provider + 桌面壳）能做成产品。
它比我们强的是**完成度**，不是想法。所以它是我们最好的工程参照 ——
**抄它的成熟度，不抄它的定位。** 我们赌的是「本子 + momo」，那是它没有的。

## 十、我认为最容易做错的三件事

1. **把本子做成标签而不是工作区。** 那样 06 里所有"文件即真相"的设计都会失去支点，
   Leemo 退化成有文件夹功能的聊天软件。（我上一轮就差点这么干，你拦住了）
2. **把 momo 做成有主见的人而不是靠谱的人。** 今天它已经会拒绝用户任务并讲道理了。
   陪伴感的来源是**被理解**，不是被指导。
3. **在路径断着的时候先做视觉。** 会得到一个"看起来很好但一用就卡"的东西 ——
   那比看起来简陋更劝退，因为期待被拉高了。

## 附：我要你验证的六个判断

如果哪条不对，说明我理解偏了，请直接打回：

1. Leemo 的资产是**用户电脑上的文件夹**，不是对话记录。
2. **本子 = 工作区 = 真文件夹**，是第一等公民；对话记录落在它里面。
3. momo 主人格住在 `~/Leemo` 根，视野覆盖所有本子。
4. 双模式是**同一个人的两种在场方式**，能力完全对等。
5. 产品的胜负手是**赌注 3（本子这个心智翻译）**，不是模型能力。
6. **"能走通" 优先于 "好看"**，但界面上任何让人走不通/误解产品是什么的东西，
   都算"走不通"，不算"不好看"。
