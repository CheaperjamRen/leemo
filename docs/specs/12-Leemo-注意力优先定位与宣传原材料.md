# 12 · Leemo 注意力优先定位与宣传原材料

> 状态：2026-08-19 用户确认；用于 README、官网、简历项目介绍与后续用户访谈。
> 本文是产品定位素材，不替代工程规格。

## 一句话

**把零散想法留住，把真实工作接着做下去。**

Leemo 是一个本地优先的个人工作台。用户可以继续用熟悉的文档、便签、Todo、本子和文件工作；Leemo 在背后保存来源、关联和进展，只有用户主动需要时才把当前对象交给 momo 或工作台。

## 差异化不是功能清单

Leemo 不与 Office、Notion、滴答清单逐项竞争，也不把“每个页面都有 AI”当作 AI Native。真正的差异化来自三段连续体验：

1. **静态工具可以独立使用。** 记录、写作、整理、查看、归档和 Todo 管理不要求用户和模型对话。
2. **工作连续性不依赖聊天记录。** 文档、Todo、会话、成果与来源通过稳定 ID 关联；用户随时能知道自己正在做什么、做到哪里、下一步是什么。
3. **AI 由用户主动交接。** 用户从对象、选区或明确动作进入搭子或工作台；原始手写内容保持可读，修改、成果和任务回执可追溯、可撤销。

## 面向用户能说什么

- 本地优先的文档、便签、Todo 与文件工作台。
- 不需要学习终端，也能让 Agent 操作真实文件和完成任务。
- 静态记录与 Agent 工作在同一个应用中连续衔接。
- momo 认识用户，但只在用户发消息或明确操作时调用模型。
- 成果、来源、任务过程和待办保持可回看。

## 暂时不能夸大什么

- 不宣称替代 Office、Notion、滴答清单或 Windows Explorer。
- 不宣称所有文档格式都能原样编辑。
- 不把代码存在、组件单测或一次截图写成“全链路已完成”。
- 未完成对象级交接与撤销闭环前，不宣称“完整认知主权系统”。

## 宣传验证的三个用户旅程

1. Alt+N 记下灵感，零模型调用，之后在本地文档库整理、引用和归档。
2. 从文档中的行动条目创建关联 Todo，原文不变；Todo 能返回来源并由用户决定完成。
3. 选中文档内容后主动进入搭子或工作台；AI 获得精确对象上下文，结果以可点击成果和安静回执返回。

三条旅程都通过真实安装包、重启恢复和失败状态验收后，产品定位才从“好故事”变成可宣传的产品事实。
