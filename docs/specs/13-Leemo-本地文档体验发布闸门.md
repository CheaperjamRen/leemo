# 13 · Leemo 本地文档体验发布闸门

> 状态：用户已选择 A 方案并确认持续推进。
> 视觉权威：`docs/design-audition/visual-redesign/start-static-workspace/design.md`
> 产品语义：`docs/superpowers/specs/2026-08-18-start-note-library-design.md`

## 1. 目标

在不更换编辑器框架、不重做已获认可的 Explorer、不扩张为 Office/Notion 克隆的前提下，把“我的文档”收口为可靠、可恢复、对象可编辑、视觉成熟的本地云文档工作面。

## 2. 用户文案合同

用户界面只说明：对象是什么、当前状态、操作结果、真实成本、风险和恢复办法。

必须删除：

- “不会自动叫醒 AI”“不会自动调用模型”等设计原则自述；
- “下一张工程卡接入”等开发进度文案；
- “momo 不会替你……”等在常规操作中预设用户误解的解释；
- 不能操作的占位入口与自嗨式产品宣言。

必须保留：

- 会产生模型费用的明确动作说明；
- “原文保留”“仅引用原文件 / 已保存副本”等数据语义；
- 删除、覆盖、冲突、失效路径和恢复办法。

## 3. 写作可靠性

- 编辑后立即写入本机恢复缓冲；恢复缓冲不是第二正文真源，只在保存成功前保护草稿。
- 停止输入约 800ms 后自动保存到现有便签真源；`Ctrl+S` 与保存按钮立即刷新。
- 成功后清除对应恢复缓冲；失败时原文和缓冲都保留。
- 切换文档、离开页面、关闭或意外退出后，未完成保存不得静默丢失。
- 基础 revision 已变化时不自动覆盖；展示“内容在别处更新”，允许重新载入或复制本地草稿。
- 保存状态只在文档头显示一处：`未保存 / 正在保存 / 已保存 / 保存失败`。

## 4. 编辑器能力与交互

- 默认“编辑”为所见即所得；“源码”继续是同一 Markdown 的显式逃生舱。
- 工具栏不以机械的“6–8 个”或“排满”为目标。宽屏直接呈现段落/标题、粗斜体、三类列表、引用、便签引用、链接、表格、公式和撤销/重做；代码块、高亮、Callout、Mermaid 进入单列“更多”。
- 窄屏按真实空间逐级把链接、表格和公式收进“更多”，但按钮仍保持同一 28–30px 比例，不拉宽、不放大填空，也不留下暗示能力贫乏的大段失衡留白。
- 工具栏反映光标所在格式的激活状态。
- `@便签`、引用按钮和从树拖入正文必须插入当前光标/拖放位置，不得追加到文末。
- 表格保留直接编辑，并达到文档表格的发布基线：
  - 单元格即时编辑；`Tab`/`Shift+Tab` 前后移动，末格 `Tab` 新增一行；
  - 点击行头/列头选择整行或整列，`Shift` 扩展连续选区；结构操作以当前选区为锚点，而不是只在末尾增删；
  - 支持在选区上下/左右插入、删除选中行列、单列对齐、恢复等宽、清空与复制选区；
  - 从表格软件粘贴 TSV 时从当前单元格开始填充并按需扩表；复制多格时输出 TSV；
  - 拖拽列边界实时预览宽度，松手后一次写回；自定义宽度通过可移植且默认不可见的 `leemo-table` Markdown 注释持久化；
  - 输入采用短延迟合并写回，拖拽不逐像素序列化整篇文档；撤销、保存、源码往返和重启后宽度不得丢失。
- GFM 不表达合并单元格、公式计算、筛选和复杂块级单元格；本轮不伪装支持这些 Excel 能力，也不为此破坏 Markdown 可移植性。
- 从文档创建 Todo 只读取用户选中的清单/文本，不扫描整篇 Markdown 生成噪声候选。

## 5. 文件、引用与派生对象

- 附件行支持：Leemo 预览、默认应用打开、资源管理器定位、移除。
- 路径失效时显示文件已移动或删除；不得打开 localhost、应用首页或伪网页。
- 外部引用与托管副本继续显示真实存储语义；永久删除之前不清理托管文件，外部原文件永不删除。
- 反向引用、附件和关联 Todo 位于正文之后，使用细分隔和紧凑行；无内容时不保留大块空区域。
- 置顶、最近、收集箱、归档、回收站必须投影同一批真实便签；尚未实现的“位置”入口要么接通最小真实路径，要么暂时隐藏，不能留死页。

## 6. 响应式与视觉

- 保留当前 72px Start 图标轨、248/224px Explorer 和大画布比例。
- 1440px 正文画布约 960–1040px；普通段落内部控制可读行长，表格/代码/图表可以占满。
- `<820px` Explorer 为可开关覆盖层，支持 Escape、遮罩关闭和焦点返回；关闭后正文占满。
- 低频结构不做厚卡；格式工具、表格工具和附件操作使用 hairline、轻背景与 30–32px 控件。
- 饱和 Leemo 橙只用于当前导航轨迹、唯一主动作、焦点和必要的状态强调；Callout 不形成大面积橙色块。
- hover、pressed、focus-visible 和 reduced-motion 都必须有实机证据。

## 7. 失败与恢复层级

借鉴 NewMax 的成熟原则而不复制其配色与 AI-first 心智：

- 失败不抹掉旧内容；
- 一句话说明发生了什么；
- 恢复动作在原位置；
- 技术详情默认折叠；
- 文件成果显示可点击路径、大小和打开/定位动作。

## 8. 发布验收矩阵

真实 Electron 必须覆盖：

1. 空文档、新建、长文与碎片便签；
2. 富文本与源码多轮切换后内容一致；
3. 标题、强调、列表、清单、引用、链接、代码、公式、Mermaid、Callout、表格；表格需实测行列选择、按选区增删、Tab 导航、TSV 粘贴/复制、列宽拖拽、源码往返和重启恢复；
4. 自动保存、立即保存、保存失败、revision 冲突、重启恢复；
5. 光标位置插入引用、反向引用与重命名/移动后稳定；
6. 图片托管、普通文件仅引用、普通文件保存副本；
7. 打开、预览、默认应用、资源管理器定位和路径失效；
8. 从选中内容创建关联 Todo，原文不变；
9. 归档、回收站、恢复和永久删除的真实边界；
10. 1440×900、960×680、760×680；
11. hover、focus、popover、拖拽、长文 sticky 工具栏；
12. 全程意外模型调用为零，renderer console error 为零。

完成标准：Kimi K3 必须真实读取最终截图并给出逐图证明；独立视觉/UX 审计无 P1，综合评分至少 90，目标 90–95。
