# 产品素材与能力候选

这里保存开发者主动收集的帖子、项目、Skill 和方法论。它们是 Leemo 的产品输入，不是用户记忆、运行时知识库或在线 Skill 市场。

## 为什么单独放

- 原始素材与产品结论分开，避免只凭一张截图直接堆功能。
- 每项都记录用户痛点、可复用原则、接入边界、风险和状态，后续可统一检索与取材。
- 截图只进入开发仓库；`electron-builder.yml` 的发布白名单不包含 `docs/`，不会增大用户安装包。
- 这里不是真源。真正进入开发后，需求写回台账，代码经过用户路径验收；外部项目仍以各自审计文档为准。

## 收录格式

每份输入至少回答：

1. 来源是什么，是否能核验原链接和许可证。
2. 它解决的是真实用户问题，还是只有概念吸引力。
3. Leemo 应吸收原则、改造后吸收，还是明确不吸收。
4. 应落在哪一层：Skill、工具、定时任务、记忆、成果组件或产品界面。
5. 哪些数据是真源，如何避免重复提醒、记忆污染和上下文膨胀。
6. 最小用户路径如何验收。

状态统一为：`待评审`、`已评审`、`候选`、`已排期`、`已交付`、`观察`、`不采用`。

## 后续收素材

新素材先放这里，不直接塞进 `bundled-skills/`。完成来源审计和产品翻译后，才决定是否做成内置 Skill、静态下载候选或产品能力。这样既保留灵感，也不让发散输入持续打断当前主线。
