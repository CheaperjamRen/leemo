## 帖子真正有价值的部分

帖子用“ENTP 模型很强、Harness 不够”描述一种常见困境：用户并非不会思考，而是分类、提醒、排序、追踪和收尾长期占用脑内空间。它提出六个外置环节：

1. **Context Router**：新想法先分类进入不同队列，不让每个念头都抢占当前主线。
2. **Scheduler**：一天只保留少量关键锚点，其余事情不持续侵入注意力。
3. **Tool Calling**：把提醒、记录、排序、追踪交给日历和 Todo，而不是靠工作记忆硬扛。
4. **Output Schema**：计划必须有下一步、时间和完成判据，不能停在“学习某事”这类模糊口号。
5. **Guardrails**：根据精力与状态主动降级，低能量也保持最小连续性，不把降级解释成失败。
6. **Evaluator**：用很轻的日终复盘闭环，并在第二天重新呈现关键未完成事项。

这套方法的价值不依赖 MBTI。它更适合描述“想法多、容易切换、执行主线容易丢失”的工作方式，也可能帮助部分自述有 ADHD 式困扰的用户；Leemo 不做医学判断或诊断。

## Leemo 的产品翻译

### 用户心智

候选名称：**稳住主线**。

它不是项目管理系统、打卡监督器或“ENTP 模式”，而是一位不会过度打扰的行动搭子：用户可以继续发散，momo 负责把新想法安全停放，并让今天真正要推进的事情始终可见。

入口应当是可选 Skill，也可从“让 momo 了解你”或个性化设置中开启。首次开启只问一个高信息问题，例如“你最希望 momo 帮你守住哪件事？”；不要求用户填写人格量表。

它面向的不只是认同 ENTP 标签的人，也包括任何自觉容易发散、切换、启动困难或精力波动的用户。产品承诺是“帮我回到自己选定的主线”，不是“替我自律”或“持续提醒我”。

### 展示形态与用户旅程

1. **发现**：在 Skill 管理与“让 momo 了解你”流程中提供清晰入口，用户主动开启；不根据 MBTI 或对话内容偷偷启用。
2. **设定**：momo 通过一次短对话确认当前主线、希望被怎样提醒，以及不希望被怎样打扰；结果先给用户整体确认，不做枯燥表单。
3. **日常**：对话中只显示一条轻量“主线条”，包含当前主线、第一个动作和“停车区 +N”；没有大张旗鼓的打卡卡片。用户不需要进入专门页面才能继续做事。
4. **回访**：早晨、晚间或任务时点均为显式可选，默认零通知；一次回访只围绕当前主线和下一个动作，不因 Todo 变多而提高提醒频率。
5. **回到主线**：用户发散或中断后再回来，momo 先恢复最近真实状态，再给最小可执行动作；不展示“连续天数归零”等惩罚信号。
6. **关闭**：关闭后停止相关编排和回访，普通任务、对话与产物仍保留；用户重新开启时可选择继续旧主线或重新开始。

### 最小版本：先用 Skill 验证

- 接住用户的碎片输入，先复述其意图，再区分 `当前主线 / 今天可做 / 以后再看`。
- 每天最多保留 1 条主线和 3 个行动锚点；不因为用户又想到新事就静默替换主线。
- 每个行动必须包含：最小下一步、建议时段或触发条件、可观察的完成判据。
- 提供 `正常 / 低能量 / 只保连续性` 三档动态执行强度；用户随时可改，momo 也可轻问一次，不自行诊断。
- 日终最多问三个问题：今天推进了什么、哪里卡住、明天第一个动作是什么。允许一句话回答或跳过。
- 新想法进入“停车区”，能找回但不持续弹提醒。

Skill 只负责方法和对话编排，不成为任务真源，也不自行伪造日历能力。

### 第二步：接现有定时任务

- 由用户选择是否开启早晨或晚间回访；默认零通知。
- 通知频率由用户显式选择，不因为待办数量增加而增加。
- 定时任务保存触发时间与 prompt；任务/计划状态由 Leemo 的结构化任务层保存，不写成大段长期记忆。
- 第二天只重新呈现仍有价值的主线和第一个动作，不把全部历史 Todo 重新塞回上下文。

### 后续组件形态

等通用 Agent 基线和原生成果协议稳定后，可在学习看板或成果视图中组合：

- 今日主线；
- 三个行动锚点；
- 日历时间块；
- 想法停车区；
- 本周连续性与可见成果；
- 当前执行强度。

组件是同一份结构化状态的不同呈现，不另建一套任务或记忆真源。先做固定组件，不急着做无限画布。

未来的日历、Todo 与看板组件不是另一套“自律产品”，而是这套执行支架的可视化出口：聊天负责商量和调整，结构化任务层保存状态，组件负责扫读、拖拽和回看。用户无须在聊天与看板之间重复维护同一件事。

## 数据边界

- 长期记忆：只保存相对稳定的偏好，例如用户喜欢少提醒、晨间更有精力、希望 momo 帮忙守主线。
- 本子记忆：保存与某个长期项目相关的目标和上下文。
- 任务层：保存具体行动、状态、时间和完成判据。
- 定时任务：只保存触发规则和执行入口。
- 想法停车区：属于可编辑的用户产物，不进入长期记忆全文。

## 明确不要做

- 不以 MBTI 给用户定型，不因“ENTP/ADHD”推断能力、意志力或医学状态。
- 不用连续打卡、红色逾期和羞耻文案惩罚用户。
- 不默认接管日历，不在未确认时移动用户已有安排。
- 不把每个念头都升级成任务，也不让 momo 以“帮你守主线”为理由拒绝用户的新任务。
- 不用频繁通知制造存在感；帮助的判据是用户更容易回来继续，而不是打开次数更多。

## 最小验收路径

1. 用户一次说出十多个想法，momo 保留全部，但只提出一个当前主线和至多三个今天行动。
2. 用户临时插入新想法，主线不被静默替换；用户明确要求切换时立即服从。
3. 用户说今天状态差，系统缩小动作并保留连续性，不显示失败或归零。
4. 用户跳过晚间复盘，不被追问；第二天仍能从上次真实状态继续。
5. 用户关闭该 Skill 后，不再出现相关编排或提醒，已有普通任务与产物不丢失。
6. 重启后任务状态、用户选择的提醒策略和停车区都能恢复，同时 prompt 不携带全部历史明细。

## 开发顺序

- **通用 Agent 基线后优先验证**：先做高质量 Skill 与结构化输出，不新增大型依赖。
- **有真实连续使用反馈后**：接日历/定时任务和固定组件。
- **明确后做**：完整自律系统、复杂习惯统计、无限画布、自动重排整天日程。
