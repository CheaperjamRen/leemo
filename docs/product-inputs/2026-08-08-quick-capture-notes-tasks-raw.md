## 已确认的最低约束

这里只忠实索引已经明确的部分，不代替后续共同设计：

- `Alt+N` 必须能在用户当前工作现场快速唤起轻量新建便签，不要求先切回 Leemo 主窗口。
- 快速记录既可能是待办，也可能是灵感、思考或普通笔记；产品不能在写入前强迫用户先分类。
- 微型编辑器至少支持加粗、序号、可勾选待办、注释、换行，以及通过 Tab / Shift+Tab（用户原话为 Alt+Tab，需调研后共同确认快捷键冲突）调整列表层级。
- 便签与待办需要独立于 Explorer / 文件预览形成自己的产品入口和视图。
- 后续可把便签全部或部分转为待办，并在工作看板中统一查看、编辑、梳理。
- 长期可以吸收 momo 汇总的未完成工作、按本子归属的进度、成果与提醒，但 MVP 是否纳入、如何避免噪音与错误归属，需要共同定稿。
- 必须优先解决“想到什么时立刻记下，之后容易找到和处理”的完整用户路径，而不是只做一张好看的 Todo 表。

## 下一步调研问题

调研需要覆盖但不限于：OneNote、Apple 备忘录 / 快速备忘录、Microsoft To Do、TickTick / 滴答清单、Things、Notion、Obsidian、Google Keep、Raycast Notes / Quicklinks，以及成熟 Agent 工作台中的任务与上下文收集方式。重点比较：

1. 快速捕获的摩擦、快捷键与弹窗生命周期。
2. “收件箱、便签、待办、本子/项目”之间的边界和转化。
3. 用户不分类时的默认归宿与后续整理成本。
4. 富文本、Markdown、任务数据模型和本地文件之间的可迁移性。
5. 今日视图、看板、时间线、列表和搜索分别服务什么心智。
6. momo 可以自动整理到什么程度，哪些动作必须让用户确认。
7. 全局便签与本子内内容如何建立归属，又不污染记忆和文件工作区。
