## 二十五、输入区附件、工作区拖入与共享草稿（2026-08-02）

- **用户语义**：输入框区域代表“交给这一轮”，因此拖入文件、选择文件和粘贴截图都生成本轮附件；壳层其余区域代表“放进当前工作区”，继续执行导入/本子归类。两条路径互斥，不发生一份文件既发送又复制的双重动作。
- **真实路径**：有操作系统路径的文件直接沿既有附件 Bridge 发送；无路径的系统截图由 Electron 主进程暂存为 PNG 后再发送，不用 blob URL 或假路径欺骗底层工具。
- **资源边界**：单图最大 20MB、像素上限 1600 万；临时缓存最多 64 张、总量 256MB。历史进程文件按 TTL 与最旧优先淘汰，当前进程前缀受保护，避免长时间未发送草稿的附件 chip 仍在而磁盘文件已被删。
- **草稿归属**：文字、附件、暂存中、发送中和错误统一按 `conversation` 或 `workspace` scope 保存；搭子态和工作台共享同一状态。首条发送先创建但不激活对话，成功才进入；失败时该对话仍能映射回原草稿，切换模式/项目不会串任务。
- **确认与回收语义**：新发送在 host acknowledgement 前只租用附件所有权；若即时失败，上一份可重试草稿和临时截图一起恢复；确认接收后才释放被替代的旧截图。附件槽位被并发占满时，已暂存图片会立即回收；成功/中断释放本轮截图，失败保留供用户重试。
- **单轮所有权**：同一对话从恢复 host claim、发送 ACK 到活动轮结束都只允许一个发送者；定时任务或程序化调用不能绕过输入框禁用态并发创建同 ID 会话、覆盖 runId 或错配停止句柄。
- **状态**：Integrated。隔离 Electron 已走过 Windows 系统剪贴板 `Ctrl+V` → 真实 PNG 路径 → chip → 移除并确认文件消失，以及搭子/工作台草稿切换；全量 166 个测试文件、2298 项通过，typecheck、renderer/main build、`git diff --check` 通过。尚未在最终安装包内走粘贴/发送/失败重试/重启清理，因此不是 Release-verified。

## 二十八、Markdown 预览就地编辑与窄窗工作台（2026-08-02）

- **用户路径**：工作台真实 Markdown 预览新增“阅读 / 编辑”切换；编辑态提供加粗、斜体、二级标题、引用、列表与代码工具，支持 `Ctrl+S` 保存。工具栏只表达用户熟悉的格式，不暴露底层编辑协议或 Claude Code 心智。
- **写入边界**：renderer 只能改已经存在、完整读入且不超过 2 MiB 的 `.md/.markdown`；`.leemo`、`.claude` 与 Leemo 主工作区的旧 `memory/` 受保护。外部项目同名 `memory/` 是普通用户目录，不被误拦。相对路径先归一化，再对原生 realpath 的真实目标执行扩展名、内部目录与越界校验；前后空格、指向内部目录或非 Markdown 的工作区内 symlink 都不能伪装目标。
- **不丢稿语义**：保存携带用户开始编辑时的精确正文；若外部程序已改文件，Leemo 不覆盖磁盘，编辑器保留原草稿、显示失败并提供“复制草稿”。真实写盘先在同目录独占创建临时文件、刷盘、二次校验基线和元信息，再保留权限原子替换；磁盘满或暂存失败不会先截断原文件。
- **切换与退出事务**：标签关闭、切换/打开/移除工作区都会询问继续编辑、不保存或保存。异步切换期间编辑器锁定，只有操作成功才清理来源工作区草稿；原生选择器取消、注册失败或切换失败都原样保留标签与草稿。应用退出由 Electron 原生确认框承接，选择继续编辑会取消退出且后台调度不被提前停掉，选择丢弃才关闭；不同工作区的同名相对路径拥有独立草稿。
- **窄窗修复**：“全部文件”改为临时覆盖抽屉，打开文件后自动收起，不再与 420px 预览列同时永久挤压对话。开发 Electron 在 `1024x720` 下实测：抽屉打开时对话列 764px；文件打开后对话列 344px、预览 420px、消息输入 279px，页面横向溢出为 0，编辑器和保存栏完整可见。

- **状态**：Integrated。隔离 Electron 在 `1024x720` 真实走过外部文件夹 → 打开 Markdown → 修改 → 400px 单行操作确认框 → 保存并切换 → 磁盘逐字回读；又走过原生退出确认，选择“继续编辑”后窗口和草稿仍在，随后选择“退出并丢弃修改”才关闭且磁盘未写入该草稿。全量 175 个测试文件、2383/2383，三套 TypeScript typecheck 0 错，renderer/main 构建成功。尚未装入新的最终 NSIS 复验，因此不是 Release-verified。
