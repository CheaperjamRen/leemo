# Leemo r9a 界面可信度验收（2026-07-30）

## 结论

r9a 已把回复、过程、搜索、通知、技能和成果入口从“能渲染”推进到“用户路径可验证”。
本轮没有把截图当成功能证明：每个关键结论同时锚定真实 Electron 操作、DOM 状态和自动化测试。

## 验收环境

- 真 Electron renderer：`http://localhost:5173/`，CDP `9333`
- 视口：`1280x720`、`1440x900`，DPR 1
- 用户数据：现有本地工作区与历史对话，没有注入演示 fixture
- 操作：Computer Use 确认目标窗口，CDP 只执行用户等价的点击、输入、滚动和截图
- 自动化：Vitest、三套 TypeScript 配置、Vite production build

## 真实用户路径

1. 从工作台打开已有对话，确认最终回答中的标题、粗体、列表和 GFM 表格已排版。
2. 展开一轮包含 8 步的“处理过程”，确认一轮只有一张过程收据，展开内容的段落和编号列表已排版。
3. 从“成果”空页面打开全局搜索，输入“成果验收”。
4. 搜索命中真实工作区文件 `预览验收/成果验收.md`，点击结果。
5. 页面自动回到对话工作区，右侧预览显示“成果页通电验收”。
6. 关闭唯一预览标签，确认整个预览列消失，主对话重新占满可用宽度。
7. 分别打开技能与成果页，确认侧栏选中态、顶部上下文标题和可执行空状态动作。

第 3 到 5 步首次复核时发现一个真实断点：在成果页点搜索结果只更新了 `previewOpen`，但
`view` 仍是 `artifacts`，所以用户看不到预览。新增失败测试后，文件、成果和 Wiki 结果现在会
先切回 `chat` 再打开预览。这也是“状态单测通过不等于用户路径通过”的直接证据。

## 独立评审与收口

首次独立截图评审没有发现 P0，提出 4 项 P1：

1. 技能/成果入口没有选中态，顶部仍显示旧会话标题，长标题截断不规范。
2. 成果空状态没有下一步，过滤器在无数据时仍占位。
3. 技能空状态的说明与“打开技能目录”相隔一整屏。
4. 搜索路径与筛选文字过淡，且没有明确关闭按钮。

收口结果：

- 技能/成果入口使用 `aria-current="page"` 与明确选中背景；顶部改为当前页面标题。
- 会话标题使用单行省略并保留完整 `title`。
- 成果空状态说明数据来源，并提供真实“回到对话”；无数据时隐藏无意义过滤器。
- 技能图标、说明和真实目录动作组成同一视觉组。
- 搜索补充 40px 关闭按钮，次级文字提升到 `--leemo-ink-2`。
- 关闭最后一个预览标签时同步关闭预览列。
- 从非对话页面点击文件、成果或 Wiki 搜索结果时，自动回到可见预览的工作台。

独立评审使用修复后的截图逐项复核，以上 4 项 P1 均已关闭，没有发现 P0。复审另提出：
展开过程会显示模型原样返回的英文 thinking，观感更像调试日志。这里没有用规则过滤或擅自删除，
因为项目历史中有“思考作为独立过程卡”的明确产品决定，而且当前默认折叠、用户主动展开才显示。
后续应由产品决定默认展示“原始思考”还是“阶段摘要”，再为高级用户保留另一种查看方式。

## 留给 r9b 的真实缺口

成果页在当前进程中只显示 store 已知成果；应用重启后仍会变回 0 项。文件本身没有丢，
丢的是从持久化对话工具记录重建成果索引的步骤。该问题不在 r9a 伪装成已解决，进入 r9b
“成果连续性”切片处理，并以“生成文件 -> 预览 -> 重启 -> 成果仍可打开”作为验收路径。
