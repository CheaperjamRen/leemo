## 2026-08-08 实施事实校正

- 今晚已接入快捷便签、完整便签 / 待办工作台、附件、回收站、提醒、后台常驻与启动设置、`@便签`、momo 自然语言 CRUD、`Ctrl+Enter` 引导、搜索 / 归档、「今天」真实活动与通知点击定位。当前 Windows 解包应用已真实验证 `Alt+N` 写入便签、完整视图读取、带详情 / 截止时间的待办创建及整进程重启恢复；托盘、通知点击与各失败态仍保留各自发布验收边界。
- 复杂日期已采用“本地优先、模型仅兜底歧义”的一次性解析：只发送当前待办或用户选中的便签片段，结果在保存前可编辑；关闭设置、没有当前可用模型或失败时保留原文并手动确认。便签置顶 / 标签 / 分组、看板拖拽等留到真实用户之后。
- 视觉大重构是下一阶段，本轮未开始。

## 一句话结论

Leemo 不该再造一套 Todo App，也不该把所有碎片都交给 AI 自动分类。真正缺失的是 Agent 闭环最前面的低摩擦捕获层：

```text
原始捕获 → 用户确认后的整理 → momo / 用户真实执行 → 成果与状态 → 事实型回顾
```

`Alt+N` 首先要做到“任何念头都能立即、安全、离线地落下”；收件箱、今日、看板和搜索只是同一份真实数据的不同视图，不是四套存储。

## 已确认决策

1. **窗口生命周期选择后台常驻。** 用户关闭主窗口后，Leemo 隐入系统托盘，`Alt+N` 仍然可用；只有从托盘明确选择“退出 Leemo”才真正结束进程。实现与验收必须保证后台不让模型运行时、定时轮询或完整 renderer 无意义空转。
2. **后台常驻属于 Leemo 基础能力。** 主窗口隐藏后，既有 Agent 任务继续运行；任务完成、等待用户确认或失败时发送可点击的系统通知，点击后回到对应会话。隐藏状态不占 Windows 任务栏，托盘菜单提供显示主窗口、快速便签和真正退出。
3. **快速捕获统一进入全局收集箱。** `Alt+N` 不跟随当前本子，也不在捕获时要求选择归属；本子归属、整理与转行动发生在收集之后。
4. **快速窗口提供便签 / 待办两种模式，默认便签。** 便签模式中的复选框只属于便签内部清单，不自动污染正式待办；用户主动切到待办模式时才直接创建正式待办。忘记切模式也没关系，之后仍可选中整条或部分便签转为待办。
5. **后台与启动设置分开。** “关闭窗口后在后台继续运行”默认开启；“开机时自动启动 Leemo”默认关闭。两项都允许用户独立修改，不能把开机自启偷偷绑定到托盘常驻。
6. **从便签转出待办后保留原文。** 原便签只轻量标记“已转出待办”并保留双向来源关系；不剪走原文、不重复询问，也不弹额外确认框。便签负责保存当时的想法与上下文，待办负责后续行动和状态。
7. **“注释”是正文格式，不是 Word 式旁批。** 它与标题、正文、引用、清单并列，用于在便签内部标出备注、重点或提醒；首版不引入评论线程、回复或协作审阅心智。
8. **快速捕获快捷键可自定义。** 默认使用 `Alt+N`，设置中允许录制并修改；占用冲突必须明确提示且保留应用内入口，不能静默失效。修改后即时生效并在整进程重启后保持。
9. **Markdown 富文本编辑是基础能力。** 用户应直接看到标题、正文、注释、加粗、列表和可点击清单的结果，而不是被迫编辑 Markdown 源码；底层仍应保留可复制、可引用、便于交给 AI 使用的 Markdown 语义。
10. **图片持久保存，普通文件默认引用。** 粘贴或拖入的图片进入 Leemo 管理的持久附件区；Word、PDF、代码等普通文件默认记录原路径并显示文件卡片，不复制原文件。设置中另提供“拖入文件时保存副本”模式，开启后将之后拖入的文件统一复制到 Leemo 管理位置，不逐次弹窗。设置切换不追溯修改既有附件。
11. **文件副本用户可见，并与成果分开。** 复制模式把普通文件保存到全局「Leemo 文件存储位置」下的收集箱附件目录，文件卡提供“打开文件”和“打开所在文件夹”。这里保存的是用户带入材料的副本，不算 momo 产物；“成果”继续作为跨默认工作区和各本子的虚拟总览，不新建第二个物理成果目录，也不误收录普通附件副本。早期曾建议固定放入默认工作区，已被后续统一存储规则取代。
12. **快速便签用 `Ctrl+S` 明确收下。** 输入持续自动保存草稿；`Ctrl+S` 把当前非空草稿收进全局收件箱并关闭小窗；`Esc` 或关闭按钮只隐藏，下一次唤起继续编辑；空白草稿不生成记录。`Ctrl+Enter` 不占用于便签保存，保留给对话中的“任务进行时追加引导”。
13. **追加引导必须可降级但不可伪装。** 运行时支持原生 steer 时，把消息送进当前 active turn；暂不支持时仍收下消息、不中断当前任务，明确显示“下一步会采用”，本轮结束后自动开启后续轮次。不能静默丢失，也不能把排队消息冒充为“已加入本轮”。
14. **「概览」是入口，便签与待办拥有完整独立工作面。** 右侧工具栏负责进入这一能力，但不能把它压缩成临时抽屉或聊天附属品。用户需要一个持久、可追溯、可全览的便签 / 待办界面，能够在没有 AI 回复打扰的情况下独立记录、沉思和梳理；AI 原生体现为用户主动召唤时可帮助整理、转化和执行，而不是默认占据工作过程。
15. **完整工作面占据主画布，沉默本身也是能力。** 点击「概览」后，中间主画布切换为工作看板，左侧全局导航与右侧工具栏保留；打开便签时在同一主画布沉浸编辑，聊天界面退出当前工作面。AI 的价值是按需理解并操作这套持久数据，不能用持续回复抢占用户独立思考、记录和规划的空间。独立窗口只作为后续可选能力，不作为首版主路径。
16. **工作看板采用「今天 / 便签 / 待办」三个一级视图。** 快速捕获的内容在「今天」中以收集箱区域呈现，同时进入完整便签库；收集箱代表尚未整理的状态，不另占一个长期一级入口，也不形成第二套存储。
17. **增长型文件不得静默挤占系统盘。** 收集箱副本路径必须在设置中可见、可打开、可自定义；这同时是 Leemo 的全局存储规则，而非单个功能特例。附件、副本、缓存等可能持续增长的内容都应在「文件与存储」中说明位置、占用与可用空间，不能只写入隐藏的 C 盘目录后让用户自行发现。
18. **增长型数据使用一个全局文件存储位置。** 用户只管理一个「Leemo 文件存储位置」，Leemo 在其下按收集箱附件、便签图片、下载缓存等用途建立子目录，并在设置中按类别展示占用。本子继续位于用户选择的真实文件夹；数据库和设置等小型内部数据也不因这条规则被伪装成用户文件。
19. **更改存储位置必须真正迁移已有托管文件。** 设置页在迁移前展示现有数据量与目标可用空间，并显示迁移进度；只有完整迁移成功后才切换新位置并清理旧副本，失败时继续使用原路径且不破坏原文件。不能只改变未来写入位置，留下用户难以理解和清理的历史目录。
20. **「今天」首版有明确层级，后续确定演进为组件画布。** 首版主区域突出「今天要做」，并提供收集箱与继续记录等次级区域；只展示用户真实数据，不自动塞入 AI 总结，也不使用满屏等权卡片。后续必须支持用户拖拽、调整和扩展日历、待办、学习等组件，但不能让未来画布反过来阻塞当前核心路径。
21. **便签库采用轻量整理，不复制 OneNote 层级。** 便签默认可以不分类，并提供全部、收集箱、置顶、最近编辑、已归档等系统视图；用户可选用轻量分组和多个标签，全局搜索始终覆盖全部内容。不能再造一套与真实文件夹「本子」冲突的“笔记本 → 分区 → 页面”概念，也不能要求捕获前先归类。
22. **关联本子不等于偷偷生成文件。** 便签始终保留在全局便签库，可与一个本子建立轻量关联，供检索和上下文使用；只有用户明确选择「转为本子文档」时，才在该真实文件夹中创建 Markdown 文件。转换后保留原便签并建立双向来源链接，不能自动移走、删除或制造用户没预期到的工作区文件。
23. **待办默认轻量，但首次创建即可一次设置完整。** 新建时一句话标题始终是主路径；同一创建界面必须允许用户按需展开并填写日期、截止时间、提醒、重复、优先级、本子关联和说明，再一次保存。不能把“渐进披露”错误实现成“先创建残缺待办，再强迫用户进入待办页二次编辑”。
24. **待办解析本地优先，复杂歧义才使用模型。** 常见且唯一的时间表达先本地解析，并把日期、截止时间和提醒以可编辑结果呈现；出现多个日期、多个时间或角色不明确时，绝不能机械地把第一个时间当作截止时间或提醒。允许使用模型理解复杂结构，但模型解析可在设置中关闭；关闭、无可用模型或解析失败时，完整保留原文并不填写不确定字段。
25. **momo 与界面必须操作同一套待办能力。** 用户可直接告诉 momo 新增、修改、完成或提醒一条待办，momo 通过真实待办服务写入工作看板并注册提醒，不能只在聊天里口头答应或另存一份影子清单。回执保持轻量，解析歧义只在确实影响执行时提问。
26. **待办创建使用一个自适应输入区和可编辑识别标签。** 短内容保持单行，长文本自然扩展；本地或模型识别出的截止时间、提醒、重复、本子关联等都以可见、可编辑、可移除的标签呈现，同时保留可展开的完整手动字段。不能另堆一个“智能粘贴”大框，也不能让解析结果在保存前对用户不可见。
27. **便签转待办支持批量解析。** 用户可从便签中选中多行、列表项或复选项，一次解析为多条独立待办；不能把整段内容合并成一个超长任务。每条生成的待办都保留到原便签及对应来源内容的关系，原便签仍不被删除或剪走。
28. **批量转换先原位预览，再一次创建。** 预览中每条候选待办都可取消选择、修改标题和修正识别标签，也可将日期、本子等共同字段一次应用到全部候选；最终按钮明确显示将创建的数量。预览属于批量拆分的必要校正，不使用笨重弹窗，也不能解析后无提示地直接生成全部任务。
29. **复杂待办的模型解析默认开启，但调用范围必须克制。** 本地解析始终先运行；仅在多个时间、复杂依赖或字段角色不明确时，才调用已配置模型，并只发送当前待办或用户明确选中的便签片段。设置项说明可能消耗少量模型额度并允许关闭；关闭、无模型或失败时完整保留原文，不填写不确定字段，也不发送整份便签库。
30. **删除先进入可恢复的 Leemo 回收站。** 普通删除不弹确认框，可轻量撤销，默认保留 30 天；只有彻底删除与清空回收站需要明确确认。便签拥有的托管附件随记录进入回收站，外部路径引用的原文件永远不由 Leemo 删除。

## 成熟产品反复验证的规律

### 1. 捕获时少做决定

- OneNote 与 Apple Quick Note 都使用特殊的 Quick Notes 容器，关闭小窗不会删除内容，并允许之后再移动。
- Things、Todoist、TickTick 都把 Inbox 定义为未处理事项的临时落点；未指定项目时先进入 Inbox。
- Google Keep 允许笔记默认无标签，标签、颜色和置顶都是捕获后的整理动作。

因此，Leemo 的快速捕获不应先问“这是待办、灵感还是知识？”也不应要求先选本子、日期、标签和优先级。

### 2. Today 是视图，不是存储位置

Microsoft To Do 的 My Day 可以每天重新开始，但未完成任务仍留在原任务列表；Things、Todoist、TickTick 也都是从原对象生成今日视图。Leemo 的“今日”也应只回答“今天推进什么”，不能复制或吞掉原始内容。

### 3. 看板是可选显示方式，不是第二套任务系统

Todoist、Notion、TickTick 的看板都是同一批对象按状态或属性分组。首版不应为了“像工作台”先造通用 Kanban；更有价值的是一个固定、克制的工作视图，集中回答：

- 我刚记了什么；
- 今天要推进什么；
- momo 正在做什么、哪里等我；
- 最近得到什么成果。

### 4. 笔记中的勾选项不等于正式任务

OneNote、Apple Notes、Keep、Obsidian 都允许笔记内存在 checklist；其中部分产品可以另行创建带回链的任务。Leemo 也应区分：

- **便签内复选框**：只是这条便签内部的轻量清单；
- **行动**：用户明确转化后，才进入可归属、可执行、可追踪的任务层。

原文应保留，并记录“已从这里提取行动”，避免复制后失去上下文。

### 5. 富文本与附件应分层，而不是把所有按钮铺开

用户提供的手机便签截图把撤销、清单、格式、语音和“添加”放在固定工具栏；标题、正文、注释、圆点与层级列表收进格式菜单，相册、拍照、涂鸦、表格、文件、扫描和 OCR 再收进“添加”。这说明成熟便签的关键不是功能少，而是捕获时只暴露当前最需要的动作。

Apple Notes 同样支持正文格式、标题层级、清单缩进、图片、PDF、文件拖入、扫描与全文搜索；OneNote 支持富文本、图片、文件副本、链接、列表和表格。值得 Leemo 首版吸收的是：

- 直接粘贴或拖入图片；
- 拖入本地文件后形成可识别的文件引用；
- 标题、正文、注释、加粗、编号、圆点、清单与层级缩进；
- 复制出去时保留清晰 Markdown 语义；
- 之后可通过 `@` 搜索并引用一条或多条便签，而不是复制出互不关联的多份内容。

不应在首版照搬 OneNote 的无限画布、自由文本容器、音视频录制、手写、表格编辑、扫描/OCR 或多人协作。图片需要进入 Leemo 管理的持久附件区；普通文件究竟保存副本还是只引用原路径，需要单独确认，不能由实现层偷偷决定。

官方参考：[Apple Notes 附件与拖放](https://support.apple.com/guide/notes/add-photos-pdfs-and-more-not95edd2813/mac)、[Apple Notes 清单](https://support.apple.com/en-us/102296)、[Apple Notes 格式与快捷键](https://support.apple.com/guide/notes/keyboard-shortcuts-and-gestures-apd46c25187e/mac)、[OneNote 基础编辑与附件](https://support.microsoft.com/en-us/onenote/onenote-help-and-learning/basic-tasks-in-onenote-on-windows)、[OneNote 文件附件](https://support.microsoft.com/en-US/OneNote/onenote-help-and-learning/insert-or-attach-files-to-notes)。

## 对 Leemo 最合适的产品模型

### 单一闭环

```text
Alt+N
  ↓ 不调用 AI、不强制分类
全局收件箱（Capture）
  ↓ 用户主动整理；momo 可以建议，但不擅自改动
保留便签 / 选中部分转行动 / 归入本子 / 稍后提醒
  ↓
用户自行完成，或交给 momo 在对应对话中执行
  ↓
现有运行状态、等待用户、失败、成果成为事实真源
  ↓
工作视图与每日回顾按需聚合，不复制数据
```

### 最少对象

- `Capture`：原始捕获；未转化时本身就是便签。
- `Action`：用户明确转化后才产生；至少包含下一步、完成状态和可选归属。
- `AgentRun`、`Artifact`、`ScheduledTask`：继续复用 Leemo 已有真源。
- Inbox、Today、工作视图、搜索：只做派生查询。

这与 Leemo 已确定的“本子是真实本地文件夹”“全局 momo 不属于单一本子”“不让便签污染长期记忆”“工作台状态来自真实运行与产物”一致。

## 建议的 MVP

### 必须现在做

1. Leemo 运行时，其他应用内也可用 `Alt+N` 唤起轻量小窗；快捷键可修改，冲突或注册失败要说人话。
2. 弹窗立即聚焦多行输入，不先问分类；输入即自动保存。
3. `Esc`、失焦或关闭只隐藏，不丢稿；空白草稿不生成垃圾条目；崩溃和重启后可恢复。
4. 微型编辑能力只覆盖高频需求：正文、加粗、项目符号、有序列表、复选框、换行、`Tab / Shift+Tab` 缩进。
5. 所有未分类内容先进入一个全局收件箱，可搜索、编辑、归档。
6. 可选中整条或部分内容显式“转为行动”；原便签保留并带来源关系。
7. 行动可以保持全局，也可以明确归入某个本子；Leemo 不静默猜归属。
8. 固定工作视图先展示：待整理捕获、今日主线与少量行动、正在执行 / 等你处理、最近成果。
9. Agent 的运行、等待、失败与成果继续来自现有真实事件，不能在看板里维护第二份状态。

### 有连续自用或首批用户后再做

- momo 提议分类、归属、下一步、完成判据，但先让用户确认。
- 从行动创建定时任务；自然语言识别日期；语音捕获。
- 经许可附上当前网页、文件或窗口来源。
- 本子内项目进度视图与可选 Kanban。
- Kimi 式对话生成组件布局，但组件仍读取受控真源。

### 明确不现在做

- 完整复制 OneNote、Notion 或 Obsidian 的编辑器、数据库、目录树和插件系统。
- 无限画布、任意 HTML 小组件、甘特图、复杂依赖和团队协作。
- 捕获时自动 AI 分类，或把每个复选框都升级成正式任务。
- 高频通知、羞耻型逾期墙、自动重排用户全天日程。
- 云端 Inbox、移动端同步或另一套记忆数据库。

## 推荐的弹窗语义

- `Alt+N`：显示并聚焦当前未提交草稿；上一次已收下则新建空白草稿。
- 输入：立即本地自动保存，不调用模型，不消耗额度。
- `Esc` / 关闭：隐藏并保留草稿。
- `Ctrl+S`：收下当前便签并关闭。
- `Tab / Shift+Tab`：调整列表层级；Windows 的 `Alt+Tab` 保留给系统切换窗口。
- 内容为空：关闭时不创建记录。

这组语义优先保证“永不因为关窗或误触丢掉刚才的念头”。

## 调研时的实现基线（已由 2026-08-08 提交推进）

> 以下保留为方案形成时的工程依据，不再代表当前实现状态；当前收口见文首“实施事实校正”。

- `src/main/main.ts` 目前只创建一个主 `BrowserWindow`，没有全局快捷键、托盘或后台常驻；Windows 关闭主窗口会退出进程。因此首版若不改变应用生命周期，`Alt+N` 只能在 Leemo 正在运行时生效。
- 主进程已经拥有 SQLite 与迁移机制，适合保存 Capture / Action 和未提交草稿；不需要新引入数据库，也不应把快速便签写入 memory 或伪装成某个本子里的 Markdown 文件。
- 现有 `MarkdownEditor` 是为文件预览准备的 textarea + Markdown 工具条，可复用格式转换与快捷键思路，但不能直接承担可点击复选框、块级选择和局部转行动；硬塞进去会让文件编辑与快速捕获互相绑死。
- 快捷窗口应使用独立、窄权限的 preload 与 renderer surface；不能在第二个窗口再次挂载完整 `App / BridgeProvider`，否则会重复初始化整套 store 和持久化同步，也会把 AI、工作区等无关权限暴露给小窗。
- 快捷窗口和主窗口的 renderer 状态并不共享，保存后应由主进程广播变更，两个界面都从同一个主进程 Admin / SQLite 真源读取。
- 工作台右侧“文件 / 概览 / 搜索”是当前本子或对话范围的工具栏，而全局收件箱跨本子存在。两者不能无解释地合并；入口和全局 / 当前本子视图关系需要用户共同决定。
- 现有定时任务、运行状态、产物和每日回顾可以作为下游事实真源；新的行动层只补普通用户任务，不复制这些已有对象。

因此最小工程路径应是：一个懒创建且重复复用的独立轻量窗口 + 现有主进程 SQLite 中分开的 `captures / user_tasks` + 单一 CaptureAdmin + 独立快速编辑组件 + 窄 IPC；不要安装完整知识库框架，也不要借机重写工作台壳层。先把可见便签与待办闭环接到同一 Admin，再在同一首版里让 momo 和 `@`引用复用这套真实服务，不能把自然语言管理长期留成口头承诺。

## 调研时的相邻通用 Agent 缺口：任务进行时追加引导

> 当前 `Ctrl+Enter` 引导与不支持原生 steer 时的自动续轮降级已接入源码；最终安装包用户路径仍待验收。以下保留为实现前的问题依据。

这不是快速便签的数据模型，但用户明确要求在视觉大重构前保留为通用 Agent 核心能力，不能被便签快捷键占位：

- 当前 Leemo 在运行中把发送按钮替换为“停止”，`InputArea` 禁止提交，conversation store 和 Bridge pool 也拒绝同一对话的第二次 `send`；因此当前只有“等待完成”或“中断”两种选择，没有 Codex 式的“继续执行，同时吸收我的新想法”。
- 本机 Codex app-server `0.147.0` 的生成协议包含原生 `turn/steer`，并以 `expectedTurnId` 防止把引导误送进另一轮。
- 当前随项目安装的 Claude Agent SDK 暴露 `Query.streamInput()`，但 Leemo 的 adapter 把 `Query` 收窄成普通 `AsyncIterable`，且初始输入流立即结束，所以该能力尚未接入。
- Gemini ACP 当前适配层只有 `prompt` 与 `cancel`，尚未证明支持真正的同轮引导。产品不能把“排到下一轮”伪装成“已加入当前任务”。

推荐产品语义是把三种动作彻底分开：`追加引导` 不取消当前执行；`停止` 明确中断；普通新消息在空闲时开启下一轮。支持原生引导的运行时应送入同一 active turn；不支持时应透明显示为“下一步采用”并保证排队，而不是虚假回执或静默丢失。具体快捷键、按钮和降级文案需另卡定稿，不与快速便签实现混在一起。

## 已完成的逐题确认记录

以下问题均已在正式规格中定案；保留清单仅用于追溯调研时的决策范围：

1. Alt+N 是否只要求 Leemo 已运行时可用，还是必须支持完全退出后的冷启动。
2. 快速捕获默认进入全局收件箱，还是默认跟随当前本子。
3. 便签内复选框和正式行动的边界。
4. 从便签转出行动后，原文保留、移动或只留引用。
5. 工作视图第一屏的四个信息区及优先级。
6. momo 可以自动做哪些整理，哪些必须确认。
7. 普通行动与 Agent 行动分别如何判定完成。
8. 归入本子后的物理存储与全局可检索方式。
9. 用户所说“注释”是提示 / 引用块，还是 Word 式行内评论。
10. 快捷键、保存、隐藏与重新唤起的具体语义。
11. 是否默认零通知，以及何时提供主动提醒。
12. 捕获阶段完全不调用 AI，整理阶段再调用 momo，用户是否接受。
