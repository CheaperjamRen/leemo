# 浏览器 Workflow 录制调研与 Leemo 路线

日期：2026-08-28

## 结论

Leemo 当前浏览器地基已经覆盖真实网页任务需要的基本执行链：独立持久浏览器身份、当前 Chrome 复用、页面快照、点击、输入、截图、人工接管、最终动作确认与失败恢复。NewMax 的教学录制补充了一层可复用流程：用户演示一次，系统保存语义步骤和变量，后续优先确定性回放，失败位置再交给模型续跑。

当前版本先完成现有浏览器链的打包验收。Workflow 录制进入下一阶段的场景特化，优先服务查课表、查分、检索论文、重复资料整理等用户能反复受益的流程。

## NewMax 已公开的机制

依据 [NewMax 浏览器自动化说明](https://newmax.cc/docs/features/browser) 与 [v1.0.280 更新日志](https://newmax.cc/docs/changelog/v1-0-280)：

- 录制运行在内置浏览器中，实时生成“点击按钮”“输入关键词”一类语义步骤。
- 用户可以把会变化的输入标记为变量；保存时模型也会辅助识别变量和精简步骤。
- 密码、验证码、银行卡等敏感字段不保存原文。
- Workflow 绑定浏览器身份，回放时沿用对应登录状态。
- 回放优先执行保存步骤，通常只在参数询问、步骤整理或失败续跑时使用模型。
- 失败后保留当前页面状态，允许人工接管或模型从断点继续。
- 多标签普通网页任务不会自动转换成线性 Workflow，降低错误标签回放的风险。

## Leemo 当前能力

| 能力 | 当前状态 | 证据入口 |
| --- | --- | --- |
| 独立持久浏览器身份 | 已有 | `src/main/mcp-runtime.ts` |
| 当前 Chrome 登录态复用 | 已有 | `src/renderer/components/BrowserAutomationSection.tsx` |
| 页面读取、点击、输入、截图 | 已有 | `@playwright/mcp` 与打包浏览器验收脚本 |
| 浏览器截图回显 | 已有 | `BrowserCapturePreview` |
| 人工接管与最终动作确认 | 已有 | 浏览器旅程验收脚本与权限分类 |
| 教学录制 | 待补 | 当前没有录制状态、步骤采集与保存协议 |
| 变量化 Workflow | 待补 | 当前没有 Workflow 数据模型与参数面板 |
| 确定性回放与断点续跑 | 待补 | 当前每轮由 Agent 调用浏览器工具 |
| Workflow 成功率与维护 | 待补 | 当前没有运行记录和信度模型 |

## 推荐的数据边界

一条可保存的步骤至少包含：

- 页面来源：站点域名、可选路径模式、浏览器身份标识。
- 动作：导航、点击、输入、选择、按键、等待、读取、断言、粘贴。
- 定位：无障碍角色与名称、稳定属性、附近文本关系；坐标仅作为当次运行的末级回退。
- 参数：名称、类型、默认值策略、是否敏感；敏感值由执行时提供且不落盘。
- 结果：成功条件、失败位置、页面快照摘要与可恢复状态。
- 版本：Schema 版本、站点版本提示、最近成功时间和连续失败次数。

## 分阶段实现

### 当前版本必须完成

- 在正式包中验收独立浏览器与当前 Chrome 两条路径。
- 验收登录/验证码人工接管、最终提交确认、停止、失败恢复和截图回显。
- 保持现有权限语义：读取与普通交互顺畅执行，上传、脚本、远端提交等敏感动作明确确认。

### 有真实重复场景后实现

1. 先记录 Leemo 自己执行过的浏览器工具调用，允许用户把成功任务保存为 Workflow。
2. 加入变量编辑、敏感字段清除、语义定位与执行结果断言。
3. 回放器逐步执行并保存断点；定位失败时停在原页面，用户可接管或让 Agent 修复步骤。
4. 为查课表、查分、知网检索、招聘信息整理各做一条真实验收流程。

### 后续再评估

- 用户全程手动演示的教学录制。
- 多账号 Profile 管理界面。
- 后台无头回放、排期执行与通知。
- 跨站多标签编排和自动修复。

这部分会显著扩大权限、凭据、浏览器生命周期和恢复状态的维护面，适合在核心 Agent 与长对话已经稳定、至少出现一个高频重复场景后继续投入。
