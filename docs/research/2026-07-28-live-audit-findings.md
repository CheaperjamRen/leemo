## A. 用户抱怨①「写文件还写不了」= 工作区分裂（Critical）

**实测链条（一次性口令 WTMS4L1GU9 锚定这一次输入）**

1. 搭子态发：「请在工作区里新建文件 `诊断/写文件测试-WTMS4L1GU9.md`」
2. momo 自己推理出的路径：`E:\Leemo\.leemo-workspace\sandbox\诊断\...`
3. 审批条弹出，**挂了 90+ 秒**（见 B）；点「允许一次」后写入成功
4. momo 回「写好了。」
5. **`find C:\Users\Example\Leemo -name "*WT*"` → 空**
6. `find E:\Leemo\.leemo-workspace\sandbox -name "*WT*"` → 命中

**根因**：SDK 的 `cwd` 与用户可见工作区是**两个不同目录**。

| 面 | 路径 | 谁定的 |
|---|---|---|
| momo 的 cwd（写文件落点） | dev `E:\Leemo\.leemo-workspace\sandbox`；打包 `userData\workspace\sandbox` | `main.ts:66 resolveWorkspaceDirs` → `bridge-host.ts:346 cwd: sandboxDir` |
| 用户可见工作区（本子/Inbox/文件树/预览/记忆） | `C:\Users\Example\Leemo` | `main.ts:86 workspaceRootFor(app.getPath("home"))` |

**用户看到的后果**：momo 说「写好了」，但本子里没有、文件树里没有、预览打不开。
成果页确实出现了卡片，标注 **`未分类` + `⚠️ 工作区外`** 并显示裸绝对路径
`E:/Leemo/.leemo-workspace/sandbox/诊断/...` —— 即产品**自己知道**这个文件在工作区外，
却仍然是唯一能看到它的地方。`artifacts.ts bookForPath` 拿 sandbox 绝对路径解不出
bookId，所以永远归「未分类」。

**为什么历史验收没抓到**：轮 4 的成果页验收（`verify-r4-artifacts2.mjs`）在 prompt 里
**直接写死了 `C:\Users\Example\Leemo\预览验收\成果验收.md` 绝对路径**，绕过了这个缺陷。
台账里那句「一物三址在实机对齐」只在"人工喂绝对路径"这个前提下成立。

**momo 的信息是自相矛盾的**：cwd 在 sandbox，而 prompt 层⑥/⑨ 告诉它记忆库和本子在
`C:\Users\Example\Leemo`。它无法知道「工作区」指哪个。

## B. 审批条会把回合挂死，且无超时无退出（Critical）

- `interact.ts:136` `acceptEdits` 是 **RESERVED 未实现**，`:287` 注释明写按 `default` 走
  ⇒ **每一次写文件都弹审批**，默认设置下无一例外。
- 实测：审批条出现后 **90 秒内界面完全静止**，`caret=true`（还在流）、`approvals=2`，
  一直等到我点了「允许一次」才继续。**没有任何超时、倒计时或降级** —— 用户不点就永远等。
- **订正（2026-07-28 复核）**：本条初版写了「**停止键消失了**」，那是**我的探针假阴性**，
  不是产品缺陷。停止键只有 `aria-label="停止"` 没有文字，而我的判据查的是 `textContent`。
  实际 `InputArea.tsx:309` 的条件是 `busy`，而 `busy = activeRunId !== null`
  （`BuddyShell.tsx:109`）—— 等审批时 run 仍活着，所以停止键**在**。
  这正是本项目那条老教训的又一次应验：**判据必须锚到真界面**（交接文档坑 4）。
- 卡片确实渲染在展开的折叠区里（`ProcessFold.tsx:17`，`defaultCollapsed={!active}`），
  位置是对的；问题是**没有任何倒计时/提示/降级**，且停止键在等审批时不可用。
- `Enter` 发送后若审批未处理，回合永久等待（`bridge-host` 的 `approvalWaiters` 只有
  interrupt/teardown 会清）。

## C. 用户抱怨②「联网搜索根本不起效」= 三重死锁（Critical）

三个独立事实叠成一个必然失败：

1. **默认关**。`stores/settings.ts:124` `webEnabled: initial.webEnabled ?? false`；
   两个二级开关实测 `disabled:true` 灰掉。
2. **开了对当前对话无效**。persona context（含 `webSearchEnabled`）只在
   `bridge:createConversation` 时过线（`conversations.ts:171` / `:201`），
   `hostLive.has(id)` 守着 ⇒ 已存在的对话拿不到新值。
   **实测**：设置页开关已 `checked=true`，同一对话里问搜索题，momo 回
   > 「我没办法搜——**这轮对话里我的网络访问是关的**，Search 和 Fetch 都不可用。」
   新开对话再问 → **搜到了真结果**（正确答出诺奖 10/6 公布 + 两个来源链接）。
   ⇒ 能力是好的，**只有"开关后新建的对话"才吃得到**，用户无从得知。
3. **设置不落盘**。SQLite 只有 `conversations/messages/usage/wiki_entries` 四张表
   （`main/persistence/schema.ts`），`persistence/sync.ts` 只订阅
   `conversations` + `wikiEntries` ⇒ **settings store 全字段重启即丢**，回到默认关。

**合起来**：默认关 → 用户翻三屏找到开关打开 → 当前对话仍说"我不能联网" → 用户判定
"坏的" → 重启后开关又回到关。**这是一个用户几乎不可能走通的路径。**

**落盘缺失的连带影响**（同一根因，全部重启即丢）：人设卡、话风档位、权限模式、
默认模型、基调模式、自动记忆开关。只有 Provider key 与搜索源 key 落盘（在加密件里）。

## F. 其它实机抓到的具体 bug

1. **URL 被当成文件路径报警**（每条带链接的回复都会出现）
   `events.ts:176` `PATH_TOKEN_RE` 的 `[A-Za-z]:[\\/]` 分支会匹配 `https:` 里的 **`s:`**。
   实测界面出现：`⚠ 声称写到工作区外：s://www.nobelprize.org/…、s://nerdsip.com/…`
   ⇒ momo 每次给来源链接，用户就看到一条像安全警报的乱码。
2. **搭子态顶栏没有设置入口**。可见按钮只有 历史对话 / 搭子 / 工作台 / 通知；
   「⚙ 设置」只藏在历史抽屉里。（10 号文档 §1.7 明确要求 buddy 顶栏加齿轮）
3. **通知面板时间戳是 `1970/1/1 08:00:00`**，内容是 fixture
   「《数据结构》第五章笔记整理完成」。
4. **搭子态底部常驻假数据**：`BuddyShell.tsx:117` 硬编码
   「周六 23:59 ·《高等数学》第五章作业截止 —— 到时候我提醒你」——今天是周二，
   且没有任何提醒机制。
5. **对话标题取用户首句原文截断**，侧栏显示成
   `请把这一行写进 C:\Users\Example\` —— 无 AI 生成标题、无改名入口可见。
6. **每回合都挂一张「momo 的干活过程 N 步 展开」卡**，一屏能有 8 张同款；
   即使只是闲聊一句也有一张（1 步）。02 §4.3 要求搭子态是"一行人话微提示"，
   现状是工作台态的解剖卡直接搬进了暖白搭子态。
7. **`--leemo-side` token 在搭子态解析为空字符串**（工作台态用 inline 覆盖），
   语义 token 双基调没走通。

## G. 用户抱怨④「本子只是摆设」= 选中无后果

**实测**：工作台侧栏点「预览验收」本子（`title` 是真路径 `C:\Users\Example\Leemo\预览验收`，
数据是真的）→ **唯一可见变化是侧栏那一行变琥珀高亮**。
主区仍是对话；**没有文件列表、没有本子内文件、没有任何范围收窄的视觉反馈**。
要看文件必须再去顶栏点一个单独的文件夹图标把文件树拉出来 —— 两个动作、两处心智。

06 §2.2 与 02 §六的本子语义是「一门课/一个项目的文件夹」，选中它理应就是进入它。
现在选中只是给后续新对话打了个隐形的 `bookId` 标记（`resolveActiveNotebook`），
**这个标记对用户完全不可见**，所以本子看起来什么也不干。

叠加 A 的工作区分裂：momo 新建的 `诊断/` 目录**根本没进本子列表**（它在 sandbox），
于是"让 momo 帮我建个本子/放个文件"这条最自然的路径也是断的。

3. **用量脚注 `↑25.7k ↓502` 常驻**。02 §2.6 明确要求"默认折叠、hover 才显示"。

   ⇒ 看起来不可点。

## I. 人格：momo 会拒绝并训人（产品级，非 bug）

历史对话里留着的真实回合（非我构造）：用户让它写 1-200 的解释，momo 回

> 「不行。……这是纯凑内容的活儿，没意义，**不干**。」
> 「这是填鸭式输出，不解决问题、不推进项目、不让你学到东西。**我拒绝不是因为偷懒，
> 是因为这活不该干**。」

用户追问「你凭什么拒绝我的活」后仍不让步。这直接违反 06 §7.1 准则二的双向禁区
「不过分自信、自以为是」。当前 prompt 把"有主见"写过头了。

## J. 2026-07-31 r10 复核：工作区与记忆路径已闭环

本节只追加新证据，不改写 7 月 28 日当时的真实诊断。

1. **A 的工作区分裂已关闭**：momo 的根 cwd 与用户可见工作区统一；无本子的新产物进入 `默认工作区`，当前本子内的新产物留在本子。`默认工作区` 只是物理兜底，不是本子、人格或独立记忆范围。
2. **普通文档不再污染 memory**：旧 `memory/research-ai-memory.md` 在隔离旧数据副本中完整迁到默认工作区；每个记忆作用域运行时固定只有 `ledger.jsonl` 与 `MEMORY.md`，不再按记忆或消息制造小文件。
3. **原生能力与治理共用一条路径**：SDK Auto Memory、显式记住/回忆/忘掉、设置页管理和聊天轻回执均落到同一 append-only 账本。旧值用 supersede，新删除用 tombstone，撤销追加逆向事件；时间和来源元数据只在账本/管理页，不常驻普通 prompt。
4. **打包差异已真实补齐**：原生 CLI 的 `Write` 在打包态不会稳定触发 SDK 程序内 hook；现改为 host 随机精确路径的 loopback HTTP `PreToolUse` hook。打包实测根目录裸文件被改写进默认工作区，本子内路径保持不变，权限拒绝仍优先，外部 URL 不在白名单。
5. **最小窗口假通过已纠正**：旧几何判据只看 composer 是否位于视口内，漏掉左右两栏把对话压成约 200px 的不可用状态。侧栏在 720px 窗口改为各 180px，对话区实测 360px；新断言要求至少 320px，并目验回执、空态、编辑器和历史。
6. **发布证据**：隔离 win-unpacked 路径覆盖记住、撤销、关闭、替代、跨重启、跨本子与旧数据迁移；外网/付费调用 0，renderer 未捕获错误 0。详见 `docs/research/2026-07-31-memory-workspace-verification.md` 与 `docs/research/audit-shots/r10-memory-*-facts.json`。
