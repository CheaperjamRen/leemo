## ① 产品辨析与基本盘

### 同名产品辨析

"WorkBuddy" 存在同名歧义：
- **腾讯 WorkBuddy**（本报告主体）：官网 `workbuddy.tencent.com` 重定向至 `https://www.codebuddy.cn/work/`，是腾讯云旗下 CodeBuddy 产品线的办公分支，隶属腾讯云计算（北京）有限责任公司。
- 海外同名工具（如 HR/项目管理类 SaaS）：与本报告无关，已排除。

以下所有分析均指腾讯 WorkBuddy。

### 产品定位

WorkBuddy 自我定位：**"AI 专家团 全场景办公"**，副标题 "Work Smarter，with Experts"。

核心卖点（官网原文）：
- "全能 AI 工作台，一人指挥，全行业专家执行，从策略到交付一站搞定"
- "100+ 领域专家组成你的虚拟团队，运营、设计、数据、开发等全角色场景覆盖"
- "一句话指令自主规划并交付完整结果，多专家并行协作，一个人顶一支团队"
- "MCP 生态 + 自定义 Skills，能力无限扩展"

产品形态：
- 桌面客户端（macOS 12.0+、Windows 10+）
- 主流 IM 接入：微信、企业微信、QQ、飞书、钉钉
- 微信小程序

目标人群（官网明确列出三类）：
1. **OPC 一人公司**：个体创业者、自由职业者、小微团队负责人
2. **外部信息调研与内容生成**：需市场研究、竞品分析或快速准备汇报材料的人员
3. **业务数据洞察与自动化响应**：运营、客户成功、管理等需对业务数据做出反应的角色

与 CodeBuddy 的关系：WorkBuddy 是 CodeBuddy 产品线的办公分支，共用同一套订阅积分体系（"CodeBuddy 套餐同样适用于 WorkBuddy"）。CodeBuddy 本体是编程向 AI IDE/插件，WorkBuddy 是其通用办公延伸。两者共用 `codebuddy.cn` 域名，共用定价页面。

### 支持模型

官网定价页显示"全模型可选"（付费版）、"Auto 模型调度"（免费版限免期间也可选全模型）。具体模型列表官网未在公开页面列出。用户委托方提到"主打国模、腾讯混元 hy3 自家模型且限时免费"——**混元 hy3 免费政策细节未在官网定价页明确标注，未证实具体期限**。积分体系暗示模型消耗以积分计费，不同模型消耗积分不同（具体比率未公开）。

### 平台覆盖

桌面（Mac/Windows）+ 微信/企微/QQ/飞书/钉钉 IM Bot + 微信小程序。覆盖面广，尤其 IM 接入是差异化点。

## ⑤ 强弱与缝隙分析

### WorkBuddy 结构性的强（事实）

- **腾讯生态背书**：IM 接入（微信/企微/QQ/飞书/钉钉）是独立开发者无法复制的分发渠道。
- **免费补贴力度大**：公测期限免大量功能（自动任务 99 个、无限代码补全），获客成本极低。
- **迭代速度**：7 月 1 日刚完成定价体系升级，产品在快速演进。
- **品牌信任**：腾讯云背书，企业用户采购阻力小。
- **MCP 生态**：接入 MCP 协议，工具扩展性强。

### WorkBuddy 结构性的弱/不愿做的（事实+推断混合）

- **无自带 API key 机制**（事实）：官网无任何"自带 key"入口，用户数据和模型选择完全由平台控制。这是大厂平台模式的必然选择，不会改变。
- **无人格化搭子设计**（事实）：定位"专家团"，功能导向，无情感陪伴/搭子人格投入。大厂做人格化搭子有品牌风险和内容审核压力，投入意愿低。
- **数据自主性弱**（事实）：隐私协议归属腾讯，用户对数据流向控制有限。
- **学生/轻用户不友好**（推断）：免费版 500 积分/月极为有限，付费门槛 ¥70+/月对学生偏高；"专家团"定位偏向职场/创业者，非学生日常场景。
- **通用款深度不足**（推断）：100+ 专家覆盖面广但每个专家深度有限，垂直场景体验可能不如专项工具。

### 委托方假设检验："WorkBuddy 可能太通用了"

- **口碑证据**：未及调研，无法实证。
- **产品形态证据**（事实）：官网列出的三大场景（OPC/调研/数据洞察）均为宽泛通用场景，无深度垂直切入。"100+ 领域专家"的广度策略本身即通用化取向。
- **结论**：假设方向合理，但需口碑数据支撑。建议后续补充知乎/小红书实证。

### 给独立开发者的缝隙判断

| 缝隙 | Leemo 现有设计是否踩中 |
|---|---|
| 自带 key / 模型中立性（不被平台锁定） | ✅ 踩中：20+ 国产模型+自定义中转站，是 WorkBuddy 结构性不做的 |
| 人格化搭子 / 情感陪伴 | ✅ 踩中：momo 人格，搭子/工作台双模式，大厂不愿深做 |
| 数据自主 / 本地优先 | ✅ 踩中：Electron 本地运行，数据不经平台 |
| 学生/年轻个人用户低门槛 | ⚠️ 部分踩中：自带 key 可控成本，但 Leemo 本身无免费模型补贴，学生仍需自付 API 费用 |
| 审批卡/结构化问询（agent 透明度） | ✅ 踩中：WorkBuddy 无此设计，Leemo 的审批卡是差异化 |
| 本子/成果知识沉淀 | ✅ 踩中：WorkBuddy 无持久化知识体系，Leemo 有 |
| IM 生态接入 | ❌ 未踩中：WorkBuddy 强项，Leemo 无此能力（也不需要做） |
| 企业/团队协作 | ❌ 未踩中：WorkBuddy 有项目协作，Leemo 定位个人 |

## ⑥ 给 Leemo 的 5 条可执行结论

1. **把"自带 key + 模型中立"做成核心叙事**：WorkBuddy 平台锁定是结构性弱点，Leemo 的"你的 key，你的数据，你选模型"是真实差异化，应在产品文案和落地页中明确对比。

2. **人格搭子是护城河，不是噱头**：大厂做人格化有品牌风险和内容审核压力，WorkBuddy 不会深做。momo 的人格投入（语气、记忆、情感陪伴）是 Leemo 可以持续加深的方向，越深越难被复制。

3. **审批卡/透明 Agent 是可宣传的差异点**：WorkBuddy 的 Agent 是黑盒"专家团"，Leemo 的审批卡让用户看到并控制每一步。对有隐私顾虑或想掌控感的用户，这是强卖点。

4. **学生用户需要降低 API 成本感知**：Leemo 自带 key 可控成本，但学生不一定知道"DeepSeek API 极便宜"。建议在 onboarding 中加入"月均花费估算"或"推荐入门 key 配置"，把成本优势具象化。

5. **补做口碑调研（高优先级）**：本次 WorkBuddy 用户吐槽数据完全缺失，是报告最大盲区。建议用浏览器直接访问知乎搜索"WorkBuddy 体验"、小红书搜"WorkBuddy 好用吗"、V2EX 搜"WorkBuddy"，每个平台 30 分钟即可获得高质量吐槽数据，直接填充本报告第③节。
