# Leemo 通用 Agent 成熟度盘点

日期：2026-08-28

## 直接判断

Leemo 已经具备进入使用场景特化的通用 Agent 地基。当前版本仍需完成正式包验收和发布收口；对外表述应采用“核心执行能力已接通”，暂不宣称与 Claude Desktop、Codex、WorkBuddy、NewMax、ColaOS 全功能对齐。

Leemo 的下一阶段重点是把现有能力放进求职、科研、学习和长期陪伴的真实流程中，形成稳定的入口、上下文、工具选择、交付物和恢复路径。通用层继续保留少量高价值缺口：更完整的改动审阅、浏览器 Workflow、结构化连接器和多任务监督。

## 参照产品公开能力

- [Claude Cowork / Computer use](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork)：连接器优先，浏览器其次，屏幕操作作为通用回退；支持应用授权、停止与记忆管理。
- [Codex App](https://openai.com/index/introducing-the-codex-app/)：项目化多任务、并行 Agent、worktree、改动审阅、Skills、自动化与安全沙箱。
- [Tencent WorkBuddy](https://www.workbuddy.ai/docs/workbuddy/)：一句话交付任务，自主规划执行，覆盖文档、表格、演示与本地文件处理。
- [work-buddy](https://docs.work-buddy.ai/)：本地优先个人 Agent runtime，把笔记、任务、浏览器、项目、记忆和长任务监督接在一起。
- [ColaOS](https://docs.colaos.ai/en/overview/)：一条连续主对话、跨会话记忆、电脑操作、Skills、提醒与主动回访。
- [NewMax 浏览器自动化](https://newmax.cc/docs/features/browser)：浏览器身份、可见执行、人工接管、教学录制、变量化 Workflow 与快速回放。

| 用户管理的并行 Agent | 待补 | SDK 能运行子任务；缺少 Codex 式多 Agent 任务监督与隔离工作区 UI |
| 远程与主动陪伴 | 待补 | 当前以本机主动使用为主；移动端接管、跨设备和主动 Awareness 进入长期路线 |

## 当前版本必须完成

1. 正式包覆盖停止、运行中设置、上下文窗口、托盘唤起、网络模式、超大 PDF、窗口缩放、浏览器和电脑操作。
2. 全量测试、构建、打包与重启恢复通过；保留最新视觉证据。
3. README 准确展示当前界面、搭子章节交互、本地文档、工作台和 Skill Hub。
4. 发布说明明确公开预览边界、系统要求、模型服务差异和未签名提醒。

完成这些后，可以把主要开发精力放到使用场景特化。

## 有真实用户或高频自用后继续

- 求职：岗位资料、本地简历、故事库、投递前检查和面试复盘形成一条稳定链路。
- 科研：多 PDF 阅读、来源核验、问题形成、实验/分析计划与文档交付。
- 学习：误解诊断、复习计划、笔记与自测题在同一本子内推进。
- 浏览器 Workflow：从成功任务保存开始，逐步加入变量、断点、人工接管和定时回放。
- 改动审阅：为代码和文档分别提供适合普通用户的差异查看与撤销入口。

## 暂缓投入

- 完整连接器市场与账号托管平台。
- 云端高可用、多设备实时同步和远程桌面中继。
- 通用多 Agent 编排工作台。
- 桌宠、塔罗和大量轻量娱乐入口。

这些方向可以保留在产品待办中。场景链路有稳定使用频率后，再依据真实注意力和维护成本选择下一项。
