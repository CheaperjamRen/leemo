# Leemo r9 可信连续体验设计

> 日期：2026-07-30
> 状态：产品路线已批准，技术设计由开发负责人执行
> 产品目标：让 3-5 位不了解内部实现的学生，能独立完成一次真实学习任务，并在关闭、重启 Leemo 后继续工作。

## 一、这一版解决什么

r8 已经把 Claude Code 的核心能力、本子工作区、设置、权限、附件、MCP、计划和子任务接到了真实用户入口。r9 不继续横向堆页面，而是把现有能力收成一条可信链路：

```text
进入真实本子
  -> 发起任务
  -> 看懂 momo 正在做什么
  -> 必要时授权或回答
  -> 得到真实文件成果
  -> 在 Leemo 中预览并回到来源对话
  -> 关闭应用
  -> 重启后恢复任务、成果和下一步
```

这条链路中任何可见入口没有结果、状态与事实不一致，或重启后丢失，均视为功能缺陷，不归入纯视觉 backlog。

## 二、设计原则

1. **文件是真相。** 成果来自本子中的真实文件，不创建第二套云端或 SQLite 成果真源。
2. **状态可推导，不重复记账。** 任务状态从运行状态、待确认交互和持久化时间线推导，避免另一份状态表与真实事件漂移。
3. **一个任务一张过程收据。** 计划、工具、子任务、确认和阶段说明属于同一轮工作，不因中间文字被切成多张重复卡。
4. **只承诺已经能做的动作。** 假按钮要实现或隐藏；没有“以后会有”的字符占位。
5. **透明不等于倾倒。** 展示 SDK 明确返回的过程文本、计划、工具轨迹、结果和验证，不尝试提取模型未返回的私有思维链。
6. **简单用户零配置，高级用户可展开。** 默认模型接入只需要服务商、Key 和测试连接；模型映射、Headers 等能力放在高级设置中。
7. **密钥只进加密配置。** API Key 不回传渲染层、不写日志、不进入截图；高级环境配置只开放 Leemo 已实际消费的白名单字段。
8. **两种壳共享事实。** 搭子态与工作台态使用同一时间线、成果、模型配置和持久化数据，只改变信息密度。

## 三、信息呈现

### 3.1 共享 Markdown

新增一个共享 `MarkdownContent` 组件，统一服务于：

- momo 最终回答；
- SDK 显式返回的阶段说明；
- 子任务的用户可见文本结论；
- Markdown 文件预览。

组件统一支持 GFM 表格、任务列表、普通列表、引用、代码块、行内代码和链接，并提供三种密度：

- `answer`：完整正文，适合最终回答；
- `process`：紧凑正文，适合过程折叠卡；
- `preview`：文件阅读密度，适合右侧预览。

长链接、长代码、表格和没有空格的长单词必须在 1280x720 与 1440x900 下不撑破容器。流式增量允许暂时不完整的 Markdown，但不得造成页面跳宽或运行时异常。

### 3.2 单一过程收据

一轮对话只渲染一个 `ProcessFold`。它固定出现在该轮第一次过程事件的位置，并持续吸收这一轮后续的计划、工具、子任务、压缩和阶段说明。用户问题、授权卡、可视化成果和最终回答仍保留在时间顺序中的独立位置。

搭子态默认折叠，只显示一句人话状态；工作台态运行中展开，完成后折叠。展开后展示真实动作和结果，不再出现三张“momo 收好过程”的同义卡。

### 3.3 二级页面成熟度

成果、通知、搜索、技能统一使用现有 Leemo 设计令牌和真实图标，补齐：

- 空状态；
- 加载状态；
- 错误状态与重试；
- 有数据状态；
- 当前页面标题、导航选中态和返回路径。

技能页暂不建设市场。卡片只负责查看信息和启停；删除“点击卡片即可触发”这类当前不成立的承诺。

## 四、任务与成果连续性

### 4.1 任务状态

任务状态采用以下六态，由现有事实推导：

| 状态 | 判据 | 用户动作 |
|---|---|---|
| waiting | 新任务尚未开始，或重启后发现一轮没有结束事件 | 开始或继续 |
| running | 当前进程持有该对话的 runId | 停止、查看过程 |
| blocked | 有待回答问题或待授权操作 | 回答或授权 |
| failed | 最近一轮明确失败 | 查看原因、继续修复 |
| canceled | 最近一轮被用户停止 | 继续或改要求 |
| completed | 最近一轮成功结束 | 打开成果、继续追问 |

不新增一份独立持久化状态。重启后 `running` 不可伪装继续运行；未写入结束事件的轮次恢复为 `waiting`，文案明确为“上次停在这里，可以继续”。

### 4.2 成果重建

成果索引由已持久化时间线中的成功 `Write`、`Edit` 和 Leemo 可视化工具事件重建；当前进程中的新事件继续实时登记。这样：

- 应用重启后成果不会清空；
- 删除 SQLite 索引仍可从本子对话记录重建；
- 同一路径的新成果替换旧索引，不产生重复卡；
- 成果保留来源对话和来源轮次。

成果卡必须提供两个真实动作：打开预览、回到来源对话。文件不存在或不可预览时显示真实错误，不展示假预览。

### 4.3 可视化卡

- “在预览中打开”调用真实预览面板；
- “在成果中查看”切到成果页；
- 没有可复用重试协议前，删除“让 momo 重画”假按钮；
- 可视化工具的 `file`、`file_path`、`path` 三种已知输入字段统一解析。

## 五、模型设置

### 5.1 目标

模型页采用 NewMax 的清晰信息层级和 CC Switch 的渐进式高级配置，但保持 Leemo 的学生心智。普通用户完成配置不需要理解 Provider、环境变量或 Claude Code 别名；高级用户可以精确控制底层模型映射。

视觉方向采用 **Swiss utility panel**：白色/中性灰表面、细分隔线、左对齐、紧凑行高和单一橙色强调。保留 Leemo 外壳，不改成新的品牌主题。标志性交互是“服务商状态行 + 就地详情编辑”：列表负责比较，编辑器负责完成配置，避免连续超长卡片瀑布。

### 5.2 页面结构

```text
模型
  默认模型                     当前对话默认使用
  已连接服务商                 紧凑列表：状态、协议、模型数、延迟、编辑
  添加服务商                   官方预设 + 自定义
  用量                         保持现有真实数据
```

编辑服务商时采用分段表单：

1. `连接`：名称、协议、Base URL、API Key、测试连接；
2. `模型`：拉取、搜索、勾选、手动添加、思考/视觉能力；
3. `高级`：自定义 Headers、Claude Code 模型映射。

连接测试结果固定显示成功/失败、延迟、实际测试的模型和可操作的错误分类。保存与测试是两个动作，测试失败不偷偷保存，保存成功也不伪装成连接成功。

### 5.3 高级模型映射

首版只开放 Claude Code 当前仍支持、且 Leemo 后端实际消费并过滤的六个字段：

- `ANTHROPIC_MODEL`；
- `ANTHROPIC_DEFAULT_FABLE_MODEL`；
- `ANTHROPIC_DEFAULT_SONNET_MODEL`；
- `ANTHROPIC_DEFAULT_OPUS_MODEL`；
- `ANTHROPIC_DEFAULT_HAIKU_MODEL`；
- `CLAUDE_CODE_SUBAGENT_MODEL`。

界面主标签使用“主模型、Fable、Sonnet、Opus、Haiku、子任务模型”，环境变量名只作为高级说明。空值表示跟随当前对话模型。旧配置中的 `ANTHROPIC_SMALL_FAST_MODEL` 只做迁移兼容，不继续出现在主界面；Claude Code 当前文档已将它标为废弃。暂不开放任意 env，因为当前运行时会丢弃未知字段，放开只会制造假设置并扩大密钥暴露面。

自定义 Headers 采用结构化键值编辑。`Authorization`、`x-api-key` 等秘密型 Header 与 API Key 一样只允许写入和替换，不得从主进程回传到渲染层、日志或诊断复制内容。

## 六、搜索与学生能力的排期

以下已进入确定 backlog，但不打断 r9 核心链路：

1. 豆包搜索直接接入现有搜索回退链，同时提供官方 Skill/MCP 入口；测试 Key 只做临时探针。
2. 秘塔作为第二个通用搜索提供商。
3. Google Custom Search 仅兼容已有凭据，不作为新用户默认。
4. arXiv 单独做“学术检索”能力，与普通网页搜索分开。
5. 第一批学生 Skills 为课程资料整理、论文检索阅读、岗位与简历差距分析；不先做商城。

## 七、实施切片

### r9.0 基线固化

只提交已经通过全量测试、typecheck 和两段构建的 r8 产品代码、测试、必要脚本与证据。排除安装包、逆向目录、工具私有目录和临时会话文档。

### r9.1 界面可信度

共享 Markdown、单一过程收据、搜索文件与 Wiki 过滤、成果/通知真实状态、假控件清理、统一图标和二级页面导航。

### r9.2 任务与成果连续性

六态推导、成果重建、来源回跳、真实预览错误、重启恢复用户路径。

### r9.3 模型配置可信度

紧凑服务商列表、分段编辑、连接状态、六槽模型映射、设置搜索可定位具体项。

### r9.4 最小搭子记忆闭环

真实续接问候、记忆候选回执、确认/编辑/删除，并验证重启与纠错。不在本切片重写记忆引擎。

## 八、验收

每个切片必须同时满足：

1. 定向测试先红后绿；
2. `npm test` 全绿；
3. `npm run typecheck` 通过；
4. `npm run build` 与涉及主进程时的 `npm run build:main` 通过；
5. 真实 Electron 用户路径验收，而非写死绝对路径的零件脚本；
6. 1440x900 与 1280x720 截图检查；
7. 最终打包应用完成一次“本子 -> 任务 -> 成果 -> 关闭 -> 重启 -> 继续”。

## 九、明确不做

- 不重写 Agent 引擎或记忆引擎；
- 不建设技能/专家/模板商城；
- 不做企业协作、云盘、支付和积分；
- 不为全文搜索先建向量数据库；
- 不开放运行时不会消费的假设置；
- 不复制 NewMax 专有代码或 ColaOS 的角色包装；
- 不因视觉改造改变“本子、成果”两词的用户心智。
